    模板 API

    MongoTemplate 及其位于 org.springframework.data.mongodb.core 包中的反应式对应类 reactive，是 Spring MongoDB 支持的核心类，为与数据库交互提供了丰富的功能集。 该模板提供了创建、更新、删除和查询 MongoDB 文档的便捷操作，并在您的领域对象与 MongoDB 文档之间提供映射关系。

    配置完成后，MongoTemplate 是线程安全的，可以在多个实例中重复使用。

    便捷方法

    `MongoTemplate` 类实现了 `MongoOperations` 接口。 在尽可能多的情况下，`MongoOperations` 上的方法命名与 MongoDB 驱动程序的 `Collection` 对象上的方法保持一致，以便让熟悉驱动程序 API 的现有 MongoDB 开发者能够轻松上手。 例如，您可以找到诸如 `find`、`findAndModify`、`findAndReplace`、`findOne`、`insert`、`remove`、`save`、`update` 和 `updateMulti` 等方法。 设计目标是尽可能简化从基础 MongoDB 驱动程序切换到使用 `MongoOperations` 的过程。 这两个 API 之间的一个主要区别是，`MongoOperations` 可以传递领域对象，而不是 `Document`。 此外，`MongoOperations` 为 `Query`、`Criteria` 和 `Update` 操作提供了流式 API，而无需通过填充 `Document` 来指定这些操作的参数。

    有关更多信息，请参阅文档中的CRUD和查询部分。

    引用 MongoTemplate 实例上操作的首选方式是通过其接口 MongoOperations。

    执行回调

    MongoTemplate 提供了许多便捷方法，帮助您轻松完成常见任务。 然而，如果您需要直接访问 MongoDB 驱动程序 API，可以使用多种 `Execute` 回调方法之一。 `execute` 回调会为您提供对 `MongoCollection` 或 `MongoDatabase` 对象的引用。

    • <T> T execute (Class<?> entityClass, CollectionCallback<T> action): 为指定类的实体集合执行给定的 CollectionCallback。

    • <T> T execute (String collectionName, CollectionCallback<T> action): 在指定名称的集合上执行给定的 CollectionCallback。

    • <T> T execute (DbCallback<T> action): 执行 DbCallback，并根据需要转换任何异常。Spring Data MongoDB 提供了对 MongoDB 在 2.2 版本中引入的聚合框架的支持。

    • <T> T execute (String collectionName, DbCallback<T> action): 在指定名称的集合上运行 DbCallback，并根据需要转换任何异常。

    • <T> T executeInSession (DbCallback<T> action): 在同一个数据库连接中执行给定的 DbCallback，以确保在写密集型环境中读取您写入的数据时的一致性。

    下面的示例使用CollectionCallback返回有关索引的信息：

    • Imperative

    • Reactive

    boolean hasIndex = template.execute("geolocation", collection ->
    Streamable.of(collection.listIndexes(org.bson.Document.class))
        .stream()
        .map(document -> document.get("name"))
        .anyMatch("location_2d"::equals)
);
    Mono<Boolean> hasIndex = template.execute("geolocation", collection ->
    Flux.from(collection.listIndexes(org.bson.Document.class))
        .map(document -> document.get("name"))
        .filterWhen(name -> Mono.just("location_2d".equals(name)))
        .map(it -> Boolean.TRUE)
        .single(Boolean.FALSE)
    ).next();

    Fluent API

    作为与 MongoDB 进行更底层交互的核心组件，MongoTemplate 提供了广泛的方法集，涵盖从集合创建、索引建立到 CRUD 操作等基础需求，以及 Map-Reduce 和聚合等高级功能。 每种方法都提供多个重载版本。 其中大多数重载覆盖了 API 的可选或可为 null 的部分。

    FluentMongoOperations 为 MongoOperations 的常用方法提供了更窄的接口，并提供了更易读、流式的 API。 入口点（如 insert(…)、find(…)、update(…) 等）遵循基于要执行的操作的自然命名约定。 从入口点开始，API 设计为仅提供上下文相关的方法，这些方法最终会调用一个终止方法以实际执行对应的 MongoOperations 操作——例如在以下示例中即为 all 方法：

    Imperative
    List<Jedi> all = template.query(SWCharacter.class) (1)
  .inCollection("star-wars") (2)
  .as(Jedi.class) (3)
  .matching(query(where("jedi").is(true))) (4)
  .all();
    1 用于将查询中使用的字段映射到的类型。
    2 如果未在域类型中定义，则使用的集合名称。
    3 不使用原始域类型时的结果类型。
    4 查询语句。
    Reactive
    Flux<Jedi> all = template.query(SWCharacter.class)
  .inCollection("star-wars")
  .as(Jedi.class)
  .matching(query(where("jedi").is(true)))
  .all();
    使用投影可以让 MongoTemplate 通过限制实际响应仅包含投影目标类型所需的字段来优化结果映射。只要 Query 本身不包含任何字段限制，且目标类型为封闭接口或 DTO 投影，此规则即适用。
    不能将投影应用于 DBRefs。

    您可以通过终止方法 `first()`、`one()`、`all()` 或 `stream()`，在检索单个实体与检索多个实体（以 `List` 或 `Stream` 形式）之间进行切换。

    结果可以通过使用 `QueryResultConverter` 进行上下文后处理，该转换器能够同时访问原始结果 `Document` 和已映射的对象，通过调用如下所示的 `map(…)` 方法实现。

    List<Optional<Jedi>> result = template.query(Person.class)
    .as(Jedi.class)
    .matching(query(where("firstname").is("luke")))
    .map((document, reader) -> Optional.of(reader.get()))
    .all();

    当使用 near(NearQuery) 编写地理空间查询时，终止方法的数量会进行调整，仅包含在 MongoDB 中执行 geoNear 命令有效的方法（即在 GeoResults 内以 GeoResult 的形式获取实体），如下例所示：

    • Imperative

    • Reactive

    GeoResults<Jedi> results = template.query(SWCharacter.class)
  .as(Jedi.class)
  .near(alderaan) // NearQuery.near(-73.9667, 40.78).maxDis…
  .all();
    Flux<GeoResult<Jedi>> results = template.query(SWCharacter.class)
  .as(Jedi.class)
  .near(alderaan) // NearQuery.near(-73.9667, 40.78).maxDis…
  .all();

    异常翻译

    Spring 框架为各种数据库和映射技术提供了异常转换功能。传统上，这一功能主要针对 JDBC 和 JPA。Spring 对 MongoDB 的支持将此项功能扩展到了 MongoDB 数据库，通过提供 org.springframework.dao.support.PersistenceExceptionTranslator 接口的实现来实现。

    将异常映射到 Spring 的统一数据访问异常层次结构背后的动机在于，这样您就能编写可移植且描述清晰的异常处理代码，而无需直接针对 MongoDB 的错误码进行编码。 Spring 的所有数据访问异常都继承自根类DataAccessException，这样您就可以确保在一个 try-catch 块中捕获所有与数据库相关的异常。 请注意，并非由 MongoDB 驱动程序抛出的所有异常都继承自MongoException类。 内部异常和消息均被保留，以确保不丢失任何信息。

    `MongoExceptionTranslator` 执行的一些映射将 `com.mongodb.Network` 转换为 `DataAccessResourceFailureException`，并将错误代码 1003、12001、12010、12011 和 12012 从 `MongoException` 转换为 `InvalidDataAccessApiUsageException`。请查看实现以获取更多关于映射的详细信息。

    异常翻译可以通过在您的 `MongoDatabaseFactory` 或其响应式变体上设置自定义的 `MongoExceptionTranslator` 来配置。 您可能还希望在相应的 `MongoClientFactoryBean` 上设置异常翻译器。

    示例 1. 配置 MongoExceptionTranslator
    ConnectionString uri = new ConnectionString("mongodb://username:password@localhost/database");
SimpleMongoClientDatabaseFactory mongoDbFactory = new SimpleMongoClientDatabaseFactory(uri);
mongoDbFactory.setExceptionTranslator(myCustomExceptionTranslator);

    自定义异常的一个动机是 MongoDB 在事务期间的行为：某些失败（例如写冲突）可能是瞬时的，而重试可能导致操作成功。 在这种情况下，您可以使用特定的 MongoDB 标签包装异常，并应用不同的异常转换策略。

    领域类型映射

    MongoDB 文档与领域类之间的映射是通过委托给 `MongoConverter` 接口的一个实现来完成的。Spring 提供了 `MappingMongoConverter`，但您也可以编写自己的转换器。虽然 `MappingMongoConverter` 可以利用额外的元数据来指定对象到文档的映射，但它也可以利用一些关于 ID 和集合名称映射的约定，将不包含额外元数据的对象转换为文档。这些约定以及映射注解的使用在 映射 章节中进行了说明。
