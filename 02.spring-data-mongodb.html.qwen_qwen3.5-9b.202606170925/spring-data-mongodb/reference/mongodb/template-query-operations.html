    查询文档

    您可以使用 Query 和 Criteria 类来表达查询。它们的方法名称与原生 MongoDB 操作符名称相对应，例如 lt、lte、is 等。 Query 和 Criteria 类遵循流式 API 风格，使您可以将多个方法条件和查询串联起来，同时保持代码易于理解。 为了提高可读性，静态导入允许您在创建 Query 和 Criteria 实例时避免使用 'new' 关键字。 此外，您还可以使用 BasicQuery 从纯 JSON 字符串创建 Query 实例，如下例所示：

    示例 1：从普通 JSON 字符串创建查询实例
    BasicQuery query = new BasicQuery("{ age : { $lt : 50 }, accounts.balance : { $gt : 1000.00 }}");
List<Person> result = mongoTemplate.find(query, Person.class);

    集合中的文档查询

    之前，我们了解了如何使用 `MongoTemplate` 的 `findOne` 和 `findById` 方法检索单个文档。 这些方法会直接返回一个领域对象，或者在使用响应式 API 时返回一个发出单个元素的 `Mono`。 我们还可以查询一组文档，并将其作为领域对象的列表返回。 假设有多个 `Person` 对象，其姓名和年龄以文档形式存储在一个集合中，且每个人都有一个嵌入的账户文档并包含余额字段，那么我们可以使用以下代码运行查询：

    使用 MongoTemplate 查询文档

    • Imperative

    • Reactive

    import static org.springframework.data.mongodb.core.query.Criteria.where;
import static org.springframework.data.mongodb.core.query.Query.query;

// ...

List<Person> result = template.query(Person.class)
  .matching(query(where("age").lt(50).and("accounts.balance").gt(1000.00d)))
  .all();
    import static org.springframework.data.mongodb.core.query.Criteria.where;
import static org.springframework.data.mongodb.core.query.Query.query;

// ...

Flux<Person> result = template.query(Person.class)
  .matching(query(where("age").lt(50).and("accounts.balance").gt(1000.00d)))
  .all();

    所有查找方法都接受一个 `Query` 对象作为参数。该对象定义了执行查询时使用的标准和选项。标准是通过使用具有名为 `where` 的静态工厂方法的 `Criteria` 对象来指定的，该方法用于实例化新的 `Criteria` 对象。我们建议使用静态导入 `org.springframework.data.mongodb.core.query.Criteria.where` 和 `Query.query`，以使查询更易读。

    查询应返回符合指定条件的 List 或 Flux 类型的 Person 对象集合。 本节其余部分列出了与 MongoDB 提供的运算符相对应的 Criteria 和 Query 类的方法。 大多数方法返回 Criteria 对象，以提供 API 的流式风格。

    Criteria 类的实现方法

    `Criteria` 类提供以下方法，这些方法均对应于 MongoDB 中的运算符：

    • Criteria all (Object o) 使用 $all 运算符创建条件

    • Criteria and (String key) 向当前 Criteria 添加一个带有指定 key 的链式 Criteria，并返回新创建的实例。

    • Criteria andOperator (Criteria… criteria) 使用 $and 运算符为所有提供的条件创建与查询（需要 MongoDB 2.0 或更高版本）

    • Criteria andOperator (Collection<Criteria> criteria) 使用 $and 运算符为所有提供的条件创建与查询（需要 MongoDB 2.0 或更高版本）

    • Criteria elemMatch (Criteria c) 使用 $elemMatch 运算符创建标准

    • Criteria exists (boolean b) 使用 $exists 运算符创建条件

    • Criteria gt (Object o) 使用 $gt 操作符创建条件

    • Criteria gte (Object o) 使用 $gte 操作符创建条件

    • Criteria in (Object…​ o) 使用 $in 运算符为可变参数创建条件。

    • Criteria in (Collection<?> collection) 使用集合创建基于 $in 操作符的条件。

    • Criteria is (Object o) 使用字段匹配（{ key:value }）创建条件。如果指定的值是一个文档，则文档中字段的顺序和精确相等性至关重要。

    • Criteria lt (Object o) 使用 $lt 操作符创建条件

    • Criteria lte (Object o) 使用 $lte 操作符创建条件

    • Criteria mod (Number value, Number remainder) 使用 $mod 运算符创建条件。

    • Criteria ne (Object o) 使用 $ne 运算符创建条件

    • Criteria nin (Object…​ o) 使用 $nin 操作符创建条件

    • Criteria norOperator (Criteria…​ criteria) 使用 $nor 运算符为所有提供的条件创建 nor 查询。

    • Criteria norOperator (Collection<Criteria> criteria) 使用 $nor 运算符为所有提供的条件创建 nor 查询。

    • Criteria not () 使用影响紧随其后子句的 $not 元运算符创建条件。

    • Criteria orOperator (Criteria… criteria) 使用 $or 运算符为所有提供的条件创建或查询。

    • Criteria orOperator (Collection<Criteria> criteria) 使用 $or 运算符为所有提供的条件创建或查询。

    • Criteria regex (String re) 使用 $regex 创建标准。

    • Criteria sampleRate (double sampleRate) 使用 $sampleRate 运算符创建准则。

    • Criteria size (int s) 使用 $size 运算符创建条件

    • Criteria 类型 (int t) 使用 $type 操作符创建条件

    • Criteria matchingDocumentStructure (MongoJsonSchema schema) 使用 $jsonSchema 操作符创建用于JSON 模式条件的条件。$jsonSchema 仅可应用于查询的顶层，而不能针对特定属性。请使用模式的 properties 属性来匹配嵌套字段。

    • Criteria 中的 bits() 是访问 MongoDB 按位查询运算符（如 $bitsAllClear）的入口。

    Criteria 类还提供了以下用于地理空间查询的方法。

    • Criteria within (Circle circle) 使用 $geoWithin $center 操作符创建地理空间条件。

    • Criteria 在 (Box box) **内** 使用 $geoWithin $box 操作创建地理空间条件。

    • Criteria withinSphere (Circle circle) 使用 $geoWithin $center 操作符创建地理空间条件。

    • Criteria near (Point point) 使用 $near 操作创建地理空间条件。

    • Criteria nearSphere (Point point) 使用 $nearSphere$center 操作创建地理空间条件。此功能仅适用于 MongoDB 1.7 及以上版本。

    • Criteria minDistance (double minDistance) 使用 $minDistance 操作符创建地理空间条件，用于配合 $near 使用。

    • Criteria maxDistance (double maxDistance) 使用 $maxDistance 操作符创建地理空间条件，用于配合 $near 使用。

    `Query` 类包含一些额外的方法，可用于选择特定字段以及对结果进行限制和排序。

    Query 类的方法

    • addCriteria (Criteria criteria) 用于向查询添加额外的条件。

    • Field fields () 用于定义要包含在查询结果中的字段。

    • Query limit (int limit) 用于将返回结果的大小限制为提供的 limit（用于分页）。

    • Query skip (int skip) 用于跳过结果中指定数量的文档（用于分页）。

    • 使用 (Sort sort) 的 Query with 曾用于为结果提供排序定义。

    • Query 带有 with (ScrollPosition position) 用于提供滚动位置（基于偏移量或键集的分页），以开始或恢复 Scroll。

    模板 API 允许直接使用结果投影，从而能够将查询映射到给定的域类型，同时将操作结果投影到另一个类型上，具体方式如下所示。

    class

template.query(SWCharacter.class)
    .as(Jedi.class)

    有关结果预测的更多信息，请参阅文档中的预测部分。

    字段选择

    MongoDB 支持投影查询结果中的字段。 投影可以根据字段名称包含或排除字段（除非显式排除，否则始终包含 _id 字段）。

    示例 2：选择结果字段
    public class Person {

    @Id String id;
    String firstname;

    @Field("last_name")
    String lastname;

    Address address;
}

query.fields().include("lastname");              (1)

query.fields().exclude("id").include("lastname") (2)

query.fields().include("address")                (3)

query.fields().include("address.city")           (4)
    1 结果将包含 _id 和 last_name，通过 { "last_name" : 1 }。
    2 结果将仅包含 last_name，通过 { "_id" : 0, "last_name" : 1 }。
    3 结果将包含 _id 和完整的 address 对象，通过 { "address" : 1 }。
    4 结果将包含 _id 和仅含 city 字段的 address 对象，通过 { "address.city" : 1 }。

    从 MongoDB 4.4 开始，您可以使用聚合表达式进行字段投影，如下所示：

    示例 3：使用表达式计算结果字段
    query.fields()
  .project(MongoExpression.create("'$toUpper' : '$last_name'"))         (1)
  .as("last_name");                                                     (2)

query.fields()
  .project(StringOperators.valueOf("lastname").toUpper())               (3)
  .as("last_name");

query.fields()
  .project(AggregationSpELExpression.expressionOf("toUpper(lastname)")) (4)
  .as("last_name");
    1 使用本地表达式。所使用的字段名必须引用数据库文档中的字段名。
    2 将表达式结果投影到的字段名进行赋值。生成的字段名不对应领域模型。
    3 使用 AggregationExpression。除了本地 MongoExpression 外，字段名会映射到领域模型中使用的名称。
    4 结合 SpEL 和 AggregationExpression 来调用表达式函数。字段名会映射到领域模型中使用的名称。

    @Query(fields="…") 允许在 Repository 级别使用表达式字段投影，具体描述请参阅MongoDB JSON 基础查询方法和字段限制。

    附加查询选项

    MongoDB 提供了多种方式为查询应用元信息（如注释或批量大小）。直接使用 `Query` API，有多种方法可以实现这些选项。

    Hints

    索引提示可以通过使用索引名称或其字段定义两种方式应用。

    template.query(Person.class)
    .matching(query("...").withHint("index-to-use"));

template.query(Person.class)
    .matching(query("...").withHint("{ firstname : 1 }"));

    游标批量大小

    游标批次大小定义了每个响应批次中返回的文档数量。

    Query query = query(where("firstname").is("luke"))
    .cursorBatchSize(100)

    Collations

    使用集合操作中的排序规则，只需在查询或操作选项中指定一个Collation实例即可，如下面的两个示例所示：

    Collation collation = Collation.of("de");

Query query = new Query(Criteria.where("firstName").is("Amél"))
    .collation(collation);

List<Person> results = template.find(query, Person.class);

    读偏好

    要使用的ReadPreference可以直接设置在将要执行的Query对象上，具体方法如下所示。

    template.find(Person.class)
    .matching(query(where(...)).withReadPreference(ReadPreference.secondary()))
    .all();
    Query 实例上设置的偏好将覆盖 MongoTemplate 的默认 ReadPreference。

    Comments

    查询可以添加注释，从而便于在服务器日志中查找。

    template.find(Person.class)
    .matching(query(where(...)).comment("Use the force luke!"))
    .all();

    查询唯一值

    MongoDB 提供一项操作，可通过查询结果文档来获取单个字段的唯一值。 返回的值不必具有相同的数据类型，该功能也不仅限于简单类型。 在检索时，实际结果类型对于转换和类型化至关重要。以下示例展示了如何查询唯一值：

    示例 4：检索唯一值
    template.query(Person.class)  (1)
  .distinct("lastname")       (2)
  .all();                     (3)
    1 查询 Person 集合。
    2 选择 lastname 字段的不同值。字段名称根据域类型属性声明进行映射，并考虑潜在的 @Field 注解。
    3 将所有不同值检索为 List 类型的 Object（因为未指定明确的结果类型）。

    将 distinct 值检索到 Collection 类型的 Object 是最灵活的方式，因为它会尝试确定域类型的属性值，并将结果转换为所需的类型或映射的 Document 结构。

    有时，当所需字段的所有值都固定为某种类型时，直接获取正确类型的Collection会更加方便，如下例所示：

    示例 5：检索强类型唯一值
    template.query(Person.class)  (1)
  .distinct("lastname")       (2)
  .as(String.class)           (3)
  .all();                     (4)
    1查询 Person 集合。
    2选择 lastname 字段的不同值。字段名根据域类型属性声明进行映射，并考虑潜在的 @Field 注解。
    3检索到的值被转换为所需的目标类型——在本例中为 String。如果存储的字段包含文档，也可以将值映射到更复杂的类型。
    4以 String 的 List 形式检索所有不同值。如果无法将类型转换为所需的目標类型，此方法会抛出 DataAccessException。

    += 地理空间查询

    MongoDB 通过诸如 $near、$within、geoWithin 和 $nearSphere 等运算符支持地理空间查询。针对地理空间查询的特定方法可在 Criteria 类上找到。此外，还有几种形状类（Box、Circle 和 Point），它们与地理空间相关的 Criteria 方法配合使用。

    在 MongoDB 事务中使用 GeoSpatial 查询时需注意特殊行为，详见事务内的特殊行为。

    要了解如何执行地理空间查询，请参考以下Venue类（取自集成测试，并依赖于功能丰富的MappingMongoConverter）：

    Venue.java 
    @Document(collection="newyork")
public class Venue {

  @Id
  private String id;
  private String name;
  private double[] location;

  @PersistenceCreator
  Venue(String name, double[] location) {
    super();
    this.name = name;
    this.location = location;
  }

  public Venue(String name, double x, double y) {
    super();
    this.name = name;
    this.location = new double[] { x, y };
  }

  public String getName() {
    return name;
  }

  public double[] getLocation() {
    return location;
  }

  @Override
  public String toString() {
    return "Venue [id=" + id + ", name=" + name + ", location="
        + Arrays.toString(location) + "]";
  }
}

    要在 Circle 内查找位置，您可以使用以下查询：

    Circle circle = new Circle(-73.99171, 40.738868, 0.01);
List<Venue> venues =
    template.find(new Query(Criteria.where("location").within(circle)), Venue.class);

    要在球面坐标中查找位于 `Circle` 内的场馆，可以使用以下查询：

    Circle circle = new Circle(-73.99171, 40.738868, 0.003712240453784);
List<Venue> venues =
    template.find(new Query(Criteria.where("location").withinSphere(circle)), Venue.class);

    要在 `Box` 内查找场地，您可以使用以下查询：

    //lower-left then upper-right
Box box = new Box(new Point(-73.99756, 40.73083), new Point(-73.988135, 40.741404));
List<Venue> venues =
    template.find(new Query(Criteria.where("location").within(box)), Venue.class);

    要查找靠近某个 `Point` 的场馆，您可以使用以下查询：

    Point point = new Point(-73.99171, 40.738868);
List<Venue> venues =
    template.find(new Query(Criteria.where("location").near(point).maxDistance(0.01)), Venue.class);
    Point point = new Point(-73.99171, 40.738868);
List<Venue> venues =
    template.find(new Query(Criteria.where("location").near(point).minDistance(0.01).maxDistance(100)), Venue.class);

    要使用球面坐标查找附近的场地，可以使用以下查询：

    Point point = new Point(-73.99171, 40.738868);
List<Venue> venues =
    template.find(new Query(
        Criteria.where("location").nearSphere(point).maxDistance(0.003712240453784)),
        Venue.class);

    地理邻近查询

    2.2 版本已更改！
    MongoDB 4.2 移除了对 geoNear 命令的支持，该命令此前用于执行 NearQuery。

    Spring Data MongoDB 2.2 中的MongoOperations#geoNear使用$geoNear聚合操作符来执行NearQuery，而不是使用geoNear命令。

    之前，使用 geoNear 命令计算的距离（即dis）会返回在一个包装类型中，现在该距离已嵌入到结果文档中。 如果给定的域类型已经包含一个同名属性，则计算出的距离将命名为calculated-distance，并可能带有随机后缀。

    目标类型可以包含一个与返回的“到”距离同名的属性，以便（额外）将其直接读回至领域类型，如下所示。

    GeoResults<VenueWithDistanceField> = template.query(Venue.class) (1)
    .as(VenueWithDistanceField.class)                            (2)
    .near(NearQuery.near(new GeoJsonPoint(-73.99, 40.73), KILOMETERS))
    .all();
    1 用于标识目标集合和潜在查询映射的域类型。
    2 包含类型为 Number 的 dis 字段的目標类型。

    MongoDB 支持查询数据库中的地理位置，并同时计算从给定原点出发的距离。通过地理邻近查询（geo-near queries），您可以表达诸如“查找周围 10 英里内的所有餐厅”这样的查询需求。为此，MongoOperations 提供了 geoNear(…) 方法，该方法接受一个 NearQuery 作为参数（以及已熟悉的实体类型和集合），如下例所示：

    Point location = new Point(-73.99171, 40.738868);
NearQuery query = NearQuery.near(location).maxDistance(new Distance(10, Metrics.MILES));

GeoResults<Restaurant> = operations.geoNear(query, Restaurant.class);

    我们使用 `NearQuery` 构建器 API 来设置查询，以返回给定 `Point` 周围 10 英里内的所有 `Restaurant` 实例。 此处使用的 `Metrics` 枚举实际上实现了一个接口，以便可以将其他度量标准插入到距离计算中。 一个 `Metric` 由乘数支持，用于将给定度量的距离值转换为原生距离单位。 本示例中的 10 被视为英里。使用内置的度量标准（英里和公里）会自动触发在查询上设置球形标志。 如果您想避免这种情况，请将普通的 `double` 值传递给 `maxDistance(…)`。 有关更多信息，请参阅 `NearQuery` 和 `Distance` 的 Javadoc。

    geo 邻近查询返回一个封装了 `GeoResult` 实例的 `GeoResults` 包装对象。 对 `GeoResults` 进行包装可以访问所有结果的平均距离。 单个 `GeoResult` 对象包含找到的实体及其与起点的距离。

    GeoJSON 支持

    MongoDB 支持用于地理空间数据的 GeoJSON 和简单的（旧版）坐标对。这两种格式均可用于存储及查询数据。有关要求和限制，请参阅MongoDB 手册中关于 GeoJSON 支持的内容。

    域类中的 GeoJSON 类型

    在领域类中使用GeoJSON类型非常简单。org.springframework.data.mongodb.core.geo包包含诸如GeoJsonPoint、GeoJsonPolygon等类型。这些类型扩展了现有的org.springframework.data.geo类型。以下示例使用了一个GeoJsonPoint：

    public class Store {

	String id;

	/**
	 * { "type" : "Point", "coordinates" : [ x, y ] }
	 */
	GeoJsonPoint location;
}

    如果 GeoJSON 对象的 coordinates 表示 纬度 和 经度 对，则顺序为 经度 在前，纬度 在后。
    因此，GeoJsonPoint 将 getX() 视为 经度，将 getY() 视为 纬度。

    存储库查询方法中的 GeoJSON 类型

    使用 GeoJSON 类型作为存储库查询参数会强制在创建查询时使用$geometry操作符，如下例所示：

    public interface StoreRepository extends CrudRepository<Store, String> {

	List<Store> findByLocationWithin(Polygon polygon);  (1)

}

/*
 * {
 *   "location": {
 *     "$geoWithin": {
 *       "$geometry": {
 *         "type": "Polygon",
 *         "coordinates": [
 *           [
 *             [-73.992514,40.758934],
 *             [-73.961138,40.760348],
 *             [-73.991658,40.730006],
 *             [-73.992514,40.758934]
 *           ]
 *         ]
 *       }
 *     }
 *   }
 * }
 */
repo.findByLocationWithin(                              (2)
  new GeoJsonPolygon(
    new Point(-73.992514, 40.758934),
    new Point(-73.961138, 40.760348),
    new Point(-73.991658, 40.730006),
    new Point(-73.992514, 40.758934)));                 (3)

/*
 * {
 *   "location" : {
 *     "$geoWithin" : {
 *        "$polygon" : [ [-73.992514,40.758934] , [-73.961138,40.760348] , [-73.991658,40.730006] ]
 *     }
 *   }
 * }
 */
repo.findByLocationWithin(                              (4)
  new Polygon(
    new Point(-73.992514, 40.758934),
    new Point(-73.961138, 40.760348),
    new Point(-73.991658, 40.730006)));
    1 使用通用类型的存储库方法定义允许同时以 GeoJSON 和旧版格式调用它。
    2 使用 GeoJSON 类型以利用 $geometry 运算符。
    3 请注意，GeoJSON 多边形需要定义一个闭合环。
    4 使用旧版格式 $polygon 运算符。

    指标与距离计算

    然后，MongoDB 的 `$geoNear` 运算符允许使用 GeoJSON 点或传统坐标对。

    NearQuery.near(new Point(-73.99171, 40.738868))
    {
  "$geoNear": {
    //...
    "near": [-73.99171, 40.738868]
  }
}
    NearQuery.near(new GeoJsonPoint(-73.99171, 40.738868))
    {
  "$geoNear": {
    //...
    "near": { "type": "Point", "coordinates": [-73.99171, 40.738868] }
  }
}

    尽管语法结构不同，服务器能够接受两种格式，无论目标文档在集合中采用何种格式。

    距离计算存在巨大差异。使用旧版格式时，会在类地球的球体上基于 弧度 进行运算，而 GeoJSON 格式则使用 米。

    为避免出现严重错误，请确保将 `Metric` 设置为所需的度量单位，以确保计算的距离正确无误。

    全文搜索

    自 MongoDB 2.6 版本起，您可以使用 $text 运算符执行全文查询。与全文查询相关的方法和操作可在 TextQuery 和 TextCriteria 中获取。进行全文搜索时，请参阅其行为和限制说明的MongoDB 参考文档。

    在真正使用全文搜索之前，必须正确设置搜索索引。有关如何创建索引结构的详细信息，请参阅文本索引。以下示例展示了如何设置全文搜索：

    db.foo.createIndex(
{
  title : "text",
  content : "text"
},
{
  weights : {
              title : 3
            }
}
)

    可以按如下方式定义并执行一个搜索coffee cake的查询：

    示例 8：全文查询
    Query query = TextQuery
  .queryText(new TextCriteria().matchingAny("coffee", "cake"));

List<Document> page = template.find(query, Document.class);

    要按 `weights` 的相关性对结果进行排序，请使用 `TextQuery.sortByScore`。

    示例 9：全文查询——按分数排序
    Query query = TextQuery
  .queryText(new TextCriteria().matchingAny("coffee", "cake"))
  .sortByScore() (1)
  .includeScore(); (2)

List<Document> page = template.find(query, Document.class);
    1 使用 score 属性按相关性对结果进行排序，这会触发 .sort({'score': {'$meta': 'textScore'}})。
    2 使用 TextQuery.includeScore() 将计算出的相关性包含在返回的 Document 中。

    您可以通过在搜索词前添加-或使用notMatching来排除搜索词，如下例所示（请注意这两行具有相同的效果，因此是冗余的）：

    // search for 'coffee' and not 'cake'
TextQuery.queryText(new TextCriteria().matching("coffee").matching("-cake"));
TextQuery.queryText(new TextCriteria().matching("coffee").notMatching("cake"));

    TextCriteria.matching 直接采用提供的术语。因此，您可以通过将短语置于双引号之间（例如 "coffee cake"）或使用 TextCriteria.phrase. 来定义短语。以下示例展示了定义短语的这两种方法：

    // search for phrase 'coffee cake'
TextQuery.queryText(new TextCriteria().matching("\"coffee cake\""));
TextQuery.queryText(new TextCriteria().phrase("coffee cake"));

    您可以使用 TextCriteria 上的相应方法为 $caseSensitive 和 $diacriticSensitive 设置标志。请注意，这两个可选标志是在 MongoDB 3.2 中引入的，除非显式设置，否则不会包含在查询中。

    示例查询

    按示例查询 可用于在模板 API 级别运行示例查询。

    以下片段展示了如何通过示例进行查询：

    已输入示例查询
    Person probe = new Person();
probe.lastname = "stark";

Example example = Example.of(probe);

Query query = new Query(new Criteria().alike(example));
List<Person> result = template.find(query, Person.class);

    默认情况下，Example 是严格类型化的。这意味着映射后的查询包含类型匹配，将其限制为可探测的类型。 例如，当使用默认类型键（_class）时，查询具有诸如 (_class : { $in : [ com.acme.Person] }) 之类的限制。

    通过使用UntypedExampleMatcher，可以绕过默认行为并跳过类型限制。因此，只要字段名称匹配，几乎任何领域类型都可以用作创建引用的探针，如下例所示：

    示例 10。未类型化示例查询
    class JustAnArbitraryClassWithMatchingFieldName {
  @Field("lastname") String value;
}

JustAnArbitraryClassWithMatchingFieldNames probe = new JustAnArbitraryClassWithMatchingFieldNames();
probe.value = "stark";

Example example = Example.of(probe, UntypedExampleMatcher.matching());

Query query = new Query(new Criteria().alike(example));
List<Person> result = template.find(query, Person.class);

    在ExampleSpec中包含null值时，Spring Data Mongo 将使用嵌入文档匹配而非点号属性匹配。这样做会强制对所有属性值和嵌入文档中的属性顺序进行精确的文档匹配。

    如果您在单个集合中存储不同的实体，或者选择不编写类型提示，那么 UntypedExampleMatcher 很可能是您的最佳选择。

    此外，请注意使用@TypeAlias需要 eagerly 初始化MappingContext。为此，请配置initialEntitySet以确保读取操作能够正确解析别名。

    Spring Data MongoDB 支持不同的匹配选项：

    StringMatcher options
    匹配 逻辑结果

    DEFAULT (case-sensitive)

    {"firstname" : firstname}

    DEFAULT (case-insensitive)

    {"firstname" : { $regex: firstname, $options: 'i'}}

    EXACT (case-sensitive)

    {"firstname" : { $regex: /^firstname$/}}

    EXACT (case-insensitive)

    {"firstname" : { $regex: /^firstname$/, $options: 'i'}}

    STARTING (case-sensitive)

    {"firstname" : { $regex: /^firstname/}}

    STARTING (case-insensitive)

    {"firstname" : { $regex: /^firstname/, $options: 'i'}}

    ENDING (case-sensitive)

    {"firstname" : { $regex: /firstname$/}}

    ENDING (case-insensitive)

    {"firstname" : { $regex: /firstname$/, $options: 'i'}}

    CONTAINING (case-sensitive)
