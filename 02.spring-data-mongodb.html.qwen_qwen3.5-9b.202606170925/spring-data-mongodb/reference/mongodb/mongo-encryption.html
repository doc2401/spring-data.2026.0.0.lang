    Encryption

    客户端加密是一项功能，可在数据发送至 MongoDB 之前对其在您的应用程序中进行加密。 我们建议您先熟悉相关概念，理想情况下通过MongoDB 文档了解其能力和限制，然后再继续通过 Spring Data 应用加密功能。

    请确保将驱动程序设置 `com.mongodb.AutoEncryptionSettings` 以启用客户端加密。 MongoDB 不支持所有字段类型的加密。 某些数据类型需要确定性加密，以保持相等性比较功能。

    客户端字段级加密（CSFLE）

    选择 CSFLE 可为您提供完全的灵活性，并允许您为单个字段使用不同的密钥，例如在“每租户一个密钥”的场景中。
    请继续阅读前务必查阅 MongoDB CSFLE 文档。

    自动加密（CSFLE）

    MongoDB 原生支持通过 MongoDB 驱动程序及其自动加密功能实现客户端字段级加密。 自动加密需要提供一个JSON Schema，以便无需显式执行加密/解密步骤即可进行加密的读写操作。

    有关定义包含加密信息的 JSON Schema 的更多信息，请参阅JSON Schema部分。

    要使用 MongoJsonSchema，必须将其与 AutoEncryptionSettings 一起提供，这可以通过 MongoClientSettingsBuilderCustomizer 来实现。

    @Bean
MongoClientSettingsBuilderCustomizer customizer(MappingContext mappingContext) {
    return (builder) -> {

        // ... keyVaultCollection, kmsProvider, ...

        MongoJsonSchemaCreator schemaCreator = MongoJsonSchemaCreator.create(mappingContext);
        MongoJsonSchema patientSchema = schemaCreator
            .filter(MongoJsonSchemaCreator.encryptedOnly())
            .createSchemaFor(Patient.class);

        AutoEncryptionSettings autoEncryptionSettings = AutoEncryptionSettings.builder()
            .keyVaultNamespace(keyVaultCollection)
            .kmsProviders(kmsProviders)
            .extraOptions(extraOpts)
            .schemaMap(Collections.singletonMap("db.patient", patientSchema.schemaDocument().toBsonDocument()))
            .build();

        builder.autoEncryptionSettings(autoEncryptionSettings);
    };
}

    显式加密（CSFLE）

    显式加密使用 MongoDB 驱动程序的加密库（org.mongodb:mongodb-crypt）来执行加密和解密任务。 @ExplicitEncrypted 注解是用于 JSON Schema 创建 的 @Encrypted 注解与一个 属性转换器 的组合。 换句话说，@ExplicitEncrypted 利用现有的构建模块将它们组合在一起，以简化显式加密支持。

    使用 @ExplicitEncrypted 注解的字段始终会作为整体进行加密。 考虑以下示例：

    @ExplicitEncrypted(…)
String simpleValue;        (1)

@ExplicitEncrypted(…)
Address address;           (2)

@ExplicitEncrypted(…)
List<...> list;            (3)

@ExplicitEncrypted(…)
Map<..., ...> mapOfString; (4)
    1 如果值不为 null，则加密简单类型（如 String）的值。
    2 将整个 Address 对象及其所有嵌套字段作为 Document 进行加密。若要仅加密 Address 的部分字段（例如 Address#street），则需要在 Address 内部的 street 字段上添加 @ExplicitEncrypted 注解。
    3 类似 Collection 的字段被加密为单个值，而非按条目分别加密。
    4 类似 Map 的字段被加密为单个值，而非作为键/值对进行加密。

    客户端字段级加密允许您在确定性算法和随机化算法之间进行选择。根据所选算法，支持的操作可能有所不同。 要选择特定算法，请使用 @ExplicitEncrypted(algorithm)，有关算法常量的信息请参见 EncryptionAlgorithms。 请阅读加密类型手册以获取有关算法及其用法的更多信息。

    执行实际加密需要数据加密密钥（DEK）。有关如何设置密钥管理并创建数据加密密钥的更多信息，请参阅MongoDB 文档。 DEK 可以通过其 id 或定义的 替代名称 直接引用。 @EncryptedField 注解仅允许通过替代名称引用 DEK。 可以为任何 DEK 提供 EncryptionKeyResolver（稍后将讨论）。

    示例 1。引用数据加密密钥
    @EncryptedField(algorithm=…, altKeyName = "secret-key") (1)
String ssn;
    @EncryptedField(algorithm=…, altKeyName = "/name")      (2)
String ssn;
    1 使用与备用名称 secret-key 关联的 DEK。
    2 使用字段引用，该引用将读取实际的字段值并用于密钥查找。 保存操作始终需要完整的文档存在。 字段不能用于查询或聚合。

    默认情况下，@ExplicitEncrypted(value=…) 属性引用的是 MongoEncryptionConverter。您可以通过提供相应的类型引用来更改默认实现，并将其替换为任何 PropertyValueConverter 实现。有关自定义 PropertyValueConverters 及其所需配置的更多信息，请参阅属性转换器 - 映射特定字段部分。

    可查询加密（QE）

    选择查询加密（QE）可让您对加密字段执行不同类型的查询，例如范围或相等性查询。
    请继续阅读前务必查阅MongoDB 查询加密文档，以了解更多关于 QE 的功能和限制。

    集合设置

    可查询加密要求在针对加密字段执行实际查询之前，预先声明允许使用的某些方面。这些信息涵盖所使用的算法、允许的查询类型及其属性，并在创建集合时必须提供。

    MongoOperations#createCollection(…​) 可用于利用 QE 对集合进行初始设置。通过 Spring Data 配置的 QE 使用了与 CSFLE 相同的构建模块（即JSON Schema 创建），将模式/属性转换为 MongoDB 所需的配置格式。

    您可以手动或通过派生方式配置可查询加密：

    手动设置

    手动配置可让您完全控制加密字段的声明方式以及集合的创建方法。 当您需要显式管理数据密钥、加密算法和字段映射时，它非常有用。

    • ✅ 完全掌控加密配置

    • ✅ 显式管理数据密钥和算法

    • ✅ 支持复杂的加密场景

    • ✅ 显式配置可避免意外情况（例如，因注解不当或类路径扫描问题导致配置缺失）。

    • ⚠️ 显式字段配置可能与领域模型不一致，您必须确保其始终与领域模型保持同步。

    派生设置

    派生配置依赖于您领域模型中的注解，并自动从中生成所需的加密字段配置。 对于数据模型已添加注解的典型 Spring 应用程序，这种方式更简单且推荐使用。

    • ✅ 基于领域模型的配置

    • ✅ 易于设置和维护

    • ⚠️ 可能无法涵盖所有复杂场景

    • ⚠️ 存在意外风险（例如，由于标注不当或类路径扫描问题，导致基于子类型的文档缺少配置）

    BsonBinary pinDK = clientEncryption.createDataKey("local", new com.mongodb.client.model.vault.DataKeyOptions());
BsonBinary ssnDK = clientEncryption.createDataKey("local", new com.mongodb.client.model.vault.DataKeyOptions());
BsonBinary ageDK = clientEncryption.createDataKey("local", new com.mongodb.client.model.vault.DataKeyOptions());
BsonBinary signDK = clientEncryption.createDataKey("local", new com.mongodb.client.model.vault.DataKeyOptions());

CollectionOptions collectionOptions = CollectionOptions.encryptedCollection(options -> options
    .encrypted(string("pin"), pinDK)
    .queryable(encrypted(string("ssn")).algorithm("Indexed").keyId(ssnDK.asUuid()), equality().contention(0))
    .queryable(encrypted(int32("age")).algorithm("Range").keyId(ageDK.asUuid()), range().contention(8).min(0).max(150))
    .queryable(encrypted(int64("address.sign")).algorithm("Range").keyId(signDK.asUuid()), range().contention(2).min(-10L).max(10L))
);

mongoTemplate.createCollection(Patient.class, collectionOptions); (1)
    1 使用模板创建集合可能会阻止捕获生成的 keyIds。在这种情况下，请从选项中渲染 Document，并通过加密库使用 createEncryptedCollection(…​) 方法。 
    class Patient {

    @Id String id;        (1)

    Address address;      (1)

    @Encrypted(algorithm = "Unindexed")
    String pin;           (2)

    @Encrypted(algorithm = "Indexed")
    @Queryable(queryType = "equality", contentionFactor = 0)
    String ssn;           (3)

    @RangeEncrypted(contentionFactor = 8, rangeOptions = "{ 'min' : 0, 'max' : 150 }")
    Integer age;          (4)

    @RangeEncrypted(contentionFactor = 0L,
        rangeOptions = "{\"min\": {\"$numberDouble\": \"0.3\"}, \"max\": {\"$numberDouble\": \"2.5\"}, \"precision\": 2 }")
    double height;        (5)
}

MongoJsonSchema patientSchema = MongoJsonSchemaCreator.create(mappingContext)
    .filter(MongoJsonSchemaCreator.encryptedOnly())
    .createSchemaFor(Patient.class);

Document encryptedFields = CollectionOptions.encryptedCollection(patientSchema)
        .getEncryptedFieldsOptions()
        .map(CollectionOptions.EncryptedFieldsOptions::toDocument)
        .orElseThrow();

template.execute(db -> clientEncryption.createEncryptedCollection(db, template.getCollectionName(Patient.class), new CreateCollectionOptions()
        .encryptedFields(encryptedFields), new CreateEncryptedCollectionParams("local"))); (1)
    1 id 和 address 字段未加密，可以正常查询。
    2 pin 字段已加密但不支持查询。
    3 ssn 字段已加密，支持等值查询。
    4 age 字段已加密，支持在 0 到 150 之间进行范围查询。
    5 height 字段已加密，支持在 0.3 到 2.5 之间进行范围查询。

    `Queryable` 注解允许为加密字段定义允许的查询类型。 `@RangeEncrypted` 是 `@Encrypted` 和 `@Queryable` 的组合，适用于支持范围查询的字段。 可以基于提供的注解创建自定义注解。

    {
    name: 'patient',
    type: 'collection',
    options: {
      encryptedFields: {
        escCollection: 'enxcol_.test.esc',
        ecocCollection: 'enxcol_.test.ecoc',
        fields: [
          {
            keyId: ...,
            path: 'ssn',
            bsonType: 'string',
            queries: [ { queryType: 'equality', contention: Long('0') } ]
          },
          {
            keyId: ...,
            path: 'age',
            bsonType: 'int',
            queries: [ { queryType: 'range', contention: Long('8'), min: 0, max: 150 } ]
          },
          {
            keyId: ...,
            path: 'pin',
            bsonType: 'string'
          },
          {
            keyId: ...,
            path: 'address.sign',
            bsonType: 'long',
            queries: [ { queryType: 'range', contention: Long('2'), min: Long('-10'), max: Long('10') } ]
          }
        ]
      }
    }
}

    • 无法在同一集合中同时使用 QE 和 CSFLE。

    • 无法使用equality操作符查询range索引字段。

    • 无法使用范围运算符查询已建立等值索引的字段。

    • 无法设置。

    • 无法在可查询加密（Queryable Encryption）中使用通过 `@Encrypted` 维护的自管理加密密钥。

    • 服务器端仅支持可选的争用，客户端要求您设置该值（默认为 `8`）。

    • 例如，`min` 和 `max` 等附加选项必须与实际的字段类型相匹配。在解析 BSON 字符串时，请确保使用 `$numberLong` 等方法来保证目标类型。

    • 可查询加密会在您的每个文档中添加一个额外字段 `safeContent`。 除非显式排除，否则在检索结果时该字段会被加载到内存中。

    • 完整示例请参见： spring-data-queryable-encryption

    自动加密（QE）

    MongoDB 支持通过其自动加密功能，利用 MongoDB 驱动程序原生提供可查询加密。 自动加密需要一个JSON Schema，该模式允许执行加密的读写操作，而无需显式提供加密/解密步骤。

    您只需按照 MongoDB 文档创建集合即可。 您可以利用上述章节中概述的技术来创建所需的配置。

    显式加密（QE）

    显式加密使用 MongoDB 驱动程序的加密库（org.mongodb:mongodb-crypt），根据领域模型中注解提供的元信息执行加密和解密任务。

    目前官方并不支持使用显式可查询加密。 大胆的用户可以自行承担风险，将 `@Encrypted` 和 `@Queryable` 与 `@ValueConverter(MongoEncryptionConverter.class)` 组合使用。

    MongoEncryptionConverter 配置

    MongoEncryptionConverter 的转换器配置涉及多个组件，因此需要几个步骤。Bean 的配置包括以下内容：

    1. The ClientEncryption engine

    2. 一个配置了 ClientEncryption 和 EncryptionKeyResolver 的 MongoEncryptionConverter 实例。

    3. 一个使用已注册的 MongoEncryptionConverter 豆的 PropertyValueConverterFactory。

    EncryptionKeyResolver 使用一个 EncryptionContext，该上下文提供了访问属性的途径，从而支持动态的 DEK 解析。

    示例 2。MongoEncryptionConverter 配置样本
    class Config extends AbstractMongoClientConfiguration {

    @Autowired ApplicationContext appContext;

    @Bean
    ClientEncryption clientEncryption() {                                                            (1)
        ClientEncryptionSettings encryptionSettings = ClientEncryptionSettings.builder();
        // …

        return ClientEncryptions.create(encryptionSettings);
    }

    @Bean
    MongoEncryptionConverter encryptingConverter(ClientEncryption clientEncryption) {

        Encryption<BsonValue, BsonBinary> encryption = MongoClientEncryption.just(clientEncryption);
        EncryptionKeyResolver keyResolver = EncryptionKeyResolver.annotated((ctx) -> …);             (2)

        return new MongoEncryptionConverter(encryption, keyResolver);                                (3)
    }

    @Override
    protected void configureConverters(MongoConverterConfigurationAdapter adapter) {

        adapter
            .registerPropertyValueConverterFactory(PropertyValueConverterFactory.beanFactoryAware(appContext)); (4)
    }
}
    1 使用 com.mongodb.client.vault.ClientEncryption 配置一个 Encryption 引擎。该实例是有状态的，使用后必须关闭。Spring 会自动处理此操作，因为 ClientEncryption 实现了 Closeable 接口。
    2 配置基于注解的 EncryptionKeyResolver，以便从注解中确定 EncryptionKey。
    3 创建 MongoEncryptionConverter。
    4 启用从 BeanFactory 查找 PropertyValueConverter 的功能。
