    聚合框架支持

    Spring Data MongoDB 提供了对 MongoDB 在 2.2 版本中引入的聚合框架的支持。

    如需更多信息，请参阅聚合框架的完整参考文档以及 MongoDB 的其他数据聚合工具。

    基本概念

    Spring Data MongoDB 中的聚合框架支持基于以下关键抽象：Aggregation 和 AggregationResults。

    • Aggregation

      Aggregation 表示 MongoDB 的 aggregate 操作，并包含聚合管道指令的描述。聚合是通过调用 Aggregation 类的适当静态工厂方法 newAggregation(…) 创建的，该方法接受一个 AggregateOperation 列表和一个可选的输入类。

      实际的聚合操作由 `MongoTemplate` 的 `aggregate` 方法执行，该方法将期望的输出类作为参数传入。

    • TypedAggregation

      `TypedAggregation` 与 `Aggregation` 类似，既包含聚合管道的指令，又包含对输入类型的引用，该类型用于将领域属性映射到实际的文档字段。

      运行时，字段引用会根据给定的输入类型进行检查，并考虑潜在的 `@Field` 注解。

    在 3.2 版本中，引用不存在的属性不再抛出错误。若要恢复之前的行为，请使用AggregationOptions的strictMapping选项。

    • AggregationDefinition

      AggregationDefinition 表示 MongoDB 聚合管道操作，并描述应在该聚合步骤中执行的处理。尽管您可以手动创建 AggregationDefinition，但我们建议使用 Aggregate 类提供的静态工厂方法来构建 AggregateOperation。

    • AggregationResults

      `AggregationResults` 是聚合操作结果的容器。它提供对原始聚合结果（以 `Document` 形式）的访问，以及关于聚合的映射对象和其他信息。

      以下示例展示了使用 MongoDB 聚合框架的 Spring Data MongoDB 支持的标准范例：

      import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

Aggregation agg = newAggregation(
    pipelineOP1(),
    pipelineOP2(),
    pipelineOPn()
);

AggregationResults<OutputType> results = mongoTemplate.aggregate(agg, "INPUT_COLLECTION_NAME", OutputType.class);
List<OutputType> mappedResult = results.getMappedResults();

    请注意，如果您将输入类作为第一个参数传递给 newAggregation 方法，MongoTemplate 将从该类中推导输入集合的名称。否则，如果您未指定输入类，则必须显式提供输入集合的名称。如果同时提供了输入类和输入集合，以后者为准。

    支持的聚合操作与阶段

    MongoDB 聚合框架提供以下类型的聚合阶段和操作：

    • addFields - AddFieldsOperation

    • bucket / bucketAuto - BucketOperation / BucketAutoOperation

    • count - CountOperation

    • densify - DensifyOperation

    • facet - FacetOperation

    • geoNear - GeoNearOperation

    • graphLookup - GraphLookupOperation

    • group - GroupOperation

    • limit - LimitOperation

    • lookup - LookupOperation

    • match - MatchOperation

    • merge - MergeOperation

    • project - ProjectionOperation

    • redact - RedactOperation

    • replaceRoot - ReplaceRootOperation

    • sample - SampleOperation

    • set - SetOperation

    • setWindowFields - SetWindowFieldsOperation

    • skip - SkipOperation

    • sort / sortByCount - SortOperation / SortByCountOperation

    • unionWith - UnionWithOperation

    • unset - UnsetOperation

    • unwind - UnwindOperation

    不支持的聚合阶段（例如 MongoDB Atlas 的$search）可以通过实现AggregationOperation来提供。 Aggregation.stage是用于通过提供其 JSON 或Bson表示形式来注册管道阶段的快捷方式。

    Aggregation.stage("""
    { $search : {
        "near": {
          "path": "released",
          "origin": { "$date": { "$numberLong": "..." } } ,
          "pivot": 7
        }
      }
    }
""");

    投影表达式

    投影表达式用于定义特定聚合步骤的输出字段。可以通过 Aggregation 类的 project 方法定义投影表达式，该方法接受一个 String 对象列表或聚合框架的 Fields 对象作为参数。还可以使用流式 API 中的 and(String) 方法添加更多字段，并使用 as(String) 方法为字段设置别名。 请注意，您也可以通过聚合框架中 Fields.field 静态工厂方法来定义带别名的字段，然后使用该对象构建一个新的 Fields 实例。后续聚合阶段中对投影字段的引用仅对已包含字段或其别名（包括新定义的字段及其别名）有效。未包含在投影中的字段无法在后续聚合阶段中被引用。以下示例展示了投影表达式的用法：

    示例 1。投影表达式示例
    // generates {$project: {name: 1, netPrice: 1}}
project("name", "netPrice")

// generates {$project: {thing1: $thing2}}
project().and("thing1").as("thing2")

// generates {$project: {a: 1, b: 1, thing2: $thing1}}
project("a","b").and("thing1").as("thing2")
    示例 2：使用投影和排序进行多阶段聚合
    // generates {$project: {name: 1, netPrice: 1}}, {$sort: {name: 1}}
project("name", "netPrice"), sort(ASC, "name")

// generates {$project: {name: $firstname}}, {$sort: {name: 1}}
project().and("firstname").as("name"), sort(ASC, "name")

// does not work
project().and("firstname").as("name"), sort(ASC, "firstname")

    有关项目操作的更多示例，请参阅AggregationTests类。请注意，关于投影表达式的进一步详细信息，可参考MongoDB聚合框架参考文档中的相应部分。

    分面分类

    从版本 3.4 开始，MongoDB 支持使用聚合框架进行分面分类。分面分类采用语义类别（可以是通用类别或特定主题类别）并将其组合以创建完整的分类条目。流经聚合管道的文档会被分类到相应的桶中。多分面分类允许对同一组输入文档执行各种聚合操作，而无需多次检索这些输入文档。

    Buckets

    Bucket 操作根据指定的表达式和桶边界，将传入的文档分类到称为“桶”的组中。Bucket 操作需要一个分组字段或分组表达式。您可以使用 Aggregate 类的 bucket() 和 bucketAuto() 方法来定义它们。BucketOperation 和 BucketAutoOperation 可以基于输入文档的聚合表达式暴露累积结果。您可以通过使用 with…() 方法和 andOutput(String) 方法，通过流式 API 为 Bucket 操作添加额外参数。您可以使用 as(String) 方法为操作设置别名。每个桶在输出中均表示为一个文档。

    `BucketOperation` 接收一组预定义的边界，用于将传入的文档分组到这些类别中。边界必须是排序好的。以下示例展示了某些分桶操作的用法：

    示例 3。Bucket 操作示例
    // generates {$bucket: {groupBy: $price, boundaries: [0, 100, 400]}}
bucket("price").withBoundaries(0, 100, 400);

// generates {$bucket: {groupBy: $price, default: "Other" boundaries: [0, 100]}}
bucket("price").withBoundaries(0, 100).withDefault("Other");

// generates {$bucket: {groupBy: $price, boundaries: [0, 100], output: { count: { $sum: 1}}}}
bucket("price").withBoundaries(0, 100).andOutputCount().as("count");

// generates {$bucket: {groupBy: $price, boundaries: [0, 100], 5, output: { titles: { $push: "$title"}}}
bucket("price").withBoundaries(0, 100).andOutput("title").push().as("titles");

    `BucketAutoOperation` 通过确定边界，尝试将文档均匀分配到指定数量的桶中。`BucketAutoOperation` 可选地接受一个粒度值，该值用于指定要使用的优选数系列，以确保计算出的边界边缘落在优选的整数或 10 的幂上。以下示例展示了桶操作：

    示例 4。Bucket 操作示例
    // generates {$bucketAuto: {groupBy: $price, buckets: 5}}
bucketAuto("price", 5)

// generates {$bucketAuto: {groupBy: $price, buckets: 5, granularity: "E24"}}
bucketAuto("price", 5).withGranularity(Granularities.E24).withDefault("Other");

// generates {$bucketAuto: {groupBy: $price, buckets: 5, output: { titles: { $push: "$title"}}}
bucketAuto("price", 5).andOutput("title").push().as("titles");

    要在桶中创建输出字段，桶操作可以通过AggregationExpression使用andOutput()，并通过andOutputExpression()使用SpEL 表达式。

    请注意，有关桶表达式的更多详细信息可以在 MongoDB 聚合框架参考文档的 $bucket 和 $bucketAuto 部分中找到。

    多面聚合

    可以使用多个聚合管道来创建多面聚合，从而在单个聚合阶段内对数据按多个维度（或方面）进行特征描述。多面聚合提供了多种过滤器和分类方式，以指导数据浏览和分析。一种常见的方面实现方式是，许多在线零售商允许用户通过应用产品价格、制造商、尺寸及其他因素的过滤器来缩小搜索结果范围。

    您可以使用 `Aggregation` 类的 `facet()` 方法来定义一个 `FacetOperation`。您可以通过 `and()` 方法使用多个聚合管道对其进行自定义。每个子管道在输出文档中都有自己的字段，其结果以文档数组的形式存储在该字段中。

    子流水线可以在分组之前对输入文档进行投影和过滤。常见用例包括在分类之前提取日期部分或执行计算。以下示例展示了面操作：

    示例 5。Facet 操作示例
    // generates {$facet: {categorizedByPrice: [ { $match: { price: {$exists : true}}}, { $bucketAuto: {groupBy: $price, buckets: 5}}]}}
facet(match(Criteria.where("price").exists(true)), bucketAuto("price", 5)).as("categorizedByPrice"))

// generates {$facet: {categorizedByCountry: [ { $match: { country: {$exists : true}}}, { $sortByCount: "$country"}]}}
facet(match(Criteria.where("country").exists(true)), sortByCount("country")).as("categorizedByCountry"))

// generates {$facet: {categorizedByYear: [
//     { $project: { title: 1, publicationYear: { $year: "publicationDate"}}},
//     { $bucketAuto: {groupBy: $price, buckets: 5, output: { titles: {$push:"$title"}}}
// ]}}
facet(project("title").and("publicationDate").extractYear().as("publicationYear"),
      bucketAuto("publicationYear", 5).andOutput("title").push().as("titles"))
  .as("categorizedByYear"))

    请注意，有关 facet 操作的更多详细信息可以在 MongoDB 聚合框架参考文档的$facet部分中找到。

    按计数排序

    按计数操作根据指定表达式的值对传入文档进行分组，计算每个不同组中的文档数量，并按计数对结果进行排序。它提供了一种便捷的快捷方式，可在使用分面分类时应用排序。按计数操作需要一个分组字段或分组表达式。以下示例展示了按计数排序的情况：

    示例 6：按计数排序示例
    // generates { $sortByCount: "$country" }
sortByCount("country");

    按计数排序操作等效于以下 BSON（二进制 JSON）：

    { $group: { _id: <expression>, count: { $sum: 1 } } },
{ $sort: { count: -1 } }

    投影表达式中的 Spring 表达式支持

    我们支持在 `ProjectionOperation` 和 `BucketOperation` 类的 `andExpression` 方法中使用 SpEL 表达式作为投影表达式。此功能允许您将所需的表达式定义为 SpEL 表达式。在执行查询时，SpEL 表达式会被转换为相应的 MongoDB 投影表达式部分。这种安排使得表达复杂的计算变得更加容易。

    使用 SpEL 表达式进行复杂计算

    考虑以下 SpEL 表达式：

    1 + (q + 1) / (q - 1)

    前述表达式被转换为以下投影表达式部分：

    { "$add" : [ 1, {
    "$divide" : [ {
        "$add":["$q", 1]}, {
        "$subtract":[ "$q", 1]}
    ]
}]}

    您可以在聚合框架示例 5和聚合框架示例 6中查看更完整的上下文示例。 有关支持的 SpEL 表达式构造的更多使用示例，请参阅SpelExpressionTransformerUnitTests。

    聚合框架示例

    本节中的示例展示了在 Spring Data MongoDB 中使用 MongoDB 聚合框架的模式。

    聚合框架示例 1

    在本入门示例中，我们要聚合一个标签列表，以获取来自 MongoDB 集合（称为 tags）中特定标签的出现次数，并按出现次数降序排序。本示例展示了分组、排序、投影（选择）以及展开（结果拆分）的使用方法。

    class TagCount {
 String tag;
 int n;
}
    import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

Aggregation agg = newAggregation(
    project("tags"),
    unwind("tags"),
    group("tags").count().as("n"),
    project("n").and("tag").previousOperation(),
    sort(DESC, "n")
);

AggregationResults<TagCount> results = mongoTemplate.aggregate(agg, "tags", TagCount.class);
List<TagCount> tagCount = results.getMappedResults();

    前述列表使用了以下算法：

    1. 使用 `newAggregation` 静态工厂方法创建一个新的聚合，并传入一个聚合操作列表。这些聚合操作定义了我们的 `Aggregation` 的聚合管道。

    2. 使用 `project` 操作从输入集合中选取 `tags` 字段（该字段为字符串数组）。

    3. 使用unwind操作为tags数组中的每个标签生成一个新文档。

    4. 使用group操作为每个tags值定义一个组，并聚合其出现次数（通过使用count聚合算子并将结果收集到一个名为n的新字段中）。

    5. 选择 `n` 字段，并为上一个分组操作生成的 ID 字段创建一个名为 `tag` 的别名（因此需要调用 `previousOperation()`）。

    6. 使用 `sort` 操作按出现次数降序对生成的标签列表进行排序。

    7. 在 MongoTemplate 上调用 aggregate 方法，将创建的 Aggregation 作为参数传入，以让 MongoDB 执行实际的聚合操作。

    请注意，输入集合被显式指定为传递给 `aggregate` 方法的 `tags` 参数。如果未显式指定输入集合的名称，则它将从作为第一个参数传递给 `newAggreation` 方法的输入类中推导出来。

    聚合框架示例 2

    本示例基于 MongoDB 聚合框架文档中的按州划分的最大城市和最小城市示例。我们添加了额外的排序，以确保在不同版本的 MongoDB 中产生稳定的结果。在此示例中，我们希望使用聚合框架返回每个州人口最少和最多的城市。本示例展示了分组、排序和投影（选择）操作。

    class ZipInfo {
   String id;
   String city;
   String state;
   @Field("pop") int population;
   @Field("loc") double[] location;
}

class City {
   String name;
   int population;
}

class ZipInfoStats {
   String id;
   String state;
   City biggestCity;
   City smallestCity;
}
    import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

TypedAggregation<ZipInfo> aggregation = newAggregation(ZipInfo.class,
    group("state", "city")
       .sum("population").as("pop"),
    sort(ASC, "pop", "state", "city"),
    group("state")
       .last("city").as("biggestCity")
       .last("pop").as("biggestPop")
       .first("city").as("smallestCity")
       .first("pop").as("smallestPop"),
    project()
       .and("state").previousOperation()
       .and("biggestCity")
          .nested(bind("name", "biggestCity").and("population", "biggestPop"))
       .and("smallestCity")
          .nested(bind("name", "smallestCity").and("population", "smallestPop")),
    sort(ASC, "state")
);

AggregationResults<ZipInfoStats> result = mongoTemplate.aggregate(aggregation, ZipInfoStats.class);
ZipInfoStats firstZipInfoStats = result.getMappedResults().get(0);

    请注意，ZipInfo 类映射给定输入集合的结构。ZipInfoStats 类定义所需输出格式的结构。

    前述列表采用以下算法：

    1. 使用 `group` 操作从输入集合中定义分组。分组依据是 `state` 和 `city` 字段的组合，它们构成了分组的 ID 结构。我们使用 `sum` 操作符对分组元素的 `population` 属性值进行聚合，并将结果保存在 `pop` 字段中。

    2. 使用sort操作按pop、state和city字段对中间结果进行升序排序，使得城市最小的记录位于结果顶部，城市最大的记录位于底部。请注意，对state和city的排序是隐式针对组 ID 字段进行的（由 Spring Data MongoDB 处理）。

    3. 再次使用group操作，根据state对中间结果进行分组。注意，state同样隐式引用了一个组 ID 字段。在project操作中，我们分别通过调用last(…)和first(…​)操作符，选择名称最大和最小的城市及其人口数量。

    4. 从上一个group操作中选取state字段。请注意，state再次隐式引用了一个组 ID 字段。由于我们不希望出现隐式生成的 ID，因此通过使用and(previousOperation()).exclude()将 ID 从之前的操作中排除。因为我们要在输出类中填充嵌套的City结构，所以必须使用嵌套方法发出适当的子文档。

    5. 在 `sort` 操作中，按州名升序对生成的 `StateStats` 列表进行排序。

    请注意，输入集合的名称是从作为newAggregation方法第一个参数传递的ZipInfo类中派生的。

    聚合框架示例 3

    本示例基于 MongoDB 聚合框架文档中的人口超过 1000 万的国家示例。我们添加了额外的排序操作，以确保在不同版本的 MongoDB 中产生稳定的结果。本例旨在使用聚合框架返回所有人口超过 1000 万的国家，并演示了分组、排序和匹配（过滤）操作。

    class StateStats {
   @Id String id;
   String state;
   @Field("totalPop") int totalPopulation;
}
    import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

TypedAggregation<ZipInfo> agg = newAggregation(ZipInfo.class,
    group("state").sum("population").as("totalPop"),
    sort(ASC, previousOperation(), "totalPop"),
    match(where("totalPop").gte(10 * 1000 * 1000))
);

AggregationResults<StateStats> result = mongoTemplate.aggregate(agg, StateStats.class);
List<StateStats> stateStatsList = result.getMappedResults();

    前述列表采用以下算法：

    1. 按 `state` 字段对输入集合进行分组，计算 `population` 字段的总和，并将结果存储在新字段 `"totalPop"` 中。

    2. 按前一组操作的 id-reference 以及"totalPop"字段对中间结果进行升序排序。

    3. 使用接受Criteria查询作为参数的match操作来过滤中间结果。

    请注意，输入集合的名称是从作为newAggregation方法第一个参数传递的ZipInfo类中派生的。

    聚合框架示例 4

    本示例演示了投影运算中简单算术操作的使用。

    class Product {
    String id;
    String name;
    double netPrice;
    int spaceUnits;
}
    import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

TypedAggregation<Product> agg = newAggregation(Product.class,
    project("name", "netPrice")
        .and("netPrice").plus(1).as("netPricePlus1")
        .and("netPrice").minus(1).as("netPriceMinus1")
        .and("netPrice").multiply(1.19).as("grossPrice")
        .and("netPrice").divide(2).as("netPriceDiv2")
        .and("spaceUnits").mod(2).as("spaceUnitsMod2")
);

AggregationResults<Document> result = mongoTemplate.aggregate(agg, Document.class);
List<Document> resultList = result.getMappedResults();

    请注意，输入集合的名称是从作为newAggregation方法第一个参数传递的Product类中派生的。

    聚合框架示例 5

    本示例演示了在投影操作中如何使用源自 SpEL 表达式的简单算术运算。

    class Product {
    String id;
    String name;
    double netPrice;
    int spaceUnits;
}
    import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

TypedAggregation<Product> agg = newAggregation(Product.class,
    project("name", "netPrice")
        .andExpression("netPrice + 1").as("netPricePlus1")
        .andExpression("netPrice - 1").as("netPriceMinus1")
        .andExpression("netPrice / 2").as("netPriceDiv2")
        .andExpression("netPrice * 1.19").as("grossPrice")
        .andExpression("spaceUnits % 2").as("spaceUnitsMod2")
        .andExpression("(netPrice * 0.8  + 1.2) * 1.19").as("grossPriceIncludingDiscountAndCharge")

);

AggregationResults<Document> result = mongoTemplate.aggregate(agg, Document.class);
List<Document> resultList = result.getMappedResults();

    聚合框架示例 6

    本示例展示了在投影操作中如何使用源自 SpEL 表达式的复杂算术运算。

    注意：传递给addExpression方法的额外参数可以根据其位置使用索引表达式进行引用。在本示例中，我们使用[0]引用参数数组中的第一个参数。当 SpEL 表达式转换为 MongoDB 聚合框架表达式时，外部参数表达式将被替换为其各自的值。

    class Product {
    String id;
    String name;
    double netPrice;
    int spaceUnits;
}
    import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

double shippingCosts = 1.2;

TypedAggregation<Product> agg = newAggregation(Product.class,
    project("name", "netPrice")
        .andExpression("(netPrice * (1-discountRate)  + [0]) * (1+taxRate)", shippingCosts).as("salesPrice")
);

AggregationResults<Document> result = mongoTemplate.aggregate(agg, Document.class);
List<Document> resultList = result.getMappedResults();

    请注意，在 SpEL 表达式中，我们也可以引用文档中的其他字段。

    聚合框架示例 7

    本示例使用条件投影。它源自$cond 参考文档。

    public class InventoryItem {

  @Id int id;
  String item;
  String description;
  int qty;
}

public class InventoryItemProjection {

  @Id int id;
  String item;
  String description;
  int qty;
  int discount
}
    import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

TypedAggregation<InventoryItem> agg = newAggregation(InventoryItem.class,
  project("item").and("discount")
    .applyCondition(ConditionalOperator.newBuilder().when(Criteria.where("qty").gte(250))
      .then(30)
      .otherwise(20))
    .and(ifNull("description", "Unspecified")).as("description")
);

AggregationResults<InventoryItemProjection> result = mongoTemplate.aggregate(agg, "inventory", InventoryItemProjection.class);
List<InventoryItemProjection> stateStatsList = result.getMappedResults();

    此一步聚合操作使用了对inventory集合的投影。我们利用条件操作，对所有库存项中qty大于或等于250的项目投影discount字段。随后，对description字段执行了第二次条件投影。我们将Unspecified描述应用于所有缺少description字段或该字段值为null的项目。

    从 MongoDB 3.6 版本开始，可以使用条件表达式来排除投影中的字段。

    示例 7：条件聚合投影
    TypedAggregation<Book> agg = Aggregation.newAggregation(Book.class,
  project("title")
    .and(ConditionalOperators.when(ComparisonOperators.valueOf("author.middle")     (1)
        .equalToValue(""))                                                          (2)
        .then("$$REMOVE")                                                           (3)
        .otherwiseValueOf("author.middle")                                          (4)
    )
	.as("author.middle"));
    1 如果字段 author.middle 的值
    2 不包含任何值，
    3 则使用 $$REMOVE 来排除该字段。
    4 否则，添加 author.middle 的字段值。
