    保存、更新和删除文档

    MongoTemplate 和 ReactiveMongoTemplate 允许您保存、更新和删除领域对象，并将这些对象映射到存储在 MongoDB 中的文档。命令式和响应式 API 的签名基本相同，仅在返回类型上有所区别。同步 API 使用 void、单个 Object 和 List，而对应的响应式版本则使用 Mono<Void>、Mono<Object> 和 Flux。

    考虑以下类：

    public class Person {

	private String id;
	private String name;
	private int age;

	public Person(String name, int age) {
		this.name = name;
		this.age = age;
	}

	public String getId() {
		return id;
	}

	public String getName() {
		return name;
	}

	public int getAge() {
		return age;
	}

	@Override
	public String toString() {
		return "Person [id=" + id + ", name=" + name + ", age=" + age + "]";
	}
}

    在上面的示例中，给定`Person`类，您可以保存、更新和删除该对象，如下例所示：

    • Imperative

    • Reactive

    public class MongoApplication {

  private static final Log log = LogFactory.getLog(MongoApplication.class);

  public static void main(String[] args) {

    MongoOperations template = new MongoTemplate(new SimpleMongoClientDbFactory(MongoClients.create(), "database"));

    Person p = new Person("Joe", 34);

    // Insert is used to initially store the object into the database.
    template.insert(p);
    log.info("Insert: " + p);

    // Find
    p = template.findById(p.getId(), Person.class);
    log.info("Found: " + p);

    // Update
    template.updateFirst(query(where("name").is("Joe")), update("age", 35), Person.class);
    p = template.findOne(query(where("name").is("Joe")), Person.class);
    log.info("Updated: " + p);

    // Delete
    template.remove(p);

    // Check that deletion worked
    List<Person> people =  template.findAll(Person.class);
    log.info("Number of people = : " + people.size());


    template.dropCollection(Person.class);
  }
}

    public class ReactiveMongoApplication {

  private static final Logger log = LoggerFactory.getLogger(ReactiveMongoApplication.class);

  public static void main(String[] args) throws Exception {

    CountDownLatch latch = new CountDownLatch(1);

    ReactiveMongoTemplate template = new ReactiveMongoTemplate(MongoClients.create(), "database");

    template.insert(new Person("Joe", 34)).doOnNext(person -> log.info("Insert: " + person))
      .flatMap(person -> template.findById(person.getId(), Person.class))
      .doOnNext(person -> log.info("Found: " + person))
      .zipWith(person -> template.updateFirst(query(where("name").is("Joe")), update("age", 35), Person.class))
      .flatMap(tuple -> template.remove(tuple.getT1())).flatMap(deleteResult -> template.findAll(Person.class))
      .count().doOnSuccess(count -> {
        log.info("Number of people: " + count);
        latch.countDown();
      })

      .subscribe();

    latch.await();
  }
}

    MongoConverter 通过约定识别名为 Id 的属性，从而在数据库中存储的 String 和 ObjectId 之间触发了隐式转换。

    前面的示例旨在展示对 `MongoTemplate` / `ReactiveMongoTemplate` 的保存、更新和删除操作的使用，而非展示复杂的映射功能。 前面示例中使用的查询语法在“查询文档"一节中有更详细的说明。

    MongoDB 要求所有文档都必须包含一个 _id 字段。有关该字段的特殊处理方式，请参阅ID 处理部分以获取详细信息。
    MongoDB 集合可以包含代表多种类型实例的文档。有关详细信息，请参阅类型映射。

    Insert / Save

    在 `MongoTemplate` 上存在几种便捷的方法来保存和插入对象。 若需对转换过程进行更精细的控制，您可以向 `MappingMongoConverter` 注册 Spring 转换器——例如 `Converter` 和 `Converter`。

    插入和保存操作的区别在于：如果对象尚未存在，保存操作会执行插入。

    使用保存操作的简单情况是保存一个 POJO。 在这种情况下，集合名称由类的名称（非完全限定名）确定。 您也可以指定集合名称来调用保存操作。 您可以使用映射元数据覆盖存储对象的集合。

    在插入或保存时，如果未设置 `Id` 属性，则假定其值将由数据库自动生成。因此，若要成功自动生成本类中的 `Id` 属性或字段的 `ObjectId`，该属性的类型必须是 `String`、`ObjectId` 或 `BigInteger`。

    以下示例展示了如何保存文档并检索其内容：

    使用 MongoTemplate 插入和检索文档

    • Reactive

    import static org.springframework.data.mongodb.core.query.Criteria.where;
import static org.springframework.data.mongodb.core.query.Criteria.query;

//...

Person person = template.query(Person.class)
    .matching(query(where("age").is(33)))

        .one());

    可用的插入和保存操作如下：

    • void save (Object objectToSave)：将对象保存到默认集合中。

    • void save (Object objectToSave, String collectionName)：将对象保存到指定的集合中。

    同样也提供一组类似的插入操作：

    • void insert (Object objectToSave)：将对象插入默认集合。

    • void insert (Object objectToSave, String collectionName)：将对象插入到指定的集合中。

    映射层中如何处理 _id 字段

    MongoDB 要求所有文档都必须包含一个 `_id` 字段。 如果您未提供该字段，驱动程序会分配一个 `ObjectId` 并生成一个值，而不会考虑您的领域模型，因为服务器并不了解您的标识符类型。 当您使用 `MappingMongoConverter` 时，某些规则将决定如何从 Java 类属性映射到该 `_id` 字段：

    1. 使用 @Id（org.springframework.data.annotation.Id）注解的属性或字段将映射到 _id 字段。

    2. 未添加注解但命名为id的属性或字段将映射到_id字段。

    以下概述了在使用 MappingMongoConverter（MongoTemplate 的默认转换器）时，映射到 _id 文档字段的属性是否进行类型转换。

    1. 如果可能，Java 类中声明为 String 的 id 属性或字段会通过 Spring 的 Converter<String, ObjectId> 转换为 ObjectId 并存储。有效的转换规则由 MongoDB Java 驱动委托处理。如果无法转换为 ObjectId，则该值将以字符串形式存储在数据库中。

    2. 声明为 Date 的 id 属性或字段会被转换为并存储为 ObjectId。

    3. Java 类中声明为 BigInteger 的 id 属性或字段，将通过使用 Spring 的 Converter<BigInteger, ObjectId> 转换为 ObjectId 并存储。

    如果前一组规则中未指定任何字段或属性，而 Java 类中也缺少相应的内容，驱动程序会生成一个隐式的 `_id` 文件，但该文件不会映射到 Java 类的任何属性或字段上。

    在查询和更新时，MongoTemplate 会使用与前述保存文档规则相对应的转换器，以确保您在查询中使用的字段名称和类型能够与您的领域类中的内容相匹配。

    某些环境需要采用定制化的方法来映射 `Id` 值，例如存储在 MongoDB 中且未经过 Spring Data 映射层处理的数据。文档可能包含 `_id` 值，这些值可以表示为 `ObjectId` 或 `String`。从存储中读取文档并转换回领域类型的工作正常。然而，通过其 `id` 查询文档可能会很繁琐，因为存在隐式的 `ObjectId` 转换问题，因此无法以这种方式检索文档。对于这些情况，`@MongoId` 提供了对实际 id 映射尝试的更多控制。

    示例 1。@MongoId 映射
    public class PlainStringId {
  @MongoId String id; (1)
}

public class PlainObjectId {
  @MongoId ObjectId id; (2)
}

public class StringToObjectId {
  @MongoId(FieldType.OBJECT_ID) String id; (3)
}
    1 ID 被视为 String，无需进一步转换。
    2 ID 被视为 ObjectId。
    3 如果给定的 String 是有效的 ObjectId 十六进制字符串，则 ID 被视为 ObjectId；否则视为 String。对应于 @Id 的用法。

    文档将保存到哪个集合？

    管理文档所用集合名称有两种方式。默认情况下，使用的集合名称是将类名转换为以小写字母开头，因此com.test.Person类会被存储在person集合中。您可以通过使用@Document注解提供不同的集合名称来自定义此行为。此外，您还可以在选定的MongoTemplate方法调用中将自定义集合名称作为最后一个参数来覆盖集合名称。

    插入或保存单个对象

    MongoDB 驱动程序支持在一次操作中插入一批文档。 以下 MongoOperations 接口中的方法支持此功能：

    • insert：插入对象。 如果已存在具有相同 id 的文档，将生成错误。

    • insertAll：将对象集合作为第一个参数接收。 此方法会检查每个对象，并根据之前指定的规则将其插入到相应的集合中。

    • save：保存对象，覆盖任何具有相同 id 的对象。

    批量插入多个对象

    MongoDB 驱动程序支持在一次操作中插入一批文档。 `MongoOperations` 接口中的以下方法通过 `insert`、`bulkWrite`（需要 MongoDB 8.0+）或专用的 `BulkOperations` 接口来支持此功能。

    批量插入

    • Imperative

    • Reactive

    Collection<Person> inserted = template.insert(List.of(...), Person.class);
    Flux<Person> inserted = template.insert(List.of(...), Person.class);

    批量写入

    BulkWrite 允许您通过单个请求执行插入、更新和删除操作。

    MongoDB 8.0 引入了跨集合的批量写入功能。

    当您需要在一个请求中混合执行插入、更新和删除操作时（可选地在多个集合之间进行，适用于 MongoDB 8.0+），请使用 bulkWrite(Bulk, BulkWriteOptions)。 如果您的目标是单个集合，您仍然可以利用新的 bulkWrite 方法配合旧版 MongoDB 服务器版本，或者继续使用经典的 bulkOps(BulkMode, Class) API。
    批量写入（多个集合）

    • Imperative

    • Reactive

    Bulk bulk = Bulk.create(builder -> builder
        .inCollection(Person.class, spec -> spec
                .insert(person1)
                .insert(person2)
                .upsert(where("_id").is("..."), new Update().set("firstname", "...")))
        .inCollection(User.class, spec -> spec.insert(new User("..."))));

BulkWriteResult result = template.bulkWrite(bulk, BulkWriteOptions.ordered());
    Bulk bulk = Bulk.create(builder -> builder
        .inCollection(Person.class, spec -> spec
                .insert(person1)
                .insert(person2)
                .upsert(where("_id").is("..."), new Update().set("firstname", "...")))
        .inCollection(User.class, spec -> spec.insert(new User("..."))));

template.bulkWrite(bulk, BulkWriteOptions.ordered()).subscribe();
    批量写入（单个集合）

    • Imperative

    • Reactive

    BulkWriteResult result = template.bulkOps(BulkMode.ORDERED, Person.class)
    .insert(List.of(...))
    .execute();
    Mono<BulkWriteResult> result = template.bulkOps(BulkMode.ORDERED, Person.class)
    .insert(List.of(...))
    .execute();

    批量和单个操作的服务器性能相同。 然而，批量操作由于可以针对单个请求进行操作，因此使用的资源更少。 批量操作的生命周期事件发布受到限制。

    任何在调用 insert 之前未设置的 @Version 属性，将自动初始化为 1（对于简单类型如 int）或 0（对于包装类型，例如 Integer）。
    有关更多信息，请参阅乐观锁部分。

    Update

    若要更新数据，您可以使用 MongoOperations.updateFirst 方法更新找到的第一个文档，也可以使用 MongoOperations.updateMulti 方法或流式 API 中的 all 选项来更新所有匹配查询条件的文档。 以下示例展示了如何使用 $inc 运算符向所有 SAVINGS 账户余额中添加一次性 50.00 美元奖金：

    使用 MongoTemplate / ReactiveMongoTemplate 更新文档

    • Imperative

    • Reactive

    import static org.springframework.data.mongodb.core.query.Criteria.where;
import org.springframework.data.mongodb.core.query.Update;

// ...

UpdateResult result = template.update(Account.class)
    .matching(where("accounts.accountType").is(Type.SAVINGS))
    .apply(new Update().inc("accounts.$.balance", 50.00))
    .all();
    import static org.springframework.data.mongodb.core.query.Criteria.where;
import org.springframework.data.mongodb.core.query.Update;

// ...

Mono<UpdateResult> result = template.update(Account.class)
    .matching(where("accounts.accountType").is(Type.SAVINGS))
    .apply(new Update().inc("accounts.$.balance", 50.00))
    .all();

    除了前面讨论的Query，我们还通过Update对象提供更新定义。 Update类提供了与 MongoDB 可用的更新修饰符相匹配的方法。 大多数方法返回Update对象，以支持 API 的链式调用风格。

    如果未在 Update 中包含 @Version 属性，则该属性将自动递增。 有关更多信息，请参阅乐观锁部分。

    运行文档更新的方法

    • updateFirst：使用更新的文档更新与查询文档条件匹配的第一个文档。

    • updateMulti：使用更新后的文档更新所有匹配查询文档条件的对象。

    updateFirst 不支持 MongoDB 8.0 以下版本的排序。如果您使用的是旧版本，请使用 findAndModify 来应用 Sort。
    可以通过 Query.withHint(…​) 为更新操作提供索引提示。

    Update 类中的方法

    您可以使用一些“语法糖”来配合 `Update` 类，因为其方法设计为可以链式调用。此外，您可以通过使用 `public static Update update(String key, Object value)` 方法和静态导入来快速启动新 `Update` 实例的创建。

    `Update` 类包含以下方法：

    • Update addToSet (String key, Object value) 使用 $addToSet 更新修饰符进行更新

    • Update currentDate (String key) 使用 $currentDate 更新修饰符进行更新

    • Update currentTimestamp (String key) 使用 $currentDate 更新修饰符，并将 $type 设置为 timestamp。

    • Update inc (String key, Number inc) 使用 $inc 更新修饰符进行更新

    • Update max (String key, Object max) 使用 $max 更新修饰符进行更新

    • Update min (String key, Object min) 使用 $min 更新修饰符进行更新

    • Update 使用 $mul 更新修饰符来相乘 (String key, Number multiplier)

    • Update pop (String key, Update.Position pos) 使用 $pop 更新修饰符进行更新。

    • Update pull (String key, Object value) 使用 $pull 更新修饰符进行更新。

    • Update pullAll (String key, Object[] values) 使用 $pullAll 更新修饰符进行更新。

    • Update push (String key, Object value) 使用 $push 更新修饰符进行更新。

    • Update pushAll (String key, Object[] values) 使用 $pushAll 更新修饰符进行更新。

    • Update 重命名 (String oldName, String newName) 使用 $rename 更新修饰符进行更新

    • Update set (String key, Object value) 使用 $set 更新修饰符进行更新

    • Update setOnInsert (String key, Object value) 使用 $setOnInsert 更新修饰符进行更新

    • Update unset (String key) 使用 $unset 更新修饰符进行更新。

    某些更新修饰符（如 $push 和 $addToSet）允许嵌套其他操作符。

    // { $push : { "category" : { "$each" : [ "spring" , "data" ] } } }
new Update().push("category").each("spring", "data")

// { $push : { "key" : { "$position" : 0 , "$each" : [ "Arya" , "Arry" , "Weasel" ] } } }
new Update().push("key").atPosition(Position.FIRST).each(Arrays.asList("Arya", "Arry", "Weasel"));

// { $push : { "key" : { "$slice" : 5 , "$each" : [ "Arya" , "Arry" , "Weasel" ] } } }
new Update().push("key").slice(5).each(Arrays.asList("Arya", "Arry", "Weasel"));

// { $addToSet : { "values" : { "$each" : [ "spring" , "data" , "mongodb" ] } } }
new Update().addToSet("values").each("spring", "data", "mongodb");

    聚合管道更新

    `MongoOperations`和`ReactiveMongoOperations`暴露的更新方法也通过`AggregationUpdate`接受聚合管道。使用`AggregationUpdate`可以在更新操作中利用MongoDB 4.2 的聚合功能。在更新操作中使用聚合允许通过单个操作表达多个阶段和多个条件，从而更新一个或多个字段。

    更新可包含以下阶段：

    • AggregationUpdate.set(…​).toValue(…​) → $set : { …​ }

    • AggregationUpdate.unset(…​) → $unset : [ …​ ]

    • AggregationUpdate.replaceWith(…​) → $replaceWith : { …​ }

        .defaultTo("F")
    );

                               { case: { $gte: [ "$average", 90 ] }, then: "A" },
                               { case: { $gte: [ "$average", 80 ] }, then: "B" },
                               { case: { $gte: [ "$average", 70 ] }, then: "C" },
                               { case: { $gte: [ "$average", 60 ] }, then: "D" }
                           ],
                           default: "F"
     } } } }
   ],
   { multi: true }                                                          (4)
)
    1 第一个 $set 阶段根据 tests 字段的平均值计算出一个新字段 average。
    2 第二个 $set 阶段根据第一个聚合阶段计算的 average 字段计算出一个新字段 grade。
    3 该管道在 students 集合上运行，并使用 Student 进行聚合字段映射。
    4 将更新应用于集合中所有匹配的文档。

    Upsert

    与执行 `updateFirst` 操作相关，您还可以执行 `upsert` 操作，该操作在找不到匹配查询的文档时将执行插入。 所插入的文档是查询文档和更新文档的组合。 以下示例展示了如何使用 `upsert` 方法：

    • Imperative

    • Reactive

    UpdateResult result = template.update(Person.class)
  .matching(query(where("ssn").is(1111).and("firstName").is("Joe").and("Fraizer").is("Update"))
  .apply(update("address", addr))
  .upsert();
    Mono<UpdateResult> result = template.update(Person.class)
  .matching(query(where("ssn").is(1111).and("firstName").is("Joe").and("Fraizer").is("Update"))
  .apply(update("address", addr))
  .upsert();
    upsert 不支持排序。 请使用 findAndModify 来应用 Sort。

    如果未在 `Update` 中包含 `@Version` 属性，则该属性将自动初始化。有关更多信息，请参阅乐观锁部分。

    集合中的文档替换

    通过 `MongoTemplate` 提供的各种 `replace` 方法可以覆盖第一个匹配的文档。如果未找到匹配项，可以通过提供带有相应配置的 `ReplaceOptions` 来执行更新操作（如上一节所述）。

    替换一个
    Person tom = template.insert(new Person("Motte", 21)); (1)
Query query = Query.query(Criteria.where("firstName").is(tom.getFirstName())); (2)
tom.setFirstname("Tom"); (3)
template.replace(query, tom, ReplaceOptions.none()); (4)
    1 插入新文档。
    2 用于标识要替换的单个文档的查询条件。
    3 设置替换文档，该文档必须具有与现有文档相同的 _id，或者完全不包含 _id。
    4 执行替换操作。 使用 upsert 进行替换一个文档 
    Person tom = new Person("id-123", "Tom", 21) (1)
Query query = Query.query(Criteria.where("firstName").is(tom.getFirstName()));
template.replace(query, tom, ReplaceOptions.replaceOptions().upsert()); (2)
    1 执行更新或插入（upsert）操作时，必须包含 _id 值；否则 MongoDB 可能会创建一个与您的领域类型不兼容的潜在新 ObjectId。由于 MongoDB 无法感知您的领域类型，任何 @Field(targetType) 提示都将被忽略，由此生成的 ObjectId 可能与您的领域模型不兼容。
    2 使用 upsert 在找不到匹配项时插入新文档。

    无法通过替换操作更改现有文档的 `_id`。 在 `upsert` 操作中，MongoDB 采用以下两种方式来确定新条目的 ID： * 在查询中使用 `_id`，例如 `{"_id" : 1234 }`； * 替换文档中包含 `_id`。 如果以上两种方式均未提供 `_id`，MongoDB 将为该文档生成一个新的 `ObjectId`。 这可能导致映射和数据查找出现问题，特别是当使用的领域类型中 `id` 属性的类型不同（例如为 `Long`）时。

    查找和修改

    MongoCollection 上的 findAndModify(…) 方法可以在单个操作中更新文档，并返回旧文档或新更新的文档。 MongoTemplate 提供了四个重载的 findAndModify 方法，它们接受 Query 和 Update 类，并将 Document 转换为您的 POJO：

    <T> T findAndModify(Query query, Update update, Class<T> entityClass);

<T> T findAndModify(Query query, Update update, Class<T> entityClass, String collectionName);

<T> T findAndModify(Query query, Update update, FindAndModifyOptions options, Class<T> entityClass);

<T> T findAndModify(Query query, Update update, FindAndModifyOptions options, Class<T> entityClass, String collectionName);

    以下示例向容器中插入几个 `Person` 对象，并执行一个 `findAndUpdate` 操作：

    template.insert(new Person("Tom", 21));
template.insert(new Person("Dick", 22));
template.insert(new Person("Harry", 23));

Query query = new Query(Criteria.where("firstName").is("Harry"));
Update update = new Update().inc("age", 1);

Person oldValue = template.update(Person.class)
  .matching(query)
  .apply(update)
  .findAndModifyValue(); // oldValue.age == 23

Person newValue = template.query(Person.class)
  .matching(query)
  .findOneValue(); // newValye.age == 24

Person newestValue = template.update(Person.class)
  .matching(query)
  .apply(update)
  .withOptions(FindAndModifyOptions.options().returnNew(true)) // Now return the newly updated document when updating
  .findAndModifyValue(); // newestValue.age == 25

    `FindAndModifyOptions` 方法允许您设置 `returnNew`、`upsert` 和 `remove` 的选项。 以下是一个基于上一段代码片段的示例：

    Person upserted = template.update(Person.class)
  .matching(new Query(Criteria.where("firstName").is("Mary")))
  .apply(update)
  .withOptions(FindAndModifyOptions.options().upsert(true).returnNew(true))
  .findAndModifyValue()

    如果未在 Update 中包含 @Version 属性，则该属性将自动递增。 有关更多信息，请参阅乐观锁部分。

    查找和替换

    替换整个 `Document` 的最直接方法是通过其 `id` 使用 `save` 方法。 然而，这种方法并不总是可行的。 `findAndReplace` 提供了一种替代方案，允许通过简单的查询来识别要替换的文档。

    示例 3：查找并替换文档
    Optional<User> result = template.update(Person.class)      (1)
    .matching(query(where("firstname").is("Tom")))          (2)
    .replaceWith(new Person("Dick"))
    .withOptions(FindAndReplaceOptions.options().upsert()) (3)
    .as(User.class)                                        (4)
    .findAndReplace();                                     (5)
    1 使用流式更新 API 配合给定的域类型来映射查询并推导集合名称，或直接使用 MongoOperations#findAndReplace。
    2 针对给定域类型进行实际匹配查询。 通过查询提供 sort、fields 和 collation 设置。
    3 额外的可选钩子，用于提供除默认值之外的选项，例如 upsert。
    4 一个用于映射操作结果的可选投影类型。 如果未提供，则使用初始域类型。
    5 触发实际处理。 使用 findAndReplaceValue 获取可空结果，而不是 Optional。
    请注意，替换项本身不应包含 id，因为现有 Document 的 id 将由存储系统自动传递到替换项中。 此外，请牢记 findAndReplace 仅会根据可能提供的排序顺序，替换匹配查询条件的第一份文档。

    Delete

    您可以使用五种重载方法之一从数据库中删除对象：

    template.remove(tywin, "GOT");                                              (1)

template.remove(query(where("lastname").is("lannister")), "GOT");           (2)

template.remove(new Query().limit(3), "GOT");                               (3)

template.findAllAndRemove(query(where("lastname").is("lannister"), "GOT");  (4)

template.findAllAndRemove(new Query().limit(3), "GOT");                     (5)
    1 根据指定的 _id 从关联集合中删除单个实体。
    2 从 GOT 集合中删除所有匹配查询条件的文档。
    3 删除 GOT 集合中的前三个文档。与 <2> 不同，要删除的文档是通过其 _id 来标识的：首先运行给定查询并应用 sort、limit 和 skip 选项，然后在单独的步骤中一次性删除所有匹配的文档。
    4 从 GOT 集合中删除所有匹配查询条件的文档。与 <3> 不同，文档不是批量删除，而是逐个删除。
    5 删除 GOT 集合中的前三个文档。与 <3> 不同，文档不是批量删除，而是逐个删除。

    乐观锁

    `@Version` 注解在 MongoDB 上下文中提供了与 JPA 相似的语法，并确保更新仅应用于具有匹配版本的文档。因此，版本属性的实际值会被添加到更新查询中，使得如果在期间有其他操作修改了该文档，则此更新将不会产生任何效果。在这种情况下，会抛出 `OptimisticLockingFailureException` 异常。以下示例展示了这些功能：

    @Document
class Person {

  @Id String id;
  String firstname;
  String lastname;
  @Version Long version;
}

Person daenerys = template.insert(new Person("Daenerys"));                            (1)

Person tmp = template.findOne(query(where("id").is(daenerys.getId())), Person.class); (2)

daenerys.setLastname("Targaryen");
template.save(daenerys);                                                              (3)

template.save(tmp); // throws OptimisticLockingFailureException                       (4)
    1 最初插入文档。version 被设置为 0。
    2 加载刚刚插入的文档。version 仍然是 0。
    3 使用 version = 0 更新文档。 设置 lastname 并将 version 递增为 1。
    4 尝试更新之前加载的文档，该文档仍具有 version = 0。 由于当前的 version 为 1，操作失败并抛出 OptimisticLockingFailureException。

    只有对 `MongoTemplate`> 的某些 CRUD 操作才会考虑并修改版本属性。 请查阅 `MongoOperations`> 的 JavaDoc 以获取详细信息。

    乐观锁需要服务器端的写确认（即写结果响应）。使用 WriteConcern.UNACKNOWLEDGED 可能导致 OptimisticLockingFailureException 异常被静默吞没。
    自 2.2 版本起，MongoOperations 在从数据库中删除实体时也会包含 @Version 属性。 若要移除无需版本检查的 Document，请使用 MongoOperations#remove(Query,…​) 替代 MongoOperations#remove(Object)。
    自版本 2.2 起，仓库在删除带版本控制的实体时会检查已确认删除的结果。 如果无法通过 CrudRepository.delete(Object) 删除带版本控制的实体，则会抛出 OptimisticLockingFailureException。 在这种情况下，该实体的版本可能已被更改，或者该对象在此期间已被删除。 请使用 CrudRepository.deleteById(ID) 绕过乐观锁机制，无论对象的版本如何均执行删除操作。
