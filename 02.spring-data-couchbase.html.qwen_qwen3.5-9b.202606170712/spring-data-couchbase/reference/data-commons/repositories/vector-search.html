    向量搜索

    随着生成式人工智能的兴起，向量数据库在数据库领域获得了强劲的发展势头。这些数据库能够高效地存储和查询高维向量，使其非常适合语义搜索、推荐系统和自然语言理解等任务。

    向量搜索是一种通过比较向量表示（也称为嵌入）来检索语义相似数据的技术，而非依赖传统的精确匹配查询。这种方法能够支持超越基于关键词检索的智能、上下文感知型应用。

    在 Spring Data 的语境下，向量搜索为构建智能、上下文感知的应用程序开辟了新的可能性，特别是在自然语言处理、推荐系统和生成式 AI 等领域。 通过利用熟悉的存储库抽象来建模基于向量的查询，Spring Data 使开发人员能够无缝地将基于相似性的向量数据库集成到 Spring Data 编程模型中，同时保持其简洁性和一致性。

    向量模型

    为了以类型安全且符合惯用方式的方式支持向量搜索，Spring Data 引入了以下核心抽象：

    • Vector

    • SearchResults<T> and SearchResult<T>

    • Score、Similarity 和评分函数

    Vector

    `Vector` 类型表示一个 n 维数值嵌入，通常由嵌入模型生成。 在 Spring Data 中，它被定义为浮点数数组的轻量级包装器，以确保不可变性和一致性。 该类型可作为搜索查询的输入，或作为领域实体上的属性来存储相关的向量表示。

    Vector vector = Vector.of(0.23f, 0.11f, 0.77f);

    在领域模型中使用 Vector 消除了对原始数字数组或列表的操作需求，提供了一种更安全且更具表现力的向量数据处理方式。 这种抽象还便于与各种向量数据库和库进行集成。 它同样支持实现特定供应商的优化方案，例如二进制向量或量化向量，这些格式并不对应于标准的浮点数（float 和 double，依据 IEEE 754 标准）表示法。 领域对象可以拥有一个向量属性，该属性可用于相似性搜索。 考虑以下示例：

    搜索结果

    SearchResult<T> 类型封装了向量相似度查询的结果。它既包含匹配到的域对象，也包含一个相关性分数，用于指示该对象与查询向量的匹配程度。这种抽象提供了一种结构化的方式来处理结果排序，使开发人员能够轻松地对数据及其上下文相关性进行操作。

    在本示例中，searchByCountryAndEmbeddingNear 方法返回一个 SearchResults<Comment> 对象，其中包含 SearchResult<Comment> 实例的列表。每个结果都包括匹配的 Comment 实体及其相关性得分。

    相关性分数是一个数值，表示匹配向量与查询向量的对齐程度。 根据分数是代表距离还是相似度，较高的分数可能意味着更近的匹配或更远的匹配。

    用于计算该分数的评分函数可能因底层数据库、索引或输入参数的不同而有所变化。

    评分、相似度与评分函数

    `Score` 类型表示一个数值，用于指示搜索结果的相关性。 它可用于根据结果与查询向量的相似度对结果进行排序。 `Score` 类型通常为浮点数，其具体含义（值越大越好还是越小越好）取决于所使用的特定相似度函数。 分数是向量搜索的副产品，并非成功执行搜索操作所必需的内容。 分数值不属于领域模型的一部分，因此最好将其表示为带外数据。

    通常，分数由 `ScoringFunction` 计算得出。用于计算该分数的实际评分函数可能取决于底层数据库，并可从搜索索引或输入参数中获取。

    向量搜索方法

    向量搜索方法在存储库中定义，遵循与标准 Spring Data 查询方法相同的约定。这些方法返回 SearchResults<T>，并需要一个 Vector 参数来定义查询向量。具体实现取决于底层数据存储的内部机制及其对向量搜索的支持能力。

    如果您是 Spring Data 仓库的新手，请确保熟悉仓库定义和查询方法的基础知识。

    通常，您有两种方法可以选择来声明搜索方法：

    • 查询推导

    • 声明基于字符串的查询

    向量搜索方法必须声明一个 `Vector` 参数以定义查询向量。

    派生搜索方法

    派生搜索方法使用方法的名称来生成查询。 向量搜索支持以下关键字，在声明搜索方法时执行向量搜索：

    表 1。查询谓词关键字
    逻辑关键字 关键字表达式

    NEAR

    Near, IsNear

    WITHIN

    Within, IsWithin

    派生搜索方法通常更易读且易于维护，因为它们依赖方法名称来表达查询意图。 然而，派生搜索方法需要声明 `Score`、`Range<Score>` 或 `ScoreFunction` 作为 `Near`/`Within` 关键字的第二个参数，以便根据分数限制搜索结果。

    注释搜索方法

    注解方法提供了对查询语义和参数的完全控制。与派生方法不同，它们不依赖于方法命名约定。

    Spring Data 对实际查询拥有更多控制权，因此可以对查询及其参数做出更少的假设。例如，Similarity归一化会在查询内部使用原生评分函数，将给定的相似度值转换为评分谓词值，反之亦然。如果注解式查询未定义评分（如 score），则返回的 SearchResult<T> 中的评分值将为零。

    Sorting

    默认情况下，搜索结果按照其分数进行排序。 您可以通过使用 `Sort` 参数来覆盖排序方式：

    示例 1：在仓储搜索方法中使用Sort
    interface CommentRepository extends Repository<Comment, String> {

  SearchResults<Comment> searchByEmbeddingNearOrderByCountry(Vector vector, Score score);

  SearchResults<Comment> searchByEmbeddingWithin(Vector vector, Score score, Sort sort);
}

    请注意，自定义排序不允许将分数作为排序条件。您只能引用域属性。
