    Elasticsearch 对象映射

    Spring Data Elasticsearch 对象映射是将 Java 对象（即领域实体）映射为存储在 Elasticsearch 中的 JSON 表示形式，以及从该形式反向映射的过程。内部用于此映射的类是 MappingElasticsearchConverter。

    元模型对象映射

    基于元模型的方法利用领域类型信息来从 Elasticsearch 读取和写入数据。这使得可以为特定的领域类型映射注册Converter实例。

    映射注解概述

    MappingElasticsearchConverter 利用元数据来驱动对象到文档的映射。这些元数据来自实体的属性，这些属性可以添加注解。

    以下是可用的注释：

    • @Document：在类级别应用，用于指示该类是数据库映射的候选者。 最重要的属性如下（完整属性列表请查阅 API 文档）：

      • indexName：用于存储此实体的索引名称。 它可以包含一个 SpEL 模板表达式，例如 "log-#{T(java.time.LocalDate).now().toString()}"。

      • createIndex：标志是否在存储库引导时创建索引。默认值为 true。 参见使用相应映射自动创建索引

    • @Id：应用于字段级别，用于标记用于标识目的的字段。

    • @Transient、@ReadOnlyProperty 和 @WriteOnlyProperty：有关详细信息，请参阅以下章节控制写入和读取 Elasticsearch 的属性。

    • @PersistenceConstructor：标记一个给定的构造函数（即使是包级私有的），用于从数据库实例化对象。构造函数的参数通过名称映射到检索到的文档中的键值。

    • @Field：应用于字段级别，用于定义字段的属性。大多数属性对应于相应的 Elasticsearch 映射 定义（以下列表不完整，请查看注解的 Javadoc 以获取完整参考）：

      • name：该字段在 Elasticsearch 文档中的表示名称；若未设置，则使用 Java 字段名。

      • type：字段类型，可以是 Text、Keyword、Long、Integer、Short、Byte、Double、Float、Half_Float、Scaled_Float、Date、Date_Nanos、Boolean、Binary、Integer_Range、Float_Range、Long_Range、Double_Range、Date_Range、Ip_Range、Object、Nested、Ip、TokenCount、Percolator、Flattened、Search_As_You_Type 之一。 请参阅 Elasticsearch 映射类型。 如果未指定字段类型，则默认为 FieldType.Auto。 这意味着不会为该属性写入任何映射条目，并且当首次存储该属性的数据时，Elasticsearch 会动态添加一个映射条目（请查阅 Elasticsearch 文档以了解动态映射规则）。

      • format：一个或多个内置日期格式，详见下一节日期格式映射。

      • pattern：一个或多个自定义日期格式，请参见下一节日期格式映射。

      • store：标志是否应将原始字段值存储到 Elasticsearch 中，默认值为 false。

      • 指定自定义分析器和标准化器的 `analyzer`、`searchAnalyzer` 和 `normalizer`。

    • @GeoPoint：将字段标记为 geo_point 数据类型。如果该字段是 GeoPoint 类的实例，则可以省略此注解。

    • @ValueConverter 定义了一个类，用于转换给定的属性。与注册的 Spring Converter 不同，它仅转换带有注解的属性，而不是给定类型的每个属性。

    映射元数据基础设施定义在一个独立的、与具体技术无关的 spring-data-commons 项目中。

    控制写入和读取到 Elasticsearch 的属性

    本节详细说明用于定义属性值是写入还是从 Elasticsearch 读取的注解。

    @Transient：带有此注解的属性不会被写入映射，其值不会发送到 Elasticsearch，并且当从 Elasticsearch 返回文档时，该属性不会在生成的实体中设置。

    @ReadOnlyProperty：带有此注解的属性不会将其值写入 Elasticsearch，但在返回数据时，该属性将从 Elasticsearch 文档中返回的值进行填充。 一个使用场景是索引映射中定义的运行时字段。

    @WriteOnlyProperty：带有此注解的属性，其值将被存储到 Elasticsearch 中，但在读取文档时不会被设置任何值。例如，这可用于那些需要进入 Elasticsearch 索引但不在其他地方使用的合成字段。

    日期格式映射

    源自 TemporalAccessor 的属性或类型为 java.util.Date 的属性，必须带有类型为 FieldType.Date 的 @Field 注解，或者为此类型注册自定义转换器。 本段描述了 FieldType.Date 的用法。

    `@Field` 注解有两个属性用于定义写入映射的日期格式信息（另请参阅Elasticsearch 内置格式和Elasticsearch 自定义日期格式）。

    `format` 属性用于定义至少一个预定义格式。如果未定义该属性，则默认使用 `_date_optional_time` 和 `epoch_millis`。

    `pattern` 属性可用于添加额外的自定义格式字符串。 如果您只想使用自定义日期格式，必须将 `format` 属性设置为空 `{}`。

    下表展示了不同属性及其值之间的映射关系：

    注解 Elasticsearch 映射中的格式字符串

    @Field(type=FieldType.Date)

    "date_optional_time||epoch_millis",

    @Field(type=FieldType.Date, format=DateFormat.basic_date)

    "basic_date"

    @Field(type=FieldType.Date, format={DateFormat.basic_date, DateFormat.basic_time})

    "basic_date||basic_time"

    @Field(type=FieldType.Date, pattern="dd.MM.uuuu")

    "date_optional_time||epoch_millis||dd.MM.uuuu",

    @Field(type=FieldType.Date, format={}, pattern="dd.MM.uuuu")

    "dd.MM.uuuu"
    如果您使用自定义日期格式，需要将年份的格式从 yyyy 改为 uuuu。 这是由于 Elasticsearch 7 中的日期格式变更所致。

    检查org.springframework.data.elasticsearch.annotations.DateFormat枚举的代码，以获取预定义值及其模式的完整列表。

    范围类型

    当字段被标注为 Integer_Range、Float_Range、Long_Range、Double_Range、Date_Range 或 Ip_Range 中的一种类型时，该字段必须是将被映射到 Elasticsearch 范围（range）的类的实例，例如：

    class SomePersonData {

    @Field(type = FieldType.Integer_Range)
    private ValidAge validAge;

    // getter and setter
}

class ValidAge {
    @Field(name="gte")
    private Integer from;

    @Field(name="lte")
    private Integer to;

    // getter and setter
}

    作为替代方案，Spring Data Elasticsearch 提供了一个 `Range<T>` 类，使得上述示例可以改写为：

    class SomePersonData {

    @Field(type = FieldType.Integer_Range)
    private Range<Integer> validAge;

    // getter and setter
}

    支持类型 `` 的类包括 `Integer`、`Long`、`Float`、`Double`、`Date` 以及实现 `TemporalAccessor` 接口的类。

    映射字段名称

    默认情况下，Spring Data Elasticsearch 会将对象的属性名用作 Elasticsearch 中的字段名。可以通过在该属性上使用 `@Field` 注解来为单个字段更改此行为。

    也可以在客户端配置中定义一个FieldNamingStrategy(Elasticsearch 客户端)。例如，如果配置了SnakeCaseFieldNamingStrategy，则对象的属性sampleProperty将被映射到 Elasticsearch 中的sample_property。FieldNamingStrategy适用于所有实体；可以通过在属性上使用@Field设置特定名称来覆盖它。

    非字段支持的属性

    通常情况下，实体中使用的属性是实体类的字段。 在某些情况下，实体的属性值是在实体中计算得出的，并且需要存储到 Elasticsearch 中。在这种情况下，除了使用 @Field 注解标注 getter 方法（getProperty()）之外，还必须将该方法用 @AccessType(AccessType.Type.PROPERTY) 进行标注。在此类情况下，还需要添加第三个注解 @WriteOnlyProperty，因为该值仅被写入 Elasticsearch。 完整示例如下：

    @Field(type = Keyword)
@WriteOnlyProperty
@AccessType(AccessType.Type.PROPERTY)
public String getProperty() {
	return "some value that is calculated here";
}

    其他属性注解

    @IndexedIndexName

    此注解可设置于实体的 String 属性上。 该属性不会写入映射，也不会存储在 Elasticsearch 中，其值也不会从 Elasticsearch 文档中读取。 在实体被持久化之后（例如通过调用 `ElasticsearchOperations.save(T entity)`），从此调用返回的实体将在该属性中包含实体被保存到的索引名称。 这在索引名称由 Bean 动态设置或写入写别名时非常有用。

    为属性设置值并不会指定存储该实体的索引！

    映射规则

    类型提示

    映射使用嵌入在发送至服务器的文档中的类型提示来实现泛型类型映射。这些类型提示表示为文档内的_class属性，并为每个聚合根编写。

    示例 1：类型提示
    public class Person {              (1)
  @Id String id;
  String firstname;
  String lastname;
}
    {
  "_class" : "com.example.Person", (1)
  "id" : "cb7bef",
  "firstname" : "Sarah",
  "lastname" : "Connor"
}
    1 默认情况下，使用域类型的类名作为类型提示。

    类型提示可以配置为包含自定义信息。请使用 @TypeAlias 注解来实现此功能。

    确保在初始实体集（AbstractElasticsearchConfiguration#getInitialEntitySet）中添加带有 @TypeAlias 的类型，以便在首次从存储读取数据时即可拥有实体信息。
    示例 2：使用别名的类型提示
    @TypeAlias("human")                (1)
public class Person {

  @Id String id;
  // ...
}
    {
  "_class" : "human",              (1)
  "id" : ...
}
    1 写入实体时将使用配置的别名。
    除非属性类型为 Object、接口，或实际值类型与属性声明不匹配，否则不会为嵌套对象编写类型提示。
    禁用类型提示

    当应使用的索引已存在，但其映射中未定义类型提示且映射模式设置为严格时，可能需要禁用类型提示的写入。在这种情况下，尝试写入类型提示将导致错误，因为该字段无法自动添加。

    可以通过在继承自AbstractElasticsearchConfiguration的配置类中重写writeTypeHints()方法来禁用整个应用程序的类型提示（参见Elasticsearch 客户端）。

    作为替代方案，它们可以通过在单个索引上使用 `@Document` 注解来禁用：

    @Document(indexName = "index", writeTypeHint = WriteTypeHint.FALSE)
    我们强烈建议不要禁用类型提示。 除非迫不得已，否则请勿执行此操作。 禁用类型提示可能导致在存在多态数据的情况下无法从 Elasticsearch 正确检索文档，或者文档检索完全失败。

    地理空间类型

    地理空间类型（如Point和GeoPoint）会被转换为纬度/经度对。

    示例 3。地理空间类型
    public class Address {
  String city, street;
  Point location;
}
    {
  "city" : "Los Angeles",
  "street" : "2800 East Observatory Road",
  "location" : { "lat" : 34.118347, "lon" : -118.3026284 }
}

    GeoJSON 类型

    Spring Data Elasticsearch 通过提供 GeoJson 接口以及针对不同几何类型的实现来支持 GeoJson 类型。 它们根据 GeoJson 规范映射到 Elasticsearch 文档中。 当写入索引映射时，实体对应的属性在索引映射中被指定为 geo_shape。（请同时参考Elasticsearch 文档）

    示例 4。GeoJSON 类型
    public class Address {

  String city, street;
  GeoJsonPoint location;
}
    {
  "city": "Los Angeles",
  "street": "2800 East Observatory Road",
  "location": {
    "type": "Point",
    "coordinates": [-118.3026284, 34.118347]
  }
}

    已实现以下 GeoJSON 类型：

    • GeoJsonPoint

    • GeoJsonMultiPoint

    • GeoJsonLineString

    • GeoJsonMultiLineString

    • GeoJsonPolygon

    • GeoJsonMultiPolygon

    • GeoJsonGeometryCollection

    Collections

    对于集合中的值，在应用类型提示和自定义转换时，遵循与聚合根相同的映射规则。

    示例 5。集合
    public class Person {

  // ...

  List<Person> friends;

}
    {
  // ...

  "friends" : [ { "firstname" : "Kyle", "lastname" : "Reese" } ]
}

    Maps

    对于 Map 内部的值，其类型提示和自定义转换的映射规则与聚合根相同。然而，Map 的键必须是字符串，才能被 Elasticsearch 处理。

    示例 6。集合
    public class Person {

  // ...

  Map<String, Address> knownLocations;

}
    {
  // ...

  "knownLocations" : {
    "arrivedAt" : {
       "city" : "Los Angeles",
       "street" : "2800 East Observatory Road",
       "location" : { "lat" : 34.118347, "lon" : -118.3026284 }
     }
  }
}

    自定义转换

    查看上一节中的Configuration，ElasticsearchCustomConversions允许为映射域和简单类型注册特定规则。

    示例 7：元模型对象映射配置
    @Configuration
public class Config extends ElasticsearchConfiguration  {

	@Override
	public ClientConfiguration clientConfiguration() {
		return ClientConfiguration.builder() //
				.connectedTo("localhost:9200") //
				.build();
	}

  @Bean
  @Override
  public ElasticsearchCustomConversions elasticsearchCustomConversions() {
    return new ElasticsearchCustomConversions(
      Arrays.asList(new AddressToMap(), new MapToAddress()));       (1)
  }

  @WritingConverter                                                 (2)
  static class AddressToMap implements Converter<Address, Map<String, Object>> {

    @Override
    public Map<String, Object> convert(Address source) {

      LinkedHashMap<String, Object> target = new LinkedHashMap<>();
      target.put("ciudad", source.getCity());
      // ...

      return target;
    }
  }

  @ReadingConverter                                                 (3)
  static class MapToAddress implements Converter<Map<String, Object>, Address> {

    @Override
    public Address convert(Map<String, Object> source) {

      // ...
      return address;
    }
  }
}
    {
  "ciudad" : "Los Angeles",
  "calle" : "2800 East Observatory Road",
  "localidad" : { "lat" : 34.118347, "lon" : -118.3026284 }
}
    1 添加Converter实现。
    2 配置用于将DomainType写入Elasticsearch的Converter。
    3 配置用于从搜索结果中读取DomainType的Converter。
