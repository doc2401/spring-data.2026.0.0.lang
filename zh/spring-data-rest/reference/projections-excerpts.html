    预测与摘录

    Spring Data REST 会导出您定义域模型的默认视图。然而，出于各种考虑，您可能需要修改该模型的视图。本节将介绍如何定义投影和摘录，以提供资源的简化及精简视图。

    Projections

    考虑以下领域模型：

    @Entity
public class Person {

  @Id @GeneratedValue
  private Long id;
  private String firstName, lastName;

  @OneToOne
  private Address address;
  …
}

    前例中的 `Person` 对象具有多个属性：

    • `id` 是主键。

    • `firstName` 和 `lastName` 是数据属性。

    • `address` 是另一个域对象的链接。

    现在假设我们创建一个相应的仓库，如下所示：

    interface PersonRepository extends CrudRepository<Person, Long> {}

    默认情况下，Spring Data REST 会导出此领域对象及其所有属性。firstName和lastName作为普通数据对象被导出。关于address属性有两种选择。其中一种选项是为Address对象定义一个存储库，如下所示：

    interface AddressRepository extends CrudRepository<Address, Long> {}

    在这种情况下，`Person` 资源会将 `address` 属性渲染为指向其对应 `Address` 资源的 URI。如果我们在系统中查找“弗罗多”，我们可能会看到如下所示的 HAL 文档：

    {
  "firstName" : "Frodo",
  "lastName" : "Baggins",
  "_links" : {
    "self" : {
      "href" : "http://localhost:8080/persons/1"
    },
    "address" : {
      "href" : "http://localhost:8080/persons/1/address"
    }
  }
}

    还有另一种方法。如果Address领域对象没有自己的仓储定义，Spring Data REST 会将数据字段包含在Person资源中，如下例所示：

    {
  "firstName" : "Frodo",
  "lastName" : "Baggins",
  "address" : {
    "street": "Bag End",
    "state": "The Shire",
    "country": "Middle Earth"
  },
  "_links" : {
    "self" : {
      "href" : "http://localhost:8080/persons/1"
    }
  }
}

    那如果您根本不需要 `

    ` 详细信息呢？同样地，默认情况下，Spring Data REST 会导出其所有属性（`` 除外）。您可以通过定义一个或多个投影来为您的 REST 服务消费者提供替代方案。以下示例展示了一个不包含地址的投影：

    @Projection(name = "noAddresses", types = { Person.class }) (1)
interface NoAddresses { (2)

  String getFirstName(); (3)

  String getLastName(); (4)
}
    1 @Projection 注解将此标记为投影。name 属性提供了该投影的名称，我们稍后将更详细地介绍它。types 属性将该投影的目标限定为仅适用于 Person 对象。
    2 它是一个 Java 接口，使其具有声明式特性。
    3 它导出了 firstName。
    4 它导出了 lastName。

    `NoAddresses` 投影仅包含 `firstName` 和 `lastName` 的 getter，这意味着它不提供任何地址信息。假设您为 `Address` 资源拥有单独的存储库，Spring Data REST 的默认视图与之前的表示形式略有不同，如下例所示：

    {
  "firstName" : "Frodo",
  "lastName" : "Baggins",
  "_links" : {
    "self" : {
      "href" : "http://localhost:8080/persons/1{?projection}", (1)
      "templated" : true (2)
    },
    "address" : {
      "href" : "http://localhost:8080/persons/1/address"
    }
  }
}
    1 此资源新增了一个选项：{?projection}。
    2 self URI 是一个 URI 模板。

    要查看对资源的投影，请查找 localhost:8080/persons/1?projection=noAddresses。

    传递给 projection 查询参数的值与在 @Projection(name = "noAddress") 中指定的值相同，它与投影接口的名称无关。

    您可以拥有多个投影。

    请参见投影 (Projections)以查看示例项目。我们鼓励您对其进行实验。

    Spring Data REST 查找投影定义的方式如下：

    • 与您的实体定义位于同一包（或其子包）中的任何 `@Projection` 接口都会被注册。

    • 您可以使用 `RepositoryRestConfiguration.getProjectionConfiguration().addProjection(…)` 手动注册投影。

    无论哪种情况，投影接口都必须带有 `@Projection` 注解。

    查找现有预测

    Spring Data REST 会暴露应用级语义配置文件（ALPS）文档，这是一种微元数据格式。要查看 ALPS 元数据，请遵循根资源所暴露的profile链接。如果您导航至Person资源的 ALPS 文档（即/alps/persons），可以找到关于Person资源的许多详细信息。其中列出了投影（Projections）以及关于GETREST 转换的详情，并以如下示例中的块形式呈现：

    { …
  "id" : "get-person", (1)
  "name" : "person",
  "type" : "SAFE",
  "rt" : "#person-representation",
  "descriptors" : [ {
    "name" : "projection", (2)
    "doc" : {
      "value" : "The projection that shall be applied when rendering the response. Acceptable values available in nested descriptors.",
      "format" : "TEXT"
    },
    "type" : "SEMANTIC",
    "descriptors" : [ {
      "name" : "noAddresses", (3)
      "type" : "SEMANTIC",
      "descriptors" : [ {
        "name" : "firstName", (4)
        "type" : "SEMANTIC"
      }, {
        "name" : "lastName", (4)
        "type" : "SEMANTIC"
      } ]
    } ]
  } ]
},
…
    1 ALPS 文档的这一部分展示了关于 GET 和 Person 资源的详细信息。
    2 这一部分包含了 projection 选项。
    3 这一部分包含了 noAddresses 投影。
    4 该投影实际提供的属性包括 firstName 和 lastName。

    如果投影定义满足以下条件，则会被拾取并供客户端使用：

    • 使用@Projection注解标记，并且位于域类型的同一包（或子包）中，或者

    • 通过手动注册 `RepositoryRestConfiguration.getProjectionConfiguration().addProjection(…)` 实现。

    引入隐藏数据

    到目前为止，本节已介绍了如何使用投影来减少呈现给用户的量信息。投影还可以引入通常不可见的数据。例如，Spring Data REST 会忽略标记有@JsonIgnore注解的字段或 getter 方法。考虑以下领域对象：

    @Entity
public class User {

	@Id @GeneratedValue
	private Long id;
	private String name;

	@JsonIgnore private String password; (1)

	private String[] roles;
  …
    1 Jackson 的 @JsonIgnore 注解用于防止将 password 字段序列化为 JSON。

    前例中的 `` 类可用于存储用户信息并与 Spring Security 集成。如果您创建了一个 ``，`password` 字段通常会被导出，这并不理想。在前例中，我们通过在该 `password` 字段上应用 Jackson 的 `<@JsonIgnore>` 来防止这种情况发生。

    如果字段对应的 getter 方法上标注了 @JsonIgnore，Jackson 也不会将该字段序列化为 JSON。

    然而，投影功能使得我们仍然能够服务于该领域。可以创建如下投影：

    @Projection(name = "passwords", types = { User.class })
interface PasswordProjection {

  String getPassword();
}

    如果创建了此类投影并加以使用，它将绕过针对`User.password` 设置的`@JsonIgnore` 指令。

    此示例可能略显牵强，但在拥有更丰富的领域模型和众多投影的情况下，确实可能意外泄露此类细节。由于 Spring Data REST 无法辨别此类数据的敏感性，因此避免此类情况的责任在于您自己。

    预测还可以生成虚拟数据。想象一下，您拥有如下实体定义：

    @Entity
public class Person {

  ...
  private String firstName;
  private String lastName;

  ...
}

    您可以创建一种投影，将前面示例中的两个数据字段组合在一起，方法如下：

    @Projection(name = "virtual", types = { Person.class })
public interface VirtualProjection {

  @Value("#{target.firstName} #{target.lastName}") (1)
  String getFullName();

}
    1 Spring 的@Value注解允许您插入一个 SpEL 表达式，该表达式接收目标对象并将其firstName和lastName属性拼接起来，以渲染只读的fullName。

    Excerpts

    摘录是一种自动应用于资源集合的投影。例如，您可以按以下方式修改PersonRepository：

    @RepositoryRestResource(excerptProjection = NoAddresses.class)
interface PersonRepository extends CrudRepository<Person, Long> {}

    前面的示例指示 Spring Data REST 在将 Person 资源嵌入集合或相关资源时使用 NoAddresses 投影。

    摘录投影不会自动应用于单个资源，必须手动应用。摘录投影旨在为集合数据提供默认预览，而非在获取单个资源时使用。有关此主题的讨论，请参阅 为什么 Spring Data REST 项目资源不会自动应用摘录投影？。

    除了更改默认渲染方式外，摘录还具有其他渲染选项，如下一节所示。

    截取常用数据

    在使用 REST 服务组合领域对象时，常会遇到一种情况。例如，Person 存储在一个表中，而其相关的 Address 存储在另一个表中。默认情况下，Spring Data REST 会将人员的 address 作为客户端必须导航的 URI 提供。但如果消费者经常需要获取这部分额外数据，则可以使用摘录投影（excerpt projection）将该数据内联展示，从而避免一次额外的 GET 请求。为此，您可以定义另一个摘录投影，如下所示：

    @Projection(name = "inlineAddress", types = { Person.class }) (1)
interface InlineAddress {

  String getFirstName();

  String getLastName();

  Address getAddress(); (2)
}
    1 此投影被命名为 inlineAddress。
    2 此投影添加了 getAddress，它返回 Address 字段。当在投影内部使用时，会导致该信息以行内方式包含。

    您可以将其注入到 `PersonRepository` 定义中，如下所示：

    @RepositoryRestResource(excerptProjection = InlineAddress.class)
interface PersonRepository extends CrudRepository<Person, Long> {}

    这样做会导致 HAL 文档显示如下：

    {
  "firstName" : "Frodo",
  "lastName" : "Baggins",
  "address" : { (1)
    "street": "Bag End",
    "state": "The Shire",
    "country": "Middle Earth"
  },
  "_links" : {
    "self" : {
      "href" : "http://localhost:8080/persons/1"
    },
    "address" : { (2)
      "href" : "http://localhost:8080/persons/1/address"
    }
  }
}
    1 address 数据直接内联包含，因此无需导航即可获取。
    2 到 Address 资源的链接仍然提供，因此仍可导航至其自身资源。

    请注意，前面的示例是本章前面所示示例的混合。您可能需要回顾它们，以了解如何逐步过渡到最终示例。

    为存储库配置 @RepositoryRestResource(excerptProjection=…​) 会改变默认行为。如果您已经发布了版本，这可能会导致服务消费者的破坏性变更。
