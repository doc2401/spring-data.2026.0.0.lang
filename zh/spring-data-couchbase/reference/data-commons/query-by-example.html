    示例查询

    Introduction

    本章介绍示例查询（Query by Example）并解释如何使用它。

    示例查询（QBE）是一种用户友好的查询技术，具有简洁的界面。它支持动态创建查询，无需编写包含字段名的查询语句。事实上，示例查询根本不需要使用特定于存储的查询语言来编写查询。

    本章介绍查询示例（Query by Example）的核心概念。 相关信息源自 Spring Data Commons 模块。 根据您的数据库不同，字符串匹配支持可能受到限制。

    Usage

    Query by Example API 由四个部分组成：

    • 探针：一个具有已填充字段的领域对象的实际示例。

    • ExampleMatcher：该 ExampleMatcher 包含匹配特定字段的详细信息。它可以在多个示例中重复使用。

    • 示例：一个示例由探针和示例匹配器组成。它用于创建查询。

    • FetchableFluentQuery：一个 FetchableFluentQuery 提供流式 API，允许对源自 Example 的查询进行进一步定制。使用流式 API 可指定查询的排序、投影和结果处理方式。

    示例查询适用于多种使用场景：

    • 使用一组静态或动态约束查询您的数据存储。

    • 无需担心破坏现有查询，即可频繁重构领域对象。

    • 独立于底层数据存储 API 工作。

    基于示例的方法也存在一些局限性：

    • 不支持嵌套或分组属性约束，例如firstname = ?0 or (firstname = ?1 and lastname = ?2)。

    • 针对字符串匹配的存储特定支持。 根据您的数据库，字符串匹配可支持字符串的起始/包含/结尾/正则表达式匹配。

    • 其他属性类型的精确匹配。

    在开始使用示例查询之前，您需要拥有一个领域对象。 要开始操作，请按照以下示例为您的仓库创建一个接口：

    示例人员对象
    public class Person {

  @Id
  private String id;
  private String firstname;
  private String lastname;
  private Address address;

  // … getters and setters omitted
}

    前面的示例展示了一个简单的领域对象。 您可以使用它来创建一个 `Example`。 默认情况下，值为 `null` 的字段会被忽略，而字符串则使用存储特定的默认值进行匹配。

    将属性纳入 Query by Example 标准是基于属性的可空性。使用基本类型（int、double 等）的属性始终会被包含，除非 ExampleMatcher 忽略该属性路径。

    示例可以通过使用 `of` 工厂方法或使用ExampleMatcher来构建。Example是不可变的。 以下示例展示了一个简单的 Example：

    示例 1。简单示例
    Person person = new Person();                         (1)
person.setFirstname("Dave");                          (2)

Example<Person> example = Example.of(person);         (3)
    1 创建域对象的新实例。
    2 设置要查询的属性。
    3 创建 Example 对象。

    您可以使用仓库运行示例查询。为此，让您的仓库接口扩展QueryByExampleExecutor<T>。以下列表展示了QueryByExampleExecutor接口的摘录：

    The QueryByExampleExecutor
    public interface QueryByExampleExecutor<T> {

  <S extends T> S findOne(Example<S> example);

  <S extends T> Iterable<S> findAll(Example<S> example);

  // … more functionality omitted.
}

    示例匹配器

    示例不限于默认设置。您可以使用ExampleMatcher为字符串匹配、空值处理以及特定属性设置指定自己的默认值，如下例所示：

    示例 2：具有自定义匹配的示例匹配器
    Person person = new Person();                          (1)
person.setFirstname("Dave");                           (2)

ExampleMatcher matcher = ExampleMatcher.matching()     (3)
  .withIgnorePaths("lastname")                         (4)
  .withIncludeNullValues()                             (5)
  .withStringMatcher(StringMatcher.ENDING);            (6)

Example<Person> example = Example.of(person, matcher); (7)
    1 创建域对象的新实例。
    2 设置属性。
    3 创建一个 ExampleMatcher，期望所有值都匹配。即使没有进一步配置，此时也可使用它。
    4 构造一个新的 ExampleMatcher 以忽略 lastname 属性路径。
    5 构造一个新的 ExampleMatcher 以忽略 lastname 属性路径并包含空值。
    6 构造一个新的 ExampleMatcher 以忽略 lastname 属性路径、包含空值并执行后缀字符串匹配。
    7 基于域对象和已配置的 ExampleMatcher 创建一个新的 Example。

    默认情况下，ExampleMatcher 期望探测对象上设置的所有值都匹配。 如果您希望获取匹配任何隐式定义谓词的结果，请使用 ExampleMatcher.matchingAny()。

    您可以为单个属性（例如"firstname"和"lastname"，或对于嵌套属性如"address.city"）指定行为。 您可以通过匹配选项和大小写敏感性对其进行调整，如下例所示：

    配置匹配器选项
    ExampleMatcher matcher = ExampleMatcher.matching()
  .withMatcher("firstname", endsWith())
  .withMatcher("lastname", startsWith().ignoreCase());
}

    另一种配置匹配器选项的方法是使用 Lambda 表达式（Java 8 引入）。这种方法会创建一个回调，要求实现者修改匹配器。您无需返回匹配器，因为配置选项保存在匹配器实例内部。以下示例展示了一个使用 Lambda 表达式的匹配器：

    使用 Lambda 配置匹配器选项
    ExampleMatcher matcher = ExampleMatcher.matching()
  .withMatcher("firstname", match -> match.endsWith())
  .withMatcher("firstname", match -> match.startsWith());
}

    由 `Example` 创建的查询使用配置的合并视图。 默认匹配设置可在 `ExampleMatcher` 级别进行配置，而特定属性路径可应用独立的设置。 在 `ExampleMatcher` 上设置的配置会被属性路径设置继承，除非这些配置被显式定义。 属性路径上的设置优先级高于默认设置。 下表描述了各种 `ExampleMatcher` 配置的适用范围：

    流式 API

    QueryByExampleExecutor 定义了流式查询方法，用于基于 Example 实例灵活执行查询，其接口为 findBy(Example<S> example, Function<FluentQuery.FetchableFluentQuery<S>, R> queryFunction)。

    与其他方法一样，它执行一个由 `Example` 派生的查询。 然而，查询函数允许您控制其他动态方式无法控制的查询执行方面。 您可以通过调用 `FetchableFluentQuery` 的各种中间和终端方法来实现这一点。

    中级方法

    • sortBy：对结果应用排序。重复调用该方法会追加每个Sort（请注意，使用已排序的Pageable的page(Pageable)会覆盖任何之前的排序顺序）。

    • limit：限制结果数量。

    • as：指定要读取或投影的类型。

    • project：限制查询属性。

    终端方法

    • first 和 firstValue：返回第一个值。如果查询未产生任何结果，first 将返回一个 Optional<T> 或 Optional.empty()。firstValue 是其无需使用 Optional 的可为 null 变体。

    • one、oneValue：返回单个值。若查询未找到任何结果，one 将返回 Optional<T> 或 Optional.empty()。oneValue 是其可空变体，无需使用 Optional。 如果找到多个匹配项，则抛出 IncorrectResultSizeDataAccessException。

    • all：返回所有结果作为 List<T>。

    • page(Pageable)：返回所有结果作为 Page<T>。

    • slice(Pageable)：将所有结果返回为 Slice<T>。

    • scroll(ScrollPosition)：使用滚动（偏移量、键集）以 Window<T> 的形式检索结果。

    • stream()：返回一个用于惰性处理结果的 Stream<T>。 该流是有状态的，使用后必须关闭。

    • count 和 exists：返回匹配实体的数量或是否存在任何匹配项。

    中间方法和终端方法必须在查询函数内调用。
    示例 3。使用流式 API 获取按 lastname 排序的投影 Page。
    Page<CustomerProjection> page = repository.findBy(example,
    q -> q.as(CustomerProjection.class)
          .page(PageRequest.of(0, 20, Sort.by("lastname")))
);
    示例 4：使用流式 API 获取按 lastname 排序的多个潜在结果中的最后一个。
    Optional<Customer> match = repository.findBy(example,
    q -> q.sortBy(Sort.by("lastname").descending())
          .first()
);
