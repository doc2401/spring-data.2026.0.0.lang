    Spring Data Neo4j 投影

    如上所述，投影分为两种类型：基于接口的投影和基于 DTO 的投影。 在 Spring Data Neo4j 中，这两种类型的投影都会直接影响通过网络传输的属性与关系。 因此，当您的节点和实体包含大量属性，而这些属性并非在所有应用场景中都需要时，这两种方法都可以降低数据库的负载。

    对于基于接口和 DTO 的投影，Spring Data Neo4j 将使用存储库的领域类型来构建查询。所有可能改变查询的属性的注解都会被考虑在内。领域类型是通过存储库声明定义的类型（例如，给定声明 `interface TestRepository extends CrudRepository<TestEntity, Long>`，领域类型即为 `TestEntity`）。

    基于接口的投影始终是对底层域类型的动态代理。定义在这些接口上的访问器名称（例如 getName）必须解析为投影实体上存在的属性（此处为 name）。这些属性在域类型上是否具有访问器并不重要，只要它们可以通过通用的 Spring Data 基础设施进行访问即可。后者已经得到保证，因为该域类型本身就不是持久化实体。

    基于 DTO 的投影在与自定义查询结合使用时具有更高的灵活性。虽然标准查询源自原始领域类型，因此只能使用该类型中定义的属性和关系，但自定义查询可以添加额外的属性。

    规则如下：首先，使用域类型的属性来填充 DTO。如果 DTO 通过访问器或字段声明了额外属性，Spring Data Neo4j 将在生成的记录中查找匹配的属性。属性必须完全按名称匹配，且可以是简单类型（如 org.springframework.data.neo4j.core.convert.Neo4jSimpleTypes 中所定义）或已知的持久化实体。支持这些类型的集合，但不支持映射。

    Spring Data Neo4j 还内置了另一种机制，允许在实体定义级别上定义加载和持久化的边界。有关此内容的更多信息，请参阅聚合边界部分。

    多级投影

    Spring Data Neo4j 还支持多级投影。

    多级投影示例
    interface ProjectionWithNestedProjection {

    String getName();

    List<Subprojection1> getLevel1();

    interface Subprojection1 {
        String getName();
        List<Subprojection2> getLevel2();
    }

    interface Subprojection2 {
        String getName();
    }
}

    尽管可以建模循环投影或指向将形成循环的实体，但投影逻辑不会遵循这些循环，而只会生成无环查询。

    多级投影被限制在其应投影的实体范围内。在此情况下，`RelationshipProperties` 属于实体类别，若应用投影则需予以尊重。

    投影的数据操作

    如果您以 DTO 形式获取了投影，则可以修改其值。 但如果您使用的是基于接口的投影，则不能直接更新该接口。 一种典型模式是在您的领域实体类中提供一个方法，该方法消费该接口并创建一个具有从接口复制值的领域实体。 这样，您就可以更新该实体，并按照下一节所述的方式使用投影蓝图/掩码再次持久化它。

    投影的持久化

    类似于通过投影检索数据，它们也可用作持久化的蓝图。 `Neo4jTemplate` 提供了一个流式 API，可将这些投影应用于保存操作。

    您可以为给定的领域类保存一个投影。

    为给定的领域类保存投影
    Projection projection = neo4jTemplate.save(DomainClass.class).one(projectionValue);

    或者，您可以保存一个域对象，但仅尊重投影中定义的字段。

    使用给定的投影蓝图保存域对象
    Projection projection = neo4jTemplate.saveAs(domainObject, Projection.class);

    在这两种情况下，仅投影中定义的字段和关系会进行更新。

    为防止数据被删除（例如移除关系），您始终应加载所有后续需要持久化的数据。

    完整示例

    鉴于以下实体、投影及其对应的仓储：

    一个简单的实体
    @Node
class TestEntity {
    @Id @GeneratedValue private Long id;

    private String name;

    @Property("a_property") (1)
    private String aProperty;
}
    1 此属性在图中具有不同的名称
    一个派生实体，继承自TestEntity
    @Node
class ExtendedTestEntity extends TestEntity {

    private String otherAttribute;
}
    接口的投影
    interface TestEntityInterfaceProjection {

    String getName();
}
    包含一个额外属性的TestEntity的 DTO 投影。
    class TestEntityDTOProjection {

    private String name;

    private Long numberOfRelations; (1)

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public Long getNumberOfRelations() {
        return numberOfRelations;
    }

    public void setNumberOfRelations(Long numberOfRelations) {
        this.numberOfRelations = numberOfRelations;
    }
}
    1 该属性在投影实体中不存在

    下面展示了一个用于 `TestEntity` 的仓储，其行为将如列表中所解释的那样。

    用于 TestEntity 的仓储
    interface TestRepository extends CrudRepository<TestEntity, Long> { (1)

    List<TestEntity> findAll(); (2)

    List<ExtendedTestEntity> findAllExtendedEntities(); (3)

    List<TestEntityInterfaceProjection> findAllInterfaceProjectionsBy(); (4)

    List<TestEntityDTOProjection> findAllDTOProjectionsBy(); (5)

    @Query("MATCH (t:TestEntity) - [r:RELATED_TO] -> () RETURN t, COUNT(r) AS numberOfRelations") (6)
    List<TestEntityDTOProjection> findAllDTOProjectionsWithCustomQuery();
}
    1 存储库的领域类型为 TestEntity
    2 返回一个或多个 TestEntity 的方法将直接返回其实例，因为它与领域类型匹配
    3 返回一个或多个继承自领域类型的类实例的方法将直接返回扩展类的实例。该方法所属的领域类型将是扩展后的类，这仍然满足存储库本身的领域类型要求
    4 此方法返回接口投影，因此方法的返回类型与存储库的领域类型不同。该接口只能访问在领域类型中定义的属性。后缀 By 是必需的，以防止 SDN 在 TestEntity 中查找名为 InterfaceProjections 的属性
    5 此方法返回 DTO 投影。执行它会导致 SDN 发出警告，因为 DTO 将 numberOfRelations 定义为额外属性，而该属性不在领域类型的契约中。TestEntity 中标注的属性 aProperty 将被正确翻译为查询中的 a_property。如上所述，返回类型与存储库的领域类型不同。后缀 By 是必需的，以防止 SDN 在 TestEntity 中查找名为 DTOProjections 的属性
    6 此方法也返回 DTO 投影。然而，不会发出警告，因为查询包含了投影中定义的额外属性的合适值
    虽然上面列出的存储库使用具体的返回类型来定义投影，但另一种变体是使用动态投影，正如 Spring Data Neo4j 与其他 Spring Data 项目共享的文档部分中所解释的那样。动态投影可以应用于封闭和开放接口投影，以及基于类的 DTO 投影：

    动态投影的关键在于将所需的投影类型作为查询方法的最后一个参数指定，例如在存储库中这样：<T> Collection<T> findByName(String name, Class<T> type)。这可以添加到上面的TestRepository中，允许通过同一方法检索不同的投影，而无需在多个方法上重复可能的@Query注解。

    聚合边界

    通过引入多个投影来反映多层级关系可能会变得繁琐。为了在实体层面简化这一问题，可以添加一个额外的参数 `aggregateBoundary` 并传入 1..n 个类。使用此参数后，参数化实体将仅返回其 `@Id` 字段，SDN 不会追踪其关联关系或获取其他属性。

    对于这些实体，仍然可以使用基于接口的投影。这些投影的范围甚至可以更广泛，例如包含声明的聚合边界内的属性或关系。
