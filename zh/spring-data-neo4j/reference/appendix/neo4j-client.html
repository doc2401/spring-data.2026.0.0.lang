    Neo4jClient

    Spring Data Neo4j 附带一个 Neo4j 客户端，它在 Neo4j 的 Java 驱动程序之上提供了一层轻量级封装。

    虽然纯 Java 驱动是一个功能强大的工具，除了提供命令式和响应式版本外，还支持异步 API，但它无法与 Spring 应用级别的事务进行集成。

    SDN 通过尽可能直接地利用惯用客户端的概念来使用驱动程序。

    客户的主要目标如下：

    1. 集成到 Spring 的事务管理中，同时支持命令式和响应式场景。

    2. 如有需要，请参与 JTA 事务。

    3. 为命令式和响应式场景提供一致的 API。

    4. 不要添加任何映射开销。

    软件定义网络（SDN）依赖所有这些特性，并利用它们来实现其实体映射功能。

    请查看SDN 构建模块，了解在我们的架构中命令式和反应式 Neo4 客户端的位置。

    Neo4j 客户端有两种类型：

    • org.springframework.data.neo4j.core.Neo4jClient

    • org.springframework.data.neo4j.core.ReactiveNeo4jClient

    虽然两个版本都使用相同的词汇和语法提供 API，但它们并不兼容。两个版本均具备相同且流畅的 API，可用于指定查询、绑定参数以及提取结果。

    命令式还是响应式？

    与 Neo4j 客户端的交互通常以调用

    • fetch().one()

    • fetch().first()

    • fetch().all()

    • run()

    命令式版本将在当前时刻与数据库交互，获取请求的结果或摘要，并将其封装在 `Optional<>` 或 `Collection` 中。

    相比之下，响应式版本将返回一个请求类型的发布者。与数据库的交互及结果的检索将在订阅该发布者时才会发生。该发布者只能被订阅一次。

    获取客户端实例

    与 SDN 中的大多数事物一样，这两种客户端都依赖于已配置的驱动程序实例。

    创建命令式 Neo4j 客户端实例
    import org.neo4j.driver.AuthTokens;
import org.neo4j.driver.Driver;
import org.neo4j.driver.GraphDatabase;

import org.springframework.data.neo4j.core.Neo4jClient;

public class Demo {

    public static void main(String...args) {

        Driver driver = GraphDatabase
            .driver("neo4j://localhost:7687", AuthTokens.basic("neo4j", "secret"));

        Neo4jClient client = Neo4jClient.create(driver);
    }
}

    驱动程序仅能针对 4.0 版本的数据库打开反应式会话，若尝试连接更低版本，则会抛出异常。

    创建反应式 Neo4j 客户端实例
    import org.neo4j.driver.AuthTokens;
import org.neo4j.driver.Driver;
import org.neo4j.driver.GraphDatabase;

import org.springframework.data.neo4j.core.ReactiveNeo4jClient;

public class Demo {

    public static void main(String...args) {

        Driver driver = GraphDatabase
            .driver("neo4j://localhost:7687", AuthTokens.basic("neo4j", "secret"));

        ReactiveNeo4jClient client = ReactiveNeo4jClient.create(driver);
    }
}
    如果您启用了事务，请确保为客户端使用的驱动程序实例与提供 Neo4jTransactionManager 或 ReactiveNeo4jTransactionManager 时使用的实例相同。 如果使用另一个驱动程序实例，客户端将无法同步事务。

    我们的 Spring Boot Starter 提供了一个适用于环境（命令式或响应式）的即用型 Neo4j Client Bean，通常您无需自行配置实例。

    Usage

    选择目标数据库

    Neo4j 客户端已为使用 Neo4j 4.0 的多数据库功能做好了充分准备。除非另有指定，否则客户端将使用默认数据库。 该客户端的流式 API 允许在声明要执行的查询之后，仅一次指定目标数据库。 选择目标数据库 部分通过响应式客户端展示了这一功能：

    选择目标数据库
    Flux<Map<String, Object>> allActors = client
	.query("MATCH (p:Person) RETURN p")
	.in("neo4j") (1)
	.fetch()
	.all();
    1 选择要执行查询的目标数据库。

    指定查询

    与客户端的交互始于一个查询。 查询可以定义为一个普通的 `String` 或一个 `Supplier`。 该供应者将在尽可能晚的时候被求值，并且可以由任何查询构建器提供。

    指定查询
    Mono<Map<String, Object>> firstActor = client
	.query(() -> "MATCH (p:Person) RETURN p")
	.fetch()
	.first();

    获取结果

    如前文所列，与客户端的交互始终以调用 `fetch` 并接收结果数量作为结束。无论是响应式还是命令式客户端均提供此功能。

    one()

    查询应仅返回一个结果。

    first()

    期望结果并返回第一条记录。

    all()

    检索所有返回的记录

    命令式客户端分别返回 `Optional<T>` 和 `Collection<T>`，而响应式客户端则返回 `Mono<T>` 和 `Flux<T>`，后者仅在订阅时才会执行。

    如果您不期望查询产生任何结果，请在指定查询后使用 `run()`。

    以响应式方式检索结果摘要
    Mono<ResultSummary> summary = reactiveClient
    .query("MATCH (m:Movie) where m.title = 'Aeon Flux' DETACH DELETE m")
    .run();

summary
    .map(ResultSummary::counters)
    .subscribe(counters ->
        System.out.println(counters.nodesDeleted() + " nodes have been deleted")
    ); (1)
    1 在此处通过订阅发布者来触发实际查询。

    请花点时间比较这两个列表，以便在触发实际查询时理解它们之间的差异。

    以命令式方式检索结果摘要
    ResultSummary resultSummary = imperativeClient
	.query("MATCH (m:Movie) where m.title = 'Aeon Flux' DETACH DELETE m")
	.run(); (1)

SummaryCounters counters = resultSummary.counters();
System.out.println(counters.nodesDeleted() + " nodes have been deleted")
    1 此处会立即触发查询。

    映射参数

    查询可以包含命名参数（$someName），Neo4j 客户端可以轻松地将值绑定到这些参数上。

    客户端不会检查所有参数是否都已绑定，也不会检查是否存在过多的值。这些由驱动程序自行处理。不过，客户端会防止您重复使用同一个参数名称。

    您可以绑定 Java 驱动程序无需转换即可理解的简单类型，或绑定复杂类。 对于复杂类，您需要提供如此示例所示的绑定函数。 请查看驱动程序手册，以了解支持的简单类型。

    映射简单类型
    Map<String, Object> parameters = new HashMap<>();
parameters.put("name", "Li.*");

Flux<Map<String, Object>> directorAndMovies = client
	.query(
		"MATCH (p:Person) - [:DIRECTED] -> (m:Movie {title: $title}), (p) - [:WROTE] -> (om:Movie) " +
			"WHERE p.name =~ $name " +
			"  AND p.born < $someDate.year " +
			"RETURN p, om"
	)
	.bind("The Matrix").to("title") (1)
	.bind(LocalDate.of(1979, 9, 21)).to("someDate")
	.bindAll(parameters) (2)
	.fetch()
	.all();
    1 存在一个用于绑定简单类型的流式 API。
    2 或者，也可以通过命名参数的映射来绑定参数。

    SDN 执行了大量复杂的映射操作，并使用了客户端可用的相同 API。

    您可以为任何给定的领域对象（例如领域类型示例中的自行车所有者）提供一个Function<T, Map<String, Object>>，并将其传递给 Neo4j Client，以便将该驱动能够理解的参数映射到这些领域对象上。

    域类型的示例
    public class Director {

    private final String name;

    private final List<Movie> movies;

    Director(String name, List<Movie> movies) {
        this.name = name;
        this.movies = new ArrayList<>(movies);
    }

    public String getName() {
        return name;
    }

    public List<Movie> getMovies() {
        return Collections.unmodifiableList(movies);
    }
}

public class Movie {

    private final String title;

    public Movie(String title) {
        this.title = title;
    }

    public String getTitle() {
        return title;
    }
}

    映射函数必须填充查询中可能出现的所有命名参数，正如使用映射函数绑定域对象所示：

    使用映射函数绑定域对象
    Director joseph = new Director("Joseph Kosinski",
        Arrays.asList(new Movie("Tron Legacy"), new Movie("Top Gun: Maverick")));

Mono<ResultSummary> summary = client
    .query(""
        + "MERGE (p:Person {name: $name}) "
        + "WITH p UNWIND $movies as movie "
        + "MERGE (m:Movie {title: movie}) "
        + "MERGE (p) - [o:DIRECTED] -> (m) "
    )
    .bind(joseph).with(director -> { (1)
        Map<String, Object> mappedValues = new HashMap<>();
        List<String> movies = director.getMovies().stream()
            .map(Movie::getTitle).collect(Collectors.toList());
        mappedValues.put("name", director.getName());
        mappedValues.put("movies", movies);
        return mappedValues;
    })
    .run();
    1 with 方法允许指定绑定函数。

    处理结果对象

    两个客户端都返回地图集合或出版商（Map<String, Object>）。 这些地图与查询可能生成的记录完全对应。

    此外，您可以通过 `fetchAs` 插入您自己的 `BiFunction<TypeSystem, Record, T>` 来重构您的领域对象。

    使用映射函数读取领域对象
    Mono<Director> lily = client
    .query(""
        + " MATCH (p:Person {name: $name}) - [:DIRECTED] -> (m:Movie)"
        + "RETURN p, collect(m) as movies")
    .bind("Lilly Wachowski").to("name")
    .fetchAs(Director.class).mappedBy((TypeSystem t, Record record) -> {
        List<Movie> movies = record.get("movies")
            .asList(v -> new Movie((v.get("title").asString())));
        return new Director(record.get("name").asString(), movies);
    })
    .one();

    TypeSystem 提供了对底层 Java 驱动用于填充记录的类型的访问权限。

    使用领域感知的映射函数

    如果您知道查询结果将包含具有应用程序中实体定义的节点，您可以使用可注入的MappingContext来获取其映射函数，并在映射过程中应用这些函数。

    使用现有的映射函数
    BiFunction<TypeSystem, MapAccessor, Movie> mappingFunction = neo4jMappingContext.getRequiredMappingFunctionFor(Movie.class);
Mono<Director> lily = client
    .query(""
        + " MATCH (p:Person {name: $name}) - [:DIRECTED] -> (m:Movie)"
        + "RETURN p, collect(m) as movies")
    .bind("Lilly Wachowski").to("name")
    .fetchAs(Director.class).mappedBy((TypeSystem t, Record record) -> {
        List<Movie> movies = record.get("movies")
            .asList(movie -> mappingFunction.apply(t, movie));
        return new Director(record.get("name").asString(), movies);
    })
    .one();

    在使用托管事务时直接与驱动程序交互

    如果您不喜欢或不需要 `Neo4jClient` 和 `ReactiveNeo4jClient` 这种带有观点的“客户端”方式，可以让客户端将所有与数据库的交互委托给您的代码。 在委托之后，命令式和响应式版本的客户端之间的交互略有不同。

    命令式版本接收一个 `Function<StatementRunner, Optional<T>>` 作为回调。返回空可选是可以的。

    将数据库交互委托给命令式 `StatementRunner`。
    Optional<Long> result = client
    .delegateTo((StatementRunner runner) -> {
        // Do as many interactions as you want
        long numberOfNodes = runner.run("MATCH (n) RETURN count(n) as cnt")
            .single().get("cnt").asLong();
        return Optional.of(numberOfNodes);
    })
    // .in("aDatabase") (1)
    .run();
    1 如选择目标数据库部分所述，数据库选择是可选的。

    响应式版本接收一个 RxStatementRunner。

    将数据库交互委托给反应式的 RxStatementRunner
    Mono<Integer> result = client
    .delegateTo((RxStatementRunner runner) ->
        Mono.from(runner.run("MATCH (n:Unused) DELETE n").summary())
            .map(ResultSummary::counters)
            .map(SummaryCounters::nodesDeleted))
    // .in("aDatabase") (1)
    .run();
    1 可选目标数据库。

    请注意，在将数据库交互委托给命令式StatementRunner和将数据库交互委托给响应式RxStatementRunner中，仅说明了运行器的类型，以便为本文档的读者提供更清晰的说明。
