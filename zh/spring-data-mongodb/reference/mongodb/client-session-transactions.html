    Sessions & Transactions

    从版本 3.6 开始，MongoDB 支持会话的概念。 使用会话可以启用 MongoDB 的因果一致性模型，该模型保证操作按照尊重其因果关系的方式运行。 这些会话分为 ServerSession 实例和 ClientSession 实例。 在本节中，当我们提到会话时，指的是 ClientSession。

    客户端会话内的操作与会话外的操作之间不存在隔离。

    `MongoOperations` 和 `ReactiveMongoOperations` 均提供了将 `ClientSession` 绑定到操作的方法。 `MongoCollection` 和 `MongoDatabase` 使用实现了 MongoDB 集合和数据库接口的会话代理对象，因此无需在每次调用时显式添加会话。 这意味着对 `MongoCollection#find()` 的潜在调用会被委托给 `MongoCollection#find(ClientSession)`。

    诸如(Reactive)MongoOperations#getCollection之类的方法会返回原生 MongoDB Java 驱动网关对象（例如MongoCollection），这些对象本身提供了用于ClientSession的专用方法。 这些方法并非会话代理。 在与MongoCollection或MongoDatabase直接交互时，您需要在需要的位置提供ClientSession，而不应通过MongoOperations上的某个#execute回调进行交互。

    客户端会话支持

    以下示例展示了会话的使用：

    • Imperative

    • Reactive

    ClientSessionOptions sessionOptions = ClientSessionOptions.builder()
    .causallyConsistent(true)
    .build();

ClientSession session = client.startSession(sessionOptions); (1)

template.withSession(() -> session)
    .execute(action -> {

        Query query = query(where("name").is("Durzo Blint"));
        Person durzo = action.findOne(query, Person.class);  (2)

        Person azoth = new Person("Kylar Stern");
        azoth.setMaster(durzo);

        action.insert(azoth);                                (3)

        return azoth;
    });

session.close()                                              (4)
    1 从服务器获取新会话。
    2 像往常一样使用 MongoOperation 方法。 ClientSession 会自动应用。
    3 确保关闭 ClientSession。
    4 关闭会话。
    在处理 DBRef 实例（尤其是懒加载的实例）时，务必在所有数据加载完成之前不要关闭 ClientSession。否则，懒加载将失败。 
    ClientSessionOptions sessionOptions = ClientSessionOptions.builder()
.causallyConsistent(true)
.build();

Publisher<ClientSession> session = client.startSession(sessionOptions); (1)

template.withSession(session)
.execute(action -> {

        Query query = query(where("name").is("Durzo Blint"));
        return action.findOne(query, Person.class)
            .flatMap(durzo -> {

                Person azoth = new Person("Kylar Stern");
                azoth.setMaster(durzo);

                return action.insert(azoth);                            (2)
            });
    }, ClientSession::close)                                            (3)
    .subscribe();                                                       (4)
    1 获取用于新会话检索的 Publisher。
    2 像往常一样使用 ReactiveMongoOperation 方法。 ClientSession 会自动获取并应用。
    3 务必关闭 ClientSession。
    4 在订阅之前不会发生任何操作。 有关详细信息，请参阅Project Reactor 参考指南。

    通过使用提供实际会话的 Publisher，您可以将会话获取推迟到实际订阅时。 不过，在使用完毕后仍需关闭会话，以免服务器中残留过期的会话。 请使用 execute 上的 doFinally 钩子来调用 ClientSession#close()，以在不再需要会话时关闭它。 如果您希望对会话本身拥有更多控制权，可以通过驱动程序获取 ClientSession，并通过一个 Supplier 提供它。

    对 ClientSession 的反应式使用仅限于模板 API。 目前尚未实现与反应式存储库的会话集成。

    MongoDB 事务

    从版本 4 开始，MongoDB 支持事务。 事务构建在会话之上，因此需要一个活跃的ClientSession。

    除非在应用程序上下文中指定了 MongoTransactionManager，否则事务支持处于禁用状态。 您可以使用 setSessionSynchronization(ALWAYS) 来参与正在进行的非原生 MongoDB 事务。

    若要实现对事务的完全程序化控制，您可能希望使用 MongoOperations 上的会话回调。

    以下示例展示了程序化事务控制：

    程序化交易

    • Imperative

    • Reactive

    ClientSession session = client.startSession(options);                   (1)

template.withSession(session)
    .execute(action -> {

        session.startTransaction();                                     (2)

        try {

            Step step = // ...;
            action.insert(step);

            process(step);

            action.update(Step.class).apply(Update.set("state", // ...

            session.commitTransaction();                                (3)

        } catch (RuntimeException e) {
            session.abortTransaction();                                 (4)
        }
    }, ClientSession::close)                                            (5)
    1 获取一个新的 ClientSession。
    2 启动事务。
    3 如果一切按预期进行，则提交更改。
    4 若出现问题，则回滚所有操作。
    5 完成后别忘了关闭会话。

    前面的示例让您在使用会话范围的 `MongoOperations` 实例时能够完全控制事务行为，同时确保在回调中将会话传递给每个服务器调用。 为避免这种方法带来的一些开销，您可以使用 `TransactionTemplate` 来简化手动事务流程中的繁琐操作。

    Mono<DeleteResult> result = Mono
    .from(client.startSession())                                                             (1)

    .flatMap(session -> {
        session.startTransaction();                                                          (2)

        return Mono.from(collection.deleteMany(session, ...))                                (3)

            .onErrorResume(e -> Mono.from(session.abortTransaction()).then(Mono.error(e)))   (4)

            .flatMap(val -> Mono.from(session.commitTransaction()).then(Mono.just(val)))     (5)

            .doFinally(signal -> session.close());                                           (6)
      });
    1 首先，我们显然需要启动会话。
    2 一旦手头有了 ClientSession，就开始事务。
    3 通过将 ClientSession 传递给操作，在事务内执行操作。
    4 如果操作异常完成，我们需要中止事务并保留错误信息。
    5 或者当然，在成功时提交更改。 同时保留操作结果。
    6 最后，我们需要确保关闭会话。

    上述操作的罪魁祸首在于保留了主流程中的 `DeleteResult`，而不是通过 `commitTransaction()` 或 `abortTransaction()` 发布事务结果，这导致了一个相当复杂的设置。

    除非在您的应用程序上下文中指定了 ReactiveMongoTransactionManager，否则事务支持处于禁用状态。 您可以使用 setSessionSynchronization(ALWAYS) 来参与正在进行的非原生 MongoDB 事务。

    使用 TransactionTemplate/TransactionalOperator 进行事务操作

    Spring Data MongoDB 的事务支持同时涵盖 `TransactionTemplate` 和 `TransactionalOperator`。

    使用 TransactionTemplate / TransactionalOperator 的事务操作

    • Imperative

    • Reactive

    template.setSessionSynchronization(ALWAYS);                                     (1)

// ...

TransactionTemplate txTemplate = new TransactionTemplate(anyTxManager);         (2)

txTemplate.execute(new TransactionCallbackWithoutResult() {

    @Override
    protected void doInTransactionWithoutResult(TransactionStatus status) {     (3)

        Step step = // ...;
        template.insert(step);

        process(step);

        template.update(Step.class).apply(Update.set("state", // ...
    }
});
    1 在配置 Template API 时启用事务同步。
    2 使用提供的 PlatformTransactionManager 创建 TransactionTemplate。
    3 在回调中，ClientSession 和事务已经注册。
    在运行时更改 MongoTemplate 的状态（正如您可能会认为在上一列表的第 1 项中那样可行）可能会导致线程和可见性问题。 
    template.setSessionSynchronization(ALWAYS);                                          (1)

// ...

TransactionalOperator rxtx = TransactionalOperator.create(anyTxManager,
                                   new DefaultTransactionDefinition());              (2)


Step step = // ...;
template.insert(step);

Mono<Void> process(step)
    .then(template.update(Step.class).apply(Update.set("state", …))
    .as(rxtx::transactional)                                                         (3)
    .then();
    1 启用事务同步以支持事务性参与。
    2 使用提供的 ReactiveTransactionManager 创建 TransactionalOperator。
    3 TransactionalOperator.transactional(…) 为所有上游操作提供事务管理。

    MongoTransactionManager 与 ReactiveMongoTransactionManager 的事务

    MongoTransactionManager 和 ReactiveMongoTransactionManager 是通往广为人知的 Spring 事务支持的入口。它们使应用程序能够使用Spring 的事务管理功能。MongoTransactionManager 将 ClientSession 绑定到线程，而 ReactiveMongoTemplate 则利用 ReactorContext 实现此功能。MongoTemplate 会检测会话，并针对与事务关联的资源执行相应操作。此外，MongoTemplate 还可以参与其他正在进行的事务。以下示例展示了如何使用 MongoTransactionManager 创建和使用事务：

    与 MongoTransactionManager / ReactiveMongoTransactionManager 的交互

    • Imperative

    • Reactive

    @Configuration
static class Config extends AbstractMongoClientConfiguration {

    @Bean
    MongoTransactionManager transactionManager(MongoDatabaseFactory dbFactory) {  (1)
        return new MongoTransactionManager(dbFactory);
    }

    @Bean
    MongoTemplate mongoTemplate(MongoDatabaseFactory dbFactory) {                 (1)
        return new MongoTemplate(dbFactory);
    }

    // ...
}

@Component
public class StateService {

    @Transactional
    void someBusinessFunction(Step step) {                                        (2)

        template.insert(step);

        process(step);

        template.update(Step.class).apply(Update.set("state", // ...
    };
});
    1 在应用程序上下文中注册 MongoTransactionManager。此外，确保在创建用于同一 MongoDatabaseFactory 事务范围的 MongoTemplate 时，使用相同的 MongoDatabaseFactory。
    2 将方法标记为事务性。
    @Transactional(readOnly = true) 会建议 MongoTransactionManager 启动一个事务，并将 ClientSession 添加到出站请求中。 
    @Configuration
public class Config extends AbstractReactiveMongoConfiguration {

    @Bean
    ReactiveMongoTransactionManager transactionManager(ReactiveMongoDatabaseFactory factory) {  (1)
        return new ReactiveMongoTransactionManager(factory);
    }

    @Bean
    ReactiveMongoTemplate reactiveMongoTemplate(ReactiveMongoDatabaseFactory dbFactory) {       (1)
        return new ReactiveMongoTemplate(dbFactory);
    }

    // ...
}

@Service
public class StateService {

    @Transactional
    Mono<UpdateResult> someBusinessFunction(Step step) {                                  (2)

        return template.insert(step)
            .then(process(step))
            .then(template.update(Step.class).apply(Update.set("state", …));
    };
});
    1 在应用程序上下文中注册 ReactiveMongoTransactionManager。此外，确保在创建 ReactiveMongoTemplate 时使用相同的 ReactiveMongoDatabaseFactory，以便在同一 ReactiveMongoDatabaseFactory 的范围内参与事务。
    2 将方法标记为事务性。
    @Transactional(readOnly = true) 会建议 ReactiveMongoTransactionManager 启动一个事务，并将 ClientSession 添加到出站请求中。

    控制 MongoDB 特定的事务选项

    事务服务方法可能需要特定的事务选项来运行事务。Spring Data MongoDB 的事务管理器支持评估事务标签，例如 `@Transactional(label = { "mongo:readConcern=available" })`。

    默认情况下，使用 `mongo:` 前缀的标签命名空间由默认配置的 `MongoTransactionOptionsResolver` 进行评估。 事务标签由 `TransactionAttribute`》提供，并通过 `TransactionTemplate`》和 `TransactionalOperator`》用于程序化事务控制。 由于其声明式特性，`@Transactional(label = …)` 提供了一个良好的起点，同时也可以作为文档使用。

    目前支持以下选项：

    最大提交时间

    控制服务器上 `commitTransaction` 操作的最大执行时间。 该值的格式对应于 `Duration.parse(…)` 中使用的 ISO-8601 持续时间格式。

    Usage: mongo:maxCommitTime=PT1S

    读关注

    设置事务的读关注级别。

    Usage: mongo:readConcern=LOCAL|MAJORITY|LINEARIZABLE|SNAPSHOT|AVAILABLE

    读偏好

    设置事务的读取偏好。

    Usage: mongo:readPreference=PRIMARY|SECONDARY|SECONDARY_PREFERRED|PRIMARY_PREFERRED|NEAREST

    写入关注

    设置事务的写关注。

    Usage: mongo:writeConcern=ACKNOWLEDGED|W1|W2|W3|UNACKNOWLEDGED|JOURNALED|MAJORITY

    与外部事务关联的嵌套事务不会影响初始的事务选项，因为该事务已经启动。 事务选项仅在启动新事务时才会应用。

    事务内的特殊行为

    在内部事务中，MongoDB 服务器的行为略有不同。

    连接设置

    MongoDB 驱动程序提供了一个专用的副本集名称配置选项，可将驱动程序切换为自动检测模式。该选项有助于在事务期间识别主副本集节点并路由命令。

    请确保在 MongoDB URI 中添加 replicaSet。 有关详细信息，请参阅连接字符串选项。

    集合操作

    MongoDB 不支持在事务内执行集合操作，例如创建集合。 这也影响了首次使用时动态创建的集合。 因此，请确保所有必要的结构均已就绪。

    瞬态错误

    MongoDB 可以在事务操作期间抛出的错误上添加特殊标签。这些标签可能表示瞬态失败，仅通过重试操作即可消除。我们强烈建议为此目的使用 Spring Retry。尽管如此，也可以重写 MongoTransactionManager#doCommit(MongoTransactionObject) 来实现 MongoDB 参考手册中概述的 重试提交操作 行为。

    Count

    MongoDB 的 `count` 操作基于集合统计信息，这些信息可能无法反映事务内的实际情况。 当在多文档事务中发出 `count` 命令时，服务器会返回错误 50851。 一旦 `MongoTemplate` 检测到活动事务，所有暴露的 `count()` 方法都会被转换并委托给聚合框架，使用 `$match` 和 `$count` 运算符，同时保留 `Query` 设置（如 `collation`）。

    在聚合计数辅助函数中使用地理命令时存在限制。以下运算符无法使用，必须替换为其他运算符：

    • $where → $expr

    • $near → $geoWithin with $center

    • $nearSphere → $geoWithin with $centerSphere

    使用 `Criteria.near(…)` 和 `Criteria.nearSphere(…)` 的查询必须重写为 `Criteria.within(…)` 或相应的 `Criteria.withinSphere(…)`。 此规则同样适用于仓库查询方法中的 `near` 查询关键字，需将其更改为 `within`。 有关更多信息，请参阅 MongoDB JIRA 工单 DRIVERS-518。

    以下代码片段展示了在会话绑定闭包中使用`count`的情况：

    session.startTransaction();

template.withSession(session)
    .execute(ops -> {
        return ops.count(query(where("state").is("active")), Step.class)
        });

    上述片段对应于以下命令：

    db.collection.aggregate(
   [
      { $match: { state: "active" } },
      { $count: "totalEntityCount" }
   ]
)

    改为：

    db.collection.find( { state: "active" } ).count()
