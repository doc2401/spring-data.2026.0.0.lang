    通过 RedisTemplate 操作对象

    大多数用户很可能会使用RedisTemplate及其对应的包org.springframework.data.redis.core，或者其响应式变体ReactiveRedisTemplate。 模板实际上是 Redis 模块的核心类，这得益于其丰富的功能集。 模板为 Redis 交互提供了高级抽象。 虽然[Reactive]RedisConnection提供接受并返回二进制值（byte数组）的低级方法，但模板负责处理序列化和连接管理，使用户无需处理这些细节。

    `RedisTemplate` 类实现了 `RedisOperations` 接口，而其响应式变体 `ReactiveRedisTemplate` 则实现了 `ReactiveRedisOperations`。

    引用 [Reactive]RedisTemplate 实例上操作的推荐方式是通过 [Reactive]RedisOperations 接口。

    此外，该模板提供了操作视图（遵循 Redis 命令参考中的分组），通过如下的表格中描述的KeyBound接口，为针对特定类型或特定键的操作提供丰富且泛化的接口：

    配置完成后，该模板是线程安全的，可在多个实例中重复使用。

    RedisTemplate 在其大多数操作中采用基于 Java 的序列化器。这意味着模板写入或读取的任何对象都通过 Java 进行序列化和反序列化。

    您可以在模板中更改序列化机制，Redis 模块提供了多种实现方式，这些实现位于 org.springframework.data.redis.serializer 包中。有关更多信息，请参阅序列化器。 您也可以将任意序列化器设置为 null，并通过将 enableDefaultSerializer 属性设置为 false 来使用 RedisTemplate 处理原始字节数组。 请注意，模板要求所有键均不能为 null。然而，只要底层序列化器支持，值可以为 null。有关更多信息，请阅读每个序列化器的 Javadoc。

    对于需要特定模板视图的情况，请将视图声明为依赖项并注入该模板。容器会自动执行转换，从而消除 `opsFor[X]` 调用，如下例所示：

    配置模板 API

    • Java 命令式

    • Java 响应式

    • XML

    @Configuration
class MyConfig {

  @Bean
  LettuceConnectionFactory connectionFactory() {
    return new LettuceConnectionFactory();
  }

  @Bean
  RedisTemplate<String, String> redisTemplate(RedisConnectionFactory connectionFactory) {

    RedisTemplate<String, String> template = new RedisTemplate<>();
    template.setConnectionFactory(connectionFactory);
    return template;
  }
}
    @Configuration
class MyConfig {

  @Bean
  LettuceConnectionFactory connectionFactory() {
    return new LettuceConnectionFactory();
  }

  @Bean
  ReactiveRedisTemplate<String, String> ReactiveRedisTemplate(ReactiveRedisConnectionFactory connectionFactory) {
    return new ReactiveRedisTemplate<>(connectionFactory, RedisSerializationContext.string());
  }
}

    使用 `[Reactive]RedisTemplate` 将项推送到列表中

    • Imperative

    • Reactive

    public class Example {

  // inject the actual operations
  @Autowired
  private RedisOperations<String, String> operations;

  // inject the template as ListOperations
  @Resource(name="redisTemplate")
  private ListOperations<String, String> listOps;

  public void addLink(String userId, URL url) {
    listOps.leftPush(userId, url.toExternalForm());
  }
}
    public class Example {

  // inject the actual template
  @Autowired
  private ReactiveRedisOperations<String, String> operations;

  public Mono<Long> addLink(String userId, URL url) {
    return operations.opsForList().leftPush(userId, url.toExternalForm());
  }
}

    专注于字符串的便捷类

    由于存储在 Redis 中的键和值通常是java.lang.String类型，Redis 模块为此提供了两个扩展：分别针对RedisConnection和RedisTemplate的StringRedisConnection（及其默认实现类DefaultStringRedisConnection）以及StringRedisTemplate，作为执行密集字符串操作的一站式便捷解决方案。 除了键被绑定为String类型外，模板和连接在底层均使用StringRedisSerializer进行序列化，这意味着存储的键和值是可读的（前提是 Redis 端与代码端使用了相同的编码）。 以下示例展示了具体用法：

    • Java 命令式

    • Java 响应式

    • XML

    @Configuration
class RedisConfiguration {

  @Bean
  LettuceConnectionFactory redisConnectionFactory() {
    return new LettuceConnectionFactory();
  }

  @Bean
  StringRedisTemplate stringRedisTemplate(RedisConnectionFactory redisConnectionFactory) {

    StringRedisTemplate template = new StringRedisTemplate();
    template.setConnectionFactory(redisConnectionFactory);
    return template;
  }
}
    @Configuration
class RedisConfiguration {

  @Bean
  LettuceConnectionFactory redisConnectionFactory() {
    return new LettuceConnectionFactory();
  }

  @Bean
  ReactiveStringRedisTemplate reactiveRedisTemplate(ReactiveRedisConnectionFactory factory) {
    return new ReactiveStringRedisTemplate<>(factory);
  }
}

    与其他 Spring 模板类似，RedisTemplate 和 StringRedisTemplate 允许您通过 RedisCallback 接口直接与 Redis 通信。 此功能为您提供完全的控制权，因为它直接访问 RedisConnection。 请注意，当使用 StringRedisTemplate 时，回调接收到的实例是 StringRedisConnection。 以下示例展示了如何使用 RedisCallback 接口：

    public void useCallback() {

  redisOperations.execute(new RedisCallback<Object>() {
    public Object doInRedis(RedisConnection connection) throws DataAccessException {
      Long size = connection.dbSize();
      // Can cast to StringRedisConnection if using a StringRedisTemplate
      ((StringRedisConnection)connection).set("key", "value");
    }
   });
}

    Serializers

    从架构角度来看，Redis 中存储的数据本质上只是字节。虽然 Redis 本身支持多种数据类型，但大多数情况下，这些类型指的是数据的存储方式，而非其代表的含义。是否将信息转换为字符串或其他对象，由用户自行决定。

    在 Spring Data 中，用户（自定义）类型与原始数据之间的转换（反之亦然）由 Spring Data Redis 在 `org.springframework.data.redis.serializer` 包中处理。

    该包包含两种类型的序列化器，顾名思义，它们负责处理序列化过程：

    • 基于 RedisSerializer 的双向序列化器。

    • 使用 `RedisElementReader` 和 `RedisElementWriter` 的 Element 读取器和写入器。

    这些变体之间的主要区别在于，RedisSerializer 主要序列化为 byte[]，而读写器则使用 ByteBuffer。

    有多种实现方式可供选择（包括本文档中已提到的两种）：

    • JdkSerializationRedisSerializer，默认用于 RedisCache 和 RedisTemplate。

    • the StringRedisSerializer.

    不过，可以使用 `OxmSerializer` 通过 Spring 的 OXM 支持进行对象/XML 映射，或使用 `JacksonJsonRedisSerializer` 或 `GenericJacksonJsonRedisSerializer` 以 JSON 格式存储数据。

    请注意，存储格式不仅限于值。它可以用于键、值或哈希，没有任何限制。

    默认情况下，RedisCache 和 RedisTemplate 被配置为使用 Java 原生序列化。 Java 原生序列化因允许执行由利用易受攻击的库和类的有效载荷引发的远程代码而臭名昭著，这些有效载荷会注入未经验证的字节码。 经过操纵的输入可能导致在反序列化步骤期间在应用程序中运行不需要的代码。 因此，请勿在不信任的环境中使用时序化。 一般来说，我们强烈建议改用其他消息格式（如 JSON）。

    如果您担心因 Java 序列化导致的安全漏洞，请考虑在核心 JVM 层面使用通用序列化过滤机制：

    • 过滤传入的序列化数据。

    • JEP 290。

    • OWASP：不可信数据的反序列化漏洞。
