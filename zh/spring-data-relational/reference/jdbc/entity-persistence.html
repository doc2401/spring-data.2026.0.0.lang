    持久实体

    可以使用 `CrudRepository.save(…)` 方法保存聚合。如果该聚合是新的，这将导致为聚合根执行一条插入语句，随后为所有直接引用或间接引用的实体执行插入语句。

    如果聚合根不是新的，所有引用的实体将被删除，聚合根会被更新，然后所有引用的实体将再次被插入。 请注意，一个实例是否为新实例是其状态的一部分。

    这种方法存在一些明显的缺点。如果只有少数被引用的实体实际发生了变更，那么执行删除和插入操作就是浪费资源。虽然这一过程可以并且很可能得到改进，但 Spring Data JDBC 所提供的功能确实存在某些局限性。它无法知晓聚合体的先前状态。因此，任何更新过程都必须从数据库中读取现有数据，并将其转换为传递给 save 方法的实体的当前状态。

    另请参阅实体状态检测以获取更多信息。

    加载聚合

    Spring Data JDBC 提供了两种加载聚合体的方式：

    1. 传统方式以及在 3.2 版本之前的唯一方法非常简单： 每个查询都会加载聚合根，无论该查询是基于 `CrudRepository` 方法、推导式查询还是注解式查询。 如果聚合根引用了其他实体，这些实体将通过单独的语句进行加载。

    2. Spring Data JDBC 3.2 支持使用单查询加载。 通过此功能，可以使用单个 SQL 查询完全加载任意数量的聚合对象。 这对于由许多实体组成的复杂聚合而言，效率应显著提高。

      目前，单次查询加载受到多种方式的限制：

      1. 聚合对象不能包含嵌套集合，这包括Map。 未来的计划是移除这一限制。

      2. 聚合体不得使用AggregateReference或嵌入实体。 未来计划移除此限制。

      3. 数据库方言必须支持该功能。Spring Data JDBC 提供的所有方言中，除 H2 和 HSQL 外均支持此功能。H2 和 HSQL 不支持分析函数（也称为窗口函数）。

      4. 它仅适用于 `CrudRepository`中的查找方法，不适用于派生查询和注解查询。 未来计划移除这一限制。

      5. 需要在JdbcMappingContext中启用单查询加载，通过调用setSingleQueryLoadingEnabled(true)实现。

    如果任何条件未满足，Spring Data JDBC 将回退到加载聚合的默认方法。

    单查询加载功能目前仍处于实验阶段。 我们非常欢迎用户反馈该功能的使用体验。
    虽然单查询加载可以缩写为 SQL，但我们强烈不建议这样做，因为这几乎肯定会与结构化查询语言（Structured Query Language）产生混淆。

    主键生成

    Spring Data 使用标识符属性来识别实体。也就是说，用于查找或创建针对特定行的语句。实体的 ID 必须使用 Spring Data 的 @Id 注解进行标注。

    当数据库的 ID 列具有自增属性时，在将实体插入数据库后，生成的值会被设置到该实体中。

    如果额外使用 @Sequence 注解标识符属性，则当底层 Dialect 支持序列时，将使用数据库序列来获取 id 的值。

    否则，如果实体是新的且标识符字段的值默认为其初始值，Spring Data 将不会尝试插入这些标识符列的值。也就是说，对于基本类型，该值为0；如果标识符属性使用的是数值包装类型（如Long），则该值为null。

    实体状态检测详细解释了检测实体是新实体还是预期存在于数据库中的策略。

    一个重要的约束是，在保存实体后，该实体不能再是新实体。 请注意，实体是否为新实体是其状态的一部分。 在使用自增列时，这一过程会自动完成，因为 Spring Data 会从 ID 列中获取值来设置 ID。

    模板 API

    作为存储库的替代方案，Spring Data JDBC 提供了 JdbcAggregateTemplate，作为一种更直接的方式来在关系型数据库中加载和持久化实体。 在很大程度上，存储库使用 JdbcAggregateTemplate 来实现其功能。

    本节仅突出显示JdbcAggregateTemplate中最有趣的部分。 如需更全面的概览，请参阅JdbcAggregateTemplate的JavaDoc。

    访问 JdbcAggregateTemplate

    JdbcAggregateTemplate 旨在作为 Spring Bean 使用。 如果您已将应用程序配置为包含 Spring Data JDBC，则可以在任何 Spring Bean 中配置对 JdbcAggregateTemplate 的依赖，Spring Framework 将注入一个已正确配置的实例。

    这包括您用于为 Spring Data 存储库实现自定义方法的片段，使您可以使用JdbcAggregateTemplate来定制和扩展您的存储库。

    Persisting

    JdbcAggregateTemplate 提供了三种用于持久化实体的方法：`save`、`insert`和`update`。每种方法都有两种形式：一种是针对单个聚合的操作，名称与上述完全一致；另一种是针对 `Iterable` 的带有 `All` 后缀的操作。

    save 与仓储中同名方法的功能相同。

    `insert` 和 `update` 会跳过新实体的测试，并根据其名称假设聚合是新的还是已存在的。

    Upsert

    JdbcAggregateTemplate 提供了一个 upsert(instance) 操作，用于在无需预先检查是否存在的情况下，以单次数据库往返操作持久化聚合根。该操作执行原生数据库的“插入或更新”：当不存在与关联主键匹配的现有行时插入该行，否则则更新它。

    请注意，此操作要求实体实例具有标识符值。此外，还需要支持相应的数据库方言：该功能适用于 PostgreSQL、H2、MySQL、MariaDB、SQL Server、Oracle、DB2 和 HSQLDB。

    目前，Upserts 不支持乐观锁。

    Querying

    JdbcAggregateTemplate 提供了大量用于查询聚合以及聚合集合的方法。其中有一类方法需要特别关注，即接受 Query 作为参数的方法。这些方法允许执行通过编程方式构建的查询，如下所示：

    template.findOne(query(where("name").is("Gandalf")), Person.class);

    由 `query` 方法返回的 `Query` 定义了要选择的列列表、WHERE 子句（通过 CriteriaDefinition）以及 LIMIT 和 OFFSET 子句的规范。有关 `Query` 类的详细信息，请参阅其 JavaDoc。

    `Criteria` 类（其包含一个静态成员 `where`）提供了 `org.springframework.data.relational.core.query.CriteriaDefinition[]` 的实现，这些实现代表了查询的 WHERE 子句。

    Criteria 类的方法

    `Criteria` 类提供以下方法，它们均对应于 SQL 运算符：

    • Criteria and (String column)：将具有指定 property 的链式 Criteria 添加到当前 Criteria，并返回新创建的实例。

    • Criteria 或 (String column)：向当前 Criteria 添加一个带有指定 property 的链式 Criteria，并返回新创建的实例。

    • Criteria greaterThan (Object o)：使用 > 运算符创建条件。

    • Criteria greaterThanOrEquals (Object o)：使用 >= 运算符创建条件。

    • Criteria in (Object…​ o)：使用 IN 运算符为可变参数创建条件。

    • Criteria in (Collection<?> collection)：使用集合通过 IN 运算符创建条件。

    • Criteria 是 (Object o)：通过使用列匹配（property = value）创建标准。

    • Criteria isNull ()：使用 IS NULL 运算符创建条件。

    • Criteria isNotNull ()：使用 IS NOT NULL 运算符创建条件。

    • Criteria lessThan (Object o)：使用 < 运算符创建条件。

    • Criteria lessThanOrEquals (Object o)：使用 ⇐ 运算符创建条件。

    • Criteria like (Object o)：使用 LIKE 运算符创建条件，且不进行转义字符处理。

    • Criteria not (Object o)：通过使用 != 运算符创建条件。

    • Criteria notIn (Object…​ o)：使用 NOT IN 运算符为变长参数创建条件。

    • Criteria notIn (Collection<?> collection)：使用集合创建基于 NOT IN 操作符的条件。

    乐观锁

    Spring Data 通过在聚合根上标注带有 @Version 的数值属性来支持乐观锁。每当 Spring Data 保存具有此类版本属性的聚合时，会发生以下两件事：

    • 聚合根的更新语句将包含一个 WHERE 子句，用于检查数据库中存储的版本号是否确实未发生变化。

    • 如果并非如此，将抛出OptimisticLockingFailureException异常。

    此外，实体和数据库中的版本号属性都会增加，因此并发操作会检测到该变更，并在适用时抛出上述描述的OptimisticLockingFailureException异常。

    该过程同样适用于插入新聚合体，其中 `null` 或 `0` 版本表示一个新实例，随后递增的实例标记则表明该实例不再为新，这使得该方法在处理 ID 在对象构建期间生成的情况（例如使用 UUID 时）尤为有效。

    删除期间同样适用版本检查，但版本号不会增加。
