    • 投影

    Projections

    Spring Data 查询方法通常返回由仓储管理的聚合根的一个或多个实例。 然而，有时可能希望基于这些类型的某些属性创建投影。 Spring Data 允许建模专用的返回类型，以更选择性地检索受管聚合的部分视图。

    想象一个仓储和聚合根类型，如下例所示：

    示例聚合与仓储
    class Person {

  @Id UUID id;
  String firstname, lastname;
  Address address;

  static class Address {
    String zipCode, city, street;
  }
}

interface PersonRepository extends Repository<Person, UUID> {

  Collection<Person> findByLastname(String lastname);
}

    现在，假设我们只想检索人员的姓名属性。Spring Data 提供了什么手段来实现这一点？本章的其余部分将回答这个问题。

    投影类型是位于实体类型层次结构之外的类型。 实体所继承的超类和实现的接口均位于该类型层次结构内部，因此返回一个超类型（或已实现的接口）时，将返回完全实例化实体的实例。

    基于接口的投影

    将查询结果限制为仅包含名称属性的最简单方法是声明一个接口，该接口提供用于读取所需属性的访问器方法，如下例所示：

    用于检索属性子集的投影接口
    interface NamesOnly {

  String getFirstname();
  String getLastname();
}

    关键在于此处定义的属性必须与聚合根中的属性完全匹配。 这样做可以添加如下查询方法：

    使用基于接口的投影和查询方法的存储库
    interface PersonRepository extends Repository<Person, UUID> {

  Collection<NamesOnly> findByLastname(String lastname);
}

    查询执行引擎会在运行时为每个返回的元素创建该接口的代理实例，并将调用转发到目标对象的公开方法。

    在您的 `Repository` 中声明一个覆盖基类方法（例如在 `CrudRepository`、特定存储库接口或 `Simple…Repository` 中声明的方法）时，无论声明的返回类型如何，都会调用基类方法。请确保使用兼容的返回类型，因为基类方法不能用于投影。某些存储模块支持 `@Query` 注解，可以将覆盖的基类方法转换为查询方法，从而能够返回投影。

    投影可以递归使用。 如果您也想包含部分 `Address` 信息，请为此创建一个投影接口，并从 `getAddress()` 的声明中返回该接口，如下例所示：

    用于检索属性子集的投影接口
    interface PersonSummary {

  String getFirstname();
  String getLastname();
  AddressSummary getAddress();

  interface AddressSummary {
    String getCity();
  }
}

    在方法调用时，获取目标实例的address属性，并将其包装为投影代理。

    封闭投影

    如果一个投影接口的所有访问器方法都匹配目标聚合的属性，则该投影被视为封闭投影。以下示例（我们在本章之前也使用过）就是一个封闭投影：

    闭投影
    interface NamesOnly {

  String getFirstname();
  String getLastname();
}

    如果使用封闭投影，Spring Data 可以优化查询执行，因为我们知道所有用于支持投影代理的属性。有关该主题的更多详细信息，请参阅参考文档中特定模块的部分。

    开放投影

    投影接口中的访问器方法也可以使用@Value注解来计算新值，如下例所示：

    开放式投影
    interface NamesOnly {

  @Value("#{target.firstname + ' ' + target.lastname}")
  String getFullName();
  …
}

    支持该投影的聚合根在 `target` 变量中可用。 使用 `@Value` 的投影接口是一个开放投影。 在这种情况下，Spring Data 无法应用查询执行优化，因为 SpEL 表达式可能会使用聚合根的任意属性。

    `@Value`注解中使用的表达式不应过于复杂——应避免在`String`变量中进行编程。 对于非常简单的表达式，一种选择是使用默认方法（Java 8 引入），如下例所示：

    使用默认方法的自定义逻辑投影接口
    interface NamesOnly {

  String getFirstname();
  String getLastname();

  default String getFullName() {
    return getFirstname().concat(" ").concat(getLastname());
  }
}

    这种方法要求您能够仅基于投影接口上公开的其他访问器方法来实现逻辑。 另一种更灵活的选项是在 Spring Bean 中实现自定义逻辑，然后从 SpEL 表达式中调用该 Bean，如下例所示：

    示例人员对象
    @Component
class MyBean {

  String getFullName(Person person) {
    …
  }
}

interface NamesOnly {

  @Value("#{@myBean.getFullName(target)}")
  String getFullName();
  …
}

    注意 SpEL 表达式如何引用 `myBean` 并调用 `getFullName(…)` 方法，同时将投影目标作为方法参数传递。 由 SpEL 表达式评估支持的方法也可以使用方法参数，这些参数可以在表达式中被引用。 方法参数可通过一个名为 `args` 的 `Object` 数组访问。 以下示例展示了如何从 `args` 数组中获取方法参数：

    示例人员对象
    interface NamesOnly {

  @Value("#{args[0] + ' ' + target.firstname + '!'}")
  String getSalutation(String prefix);
}

    同样，对于更复杂的表达式，您应该使用 Spring Bean，并让表达式调用一个方法，如前面所述。

    可空包装器

    投影接口中的 Getter 可以使用可空包装器来提升空值安全性。 当前支持的包装器类型包括：

    • java.util.Optional

    • com.google.common.base.Optional

    • scala.Option

    • io.vavr.control.Option

    使用可空包装器的投影接口
    interface NamesOnly {

  Optional<String> getFirstname();
}

    如果底层投影值不为null，则使用包装类型的当前表示形式返回该值。 如果底层值为null，则 getter 方法返回所用包装类型的空表示形式。

    基于类的投影（DTO）

    另一种定义投影的方法是使用值类型 DTO（数据传输对象），这些对象包含用于获取字段的属性。 这些 DTO 类型的使用方式与投影接口完全相同，唯一的区别是它们不会发生代理操作，且无法应用嵌套投影。

    如果商店通过限制加载的字段来优化查询执行，则待加载的字段将从所暴露的构造函数参数名称中确定。

    以下示例展示了一个投影 DTO：

    投影数据转移对象
    record NamesOnly(String firstname, String lastname) {
}

    Java 记录类型非常适合定义 DTO 类型，因为它们遵循值语义：所有字段均为 private final，并且会自动生成 equals(…)、hashCode() 和 toString() 方法。 或者，您也可以使用任何定义了所需投影属性的类。

    动态投影

    到目前为止，我们一直使用投影类型作为集合的返回类型或元素类型。 然而，您可能希望在调用时选择要使用的类型（这使其具有动态性）。 若要应用动态投影，请使用查询方法，例如以下示例中所示的方法：

    使用动态投影参数的存储库
    interface PersonRepository extends Repository<Person, UUID> {

  <T> Collection<T> findByLastname(String lastname, Class<T> type);
}

    这样，该方法可用于获取聚合结果本身，或应用投影后的结果，如下例所示：

    使用具有动态投影的存储库
    void someMethod(PersonRepository people) {

  Collection<Person> aggregates =
    people.findByLastname("Matthews", Person.class);

  Collection<NamesOnly> aggregates =
    people.findByLastname("Matthews", NamesOnly.class);
}
    类型为 Class 的查询参数会被检查以确定其是否可作为动态投影参数。如果查询的实际返回类型与 Class 参数的泛型参数类型相同，则匹配的 Class 参数不能在查询或 SpEL 表达式中使用。如果您希望将 Class 参数用作查询参数，请确保使用不同的泛型参数，例如 Class<?>。

    在使用基于类的投影（Class-based projection）时，类型必须声明单个构造函数，以便 Spring Data 能够确定其输入属性。如果类定义了多个构造函数，则无法在不提供进一步提示的情况下使用该类型的 DTO 投影。在这种情况下，请按照以下说明使用 @PersistenceCreator 注解标记所需的构造函数，以便 Spring Data 能够确定要选择的属性：

    public class NamesOnly {

  private final String firstname;
  private final String lastname;

  protected NamesOnly() { }

  @PersistenceCreator
  public NamesOnly(String firstname, String lastname) {
      this.firstname = firstname;
      this.lastname = lastname;
  }

  // ...
}
