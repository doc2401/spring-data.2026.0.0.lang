    覆盖 Spring Data REST 响应处理器

    有时，您可能需要为特定资源编写自定义处理器。 为了充分利用 Spring Data REST 的配置、消息转换器、异常处理等功能，请使用 @RepositoryRestController 注解，而不是标准的 Spring MVC @Controller 或 @RestController。 使用 @RepositoryRestController 注解标注的控制器将从 RepositoryRestConfiguration.setBasePath 中定义的 API 基础路径提供，该路径也被所有其他 RESTful 端点（例如 /api）所使用。 以下示例展示了如何使用 @RepositoryRestController 注解：

    @RepositoryRestController
class ScannerController {

  private final ScannerRepository repository;

  ScannerController(ScannerRepository repository) { (1)
    this.repository = repository;
  }

  @GetMapping(path = "/scanners/search/producers") (2)
  ResponseEntity<?> getProducers() {

    List<String> producers = repository.listProducers(); (3)

    // do some intermediate processing, logging, etc. with the producers

    CollectionModel<String> resources = CollectionModel.of(producers); (4)

    resources.add(linkTo(methodOn(ScannerController.class).getProducers()).withSelfRel()); (5)

    // add other links as needed

    return ResponseEntity.ok(resources); (6)
  }
}
    1 本示例使用构造函数注入。
    2 此处理器将自定义处理方法注册为查询方法资源。
    3 此处理器使用底层存储库获取数据，但在将最终数据集返回给客户端之前会执行某种形式的后处理。
    4 需要将类型为 T 的结果封装在 Spring HATEOAS 的 CollectionModel<T> 对象中以返回集合。EntityModel<T> 或 RepresentationModel<T> 分别适用于单个项目的合适封装。
    5 添加一个指向此确切方法的链接作为 self 链接。
    6 通过使用 Spring MVC 的 ResponseEntity 包装器返回集合，可确保集合被正确封装并以适当的接受类型进行渲染。

    CollectionModel 用于集合，而 EntityModel（或更通用的类 RepresentationModel）则用于单个项目。这些类型可以组合使用。如果您知道集合中每个项目的链接，请使用 CollectionModel<EntityModel<String>>（或者将核心领域类型替换为 String 以外的其他类型）。这样做可以让您同时为每个项目和整个集合组装链接。

    在本示例中，组合路径为 RepositoryRestConfiguration.getBasePath() + /scanners/search/producers。

    获取聚合引用

    对于接收 `PUT` 和 `POST` 请求的自定义控制器，请求体通常包含一个 JSON 文档，该文档使用 URI 来表达对其他资源的引用。 对于 `GET` 请求，这些引用则通过请求参数传递。

    自 Spring Data REST 4.1 起，我们提供了AggregateReference<T, ID>，可用作处理程序方法参数类型，以捕获此类引用并将其解析为所引用聚合的标识符、聚合本身或 jMoleculesAssociation。 您只需声明一个该类型的@RequestParam，然后即可消费标识符或完全解析后的聚合。

    @RepositoryRestController
class ScannerController {

  private final ScannerRepository repository;

  ScannerController(ScannerRepository repository) {
    this.repository = repository;
  }

  @GetMapping(path = "/scanners")
  ResponseEntity<?> getProducers(
    @RequestParam AggregateReference<Producer, ProducerIdentifier> producer) {

    var identifier = producer.resolveRequiredId();
    // Alternatively
    var aggregate = producer.resolveRequiredAggregate();
  }

  // Alternatively

  @GetMapping(path = "/scanners")
  ResponseEntity<?> getProducers(
    @RequestParam AssociationAggregateReference<Producer, ProducerIdentifier> producer) {

    var association = producer.resolveRequiredAssociation();
  }
}

    如果您正在使用 jMolecules，AssociationAggregateReference 同样允许您获取一个 Association。虽然这两种抽象都假设参数的值为与 Spring Data REST 用于公开项目资源的方案相匹配的 URI，但您可以通过在引用实例上调用 ….withIdSource(…) 来自定义该源值解析过程，从而提供一个函数，从接收到的 URI 所获得的 UriComponents 中提取最终用于聚合解析的标识符值。

    @RepositoryRestController VS. @BasePathAwareController

    如果您不关心特定实体的操作，但仍希望在 basePath 下方构建自定义操作（例如 Spring MVC 视图、资源等），请使用 @BasePathAwareController。 如果在您的自定义控制器上使用 @RepositoryRestController，则仅当您的请求映射与存储库使用的 URI 空间相融合时，该控制器才会处理请求。 此外，它还将为控制器方法应用以下额外功能：

    1. 根据请求映射中处理器方法所使用的基路径段，按照为存储库定义的 CORS 配置进行设置。

    2. 如果使用 JPA，请应用OpenEntityManagerInViewInterceptor，以确保可以访问标记为延迟解析的属性。

    如果您使用 @Controller 或 @RestController，那么该代码完全不在 Spring Data REST 的范围内。这同样适用于请求处理、消息转换器、异常处理以及其他用途。
