    仓库资源

    Fundamentals

    Spring Data REST 的核心功能是为 Spring Data 仓库导出资源。因此，需要关注并可能自定义导出方式的核心理念是仓库接口。考虑以下仓库接口：

    public interface OrderRepository extends CrudRepository<Order, Long> { }

    在此仓库中，Spring Data REST 在路径 `/orders` 处暴露集合资源。该路径是根据所管理的域类的未大写、复数化、简单类名推导得出的。此外，它还在 URI 模板 `/orders/{id}` 下为存储库管理的每个项目暴露一个项目资源。

    默认情况下，与这些资源交互的 HTTP 方法会映射到CrudRepository的相应方法。有关该主题的更多信息，请参阅集合资源和项资源部分。

    仓库方法暴露

    哪些 HTTP 资源对某个仓库可见，主要取决于该仓库的结构。换句话说，资源暴露将遵循您在仓库上公开的方法。如果您扩展了 CrudRepository，通常会暴露所有默认可注册的 HTTP 资源所需的方法。下面列出的每种资源都将定义需要存在哪些方法，以便为每种资源暴露特定的 HTTP 方法。这意味着，如果仓库未公开这些方法——无论是完全不声明它们，还是显式使用 @RestResource(exported = false)——那么这些仓库就不会在这些资源上暴露相应的 HTTP 方法。

    有关如何调整默认方法暴露或单独配置专用 HTTP 方法的详细信息，请参阅自定义支持的 HTTP 方法。

    默认状态码

    对于暴露的资源，我们使用一组默认的状态码：

    • 200 OK：针对普通 GET 请求。

    • 201 Created：表示通过 POST 和 PUT 请求成功创建了新资源。

    • 204 无内容：当配置设置为不返回资源更新的响应体时（RepositoryRestConfiguration.setReturnBodyOnUpdate(…)），针对 PUT、PATCH 和 DELETE 请求会返回此状态码。 如果配置值设置为包含响应，则对更新操作返回 200 OK，而对通过 PUT 创建的资源返回 201 Created。

    如果配置值（RepositoryRestConfiguration.returnBodyOnUpdate(…) 和 RepositoryRestConfiguration.returnBodyCreate(…)）被显式设置为 null——这也就是它们的默认值——那么将使用 HTTP Accept 头的存在与否来确定响应代码。 有关此内容的更多详细信息，请参阅集合资源和项目资源的详细描述。

    资源可发现性

    HATEOAS 的核心原则是，资源应通过发布指向可用资源的链接来实现可发现性。在 JSON 中表示链接方面存在几种相互竞争的既定事实标准。默认情况下，Spring Data REST 使用 HAL 来渲染响应。HAL 定义这些链接应包含在返回文档的属性中。

    资源发现从应用程序的顶层开始。通过向部署 Spring Data REST 应用程序的根 URL 发出请求，客户端可以从返回的 JSON 对象中提取一组链接，这些链接代表了可供客户端访问的下一级资源。

    例如，若要发现应用程序根目录中可用的资源，请向根 URL 发出 HTTP GET 请求，如下所示：

    curl -v http://localhost:8080/

< HTTP/1.1 200 OK
< Content-Type: application/hal+json

{ "_links" : {
    "orders" : {
      "href" : "http://localhost:8080/orders"
    },
    "profile" : {
      "href" : "http://localhost:8080/api/alps"
    }
  }
}

    结果文档的属性是一个对象，其键表示关系类型，嵌套的链接对象遵循 HAL 规范。

    有关 profile 链接的更多详细信息，请参阅应用级配置文件语义 (ALPS)。

    集合资源

    Spring Data REST 会暴露一个集合资源，其名称为导出仓库所处理的领域类的非首字母大写复数形式。可以通过在仓库接口上使用 `@RepositoryRestResource` 来自定义该资源的名称和路径。

    支持的 HTTP 方法

    集合资源同时支持GET和POST。所有其他HTTP方法将导致返回405 Method Not Allowed错误。

    GET

    返回存储库服务器通过其 `findAll(…)` 方法检索到的所有实体。如果该存储库是分页存储库，则在必要时包含分页链接以及额外的页面元数据。

    用于调用的方法

    若存在以下方法，则按降序使用：

    • findAll(Pageable)

    • findAll(Sort)

    • findAll()

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    Parameters

    如果存储库具有分页功能，该资源将采用以下参数：

    • page：要访问的页码（从 0 开始计数，默认为 0）。

    • size：请求的每页大小（默认为 20）。

    • sort：一组排序指令，格式为 ($propertyname,)+[asc|desc]。

    自定义状态码

    `GET` 方法仅有一个自定义状态码：

    • 405 方法不允许：如果未导出 findAll(…) 方法（通过 @RestResource(exported = false)）或仓库中不存在这些方法。

    支持的媒体类型

    GET 方法支持以下媒体类型：

    • application/hal+json

    • application/json

    相关资源

    `GET` 方法支持用于发现相关资源的单个链接：

    • search：如果底层仓库暴露了查询方法，则会公开一个搜索资源。

    HEAD

    `HEAD` 方法返回集合资源是否可用。它没有状态码、媒体类型或相关资源。

    调用方法

    若存在以下方法，则按降序使用：

    • findAll(Pageable)

    • findAll(Sort)

    • findAll()

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    POST

    `POST` 方法根据给定的请求体创建新实体。 默认情况下，响应是否包含正文由随请求发送的 `Accept` 头控制。 如果发送了该头，则创建响应正文；否则，响应正文为空，可通过遵循 `Location` 响应头中包含的链接来获取所创建资源的表示形式。 此行为可以通过相应配置 `RepositoryRestConfiguration.setReturnBodyOnCreate(…)` 进行覆盖。

    调用方法

    若存在以下方法，则按降序使用：

    • save(…)

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    自定义状态码

    `POST` 方法仅有一个自定义状态码：

    • 405 方法不允许：如果未导出save(…)方法（通过@RestResource(exported = false)）或仓库中根本不存在该方法。

    支持的媒体类型

    POST 方法支持以下媒体类型：

    • application/hal+json

    • application/json

    项目资源

    Spring Data REST 将集合中单个项目的资源作为子资源暴露出来，隶属于集合资源。

    支持的 HTTP 方法

    项目资源通常支持 `GET`、`PUT`、`PATCH` 和 `DELETE`，除非显式配置阻止了这些操作（详见"关联资源"以获取详细信息）。

    GET

    `GET` 方法返回单个实体。

    调用方法

    若存在以下方法，则按降序使用：

    • findById(…)

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    自定义状态码

    `GET` 方法仅有一个自定义状态码：

    • 405 方法不允许：如果 findOne(…) 方法未导出（通过 @RestResource(exported = false)）或不在仓库中存在。

    支持的媒体类型

    GET 方法支持以下媒体类型：

    • application/hal+json

    • application/json

    相关资源

    对于每种域类型关联，我们都会暴露以关联属性命名的链接。您可以通过在属性上使用 `@RestResource` 来自定义此行为。相关资源属于关联资源类型。

    HEAD

    `HEAD` 方法返回项目资源是否可用。它没有状态码、媒体类型或相关资源。

    调用方法

    若存在以下方法，则按降序使用：

    • findById(…)

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    PUT

    `PUT` 方法将目标资源的状态替换为请求体中提供的数据。 默认情况下，响应是否包含正文由随请求发送的 `Accept` 头控制。 如果存在该请求头，则返回响应正文和状态码 `200 OK`。 如果不存在该请求头，则响应正文为空，成功请求将返回状态码 `204 No Content`。 可以通过相应配置 `RepositoryRestConfiguration.setReturnBodyOnUpdate(…)` 来覆盖此行为。

    调用方法

    若存在以下方法，则按降序使用：

    • save(…)

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    自定义状态码

    `PUT` 方法仅有一个自定义状态码：

    • 405 方法不允许：如果未导出 save(…) 方法（通过 @RestResource(exported = false)）或该仓库中根本不存在此方法。

    支持的媒体类型

    `PUT` 方法支持以下媒体类型：

    • application/hal+json

    • application/json

    PATCH

    `PATCH` 方法与 `PUT` 方法类似，但仅部分更新资源的状态。

    调用方法

    若存在以下方法，则按降序使用：

    • save(…)

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    自定义状态码

    方法仅有一个自定义状态码：

    • 405 方法不允许：如果未导出（通过 @RestResource(exported = false)）save(…) 方法，或者该仓库中不存在这些方法。

    支持的媒体类型

    方法支持以下媒体类型：

    • application/hal+json

    • application/json

    • application/patch+json

    • application/merge-patch+json

    DELETE

    `DELETE` 方法用于删除所暴露的资源。 默认情况下，响应是否包含正文由请求中发送的 `Accept` 头控制。 如果存在该请求头，则返回响应正文以及状态码 `200 OK`。 如果不存在该头，则响应正文为空，成功请求将返回状态码 `204 No Content`。 可以通过相应配置 `RepositoryRestConfiguration.setReturnBodyOnDelete(…)` 来覆盖此行为。

    用于调用的方法

    若存在以下方法，则按降序使用：

    • delete(T)

    • delete(ID)

    • delete(Iterable)

    有关方法默认暴露的更多信息，请参阅仓库方法暴露。

    自定义状态码

    `DELETE` 方法仅有一个自定义状态码：

    • 405 方法不允许：如果未导出（通过 @RestResource(exported = false)）delete(…) 方法，或者这些方法在仓库中不存在。

    关联资源

    Spring Data REST 会为每个关联属性暴露对应项资源的子资源。该资源的名称和路径默认与关联属性的名称相同，可以通过在关联属性上使用 `@RestResource` 进行自定义。

    支持的 HTTP 方法

    关联资源支持以下媒体类型：

    • GET

    • PUT

    • POST

    • DELETE

    GET

    `GET` 方法返回关联资源的当前状态。

    支持的媒体类型

    GET 方法支持以下媒体类型：

    • application/hal+json

    • application/json

    PUT

    `PUT` 方法将给定 URI 所指向的资源绑定到关联资源（请参阅支持的媒体类型）。

    自定义状态码

    `PUT` 方法仅有一个自定义状态码：

    • 400 错误请求：当为一对一关联提供了多个 URI 时。

    支持的媒体类型

    `PUT` 方法仅支持一种媒体类型：

    • text/uri-list：指向要与关联绑定的资源的 URI。

    POST

    POST 方法仅支持集合关联。它会在集合中添加一个新元素。

    支持的媒体类型

    `POST` 方法仅支持一种媒体类型：

    • text/uri-list：指向要添加到关联中的资源的 URI。

    DELETE

    `DELETE` 方法解除关联。

    自定义状态码

    `POST` 方法仅有一个自定义状态码：

    • 405 方法不允许：当关联为非可选时。

    搜索资源

    搜索资源返回由仓库暴露的所有查询方法的链接。可以使用方法声明上的 `@RestResource` 修改查询方法资源的路径和名称。

    支持的 HTTP 方法

    由于搜索资源为只读资源，因此仅支持GET方法。

    GET

    GET 方法返回指向各个查询方法资源的链接列表。

    支持的媒体类型

    GET 方法支持以下媒体类型：

    • application/hal+json

    • application/json

    相关资源

    对于仓库中声明的每个查询方法，我们都暴露一个查询方法资源。如果该资源支持分页，则指向它的 URI 是一个包含分页参数的 URI 模板。

    HEAD

    `HEAD` 方法返回搜索资源是否可用。返回代码 404 表示没有可用的查询方法资源。

    查询方法资源

    查询方法资源通过仓储接口上的单个查询方法执行暴露的查询。

    支持的 HTTP 方法

    由于查询方法资源是只读资源，因此仅支持GET。

    GET

    GET 方法返回查询结果。

    Parameters

    如果查询方法具有分页功能（在指向该资源的 URI 模板中有所指示），则该资源将采用以下参数：

    • page：要访问的页码（从 0 开始计数，默认为 0）。

    • size：请求的每页大小（默认为 20）。

    • sort：一组排序指令，格式为 ($propertyname,)+[asc|desc]。

    支持的媒体类型

    GET 方法支持以下媒体类型：

    • application/hal+json

    • application/json

    HEAD

    `HEAD` 方法返回查询方法资源是否可用。
