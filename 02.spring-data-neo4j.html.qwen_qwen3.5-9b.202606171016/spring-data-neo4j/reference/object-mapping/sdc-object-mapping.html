    Spring Data 对象映射基础

    本节涵盖 Spring Data 对象映射、对象创建、字段和属性访问以及可变性与不可变性的基础知识。

    Spring Data 对象映射的核心职责是创建领域对象实例，并将存储原生的数据结构映射到这些对象上。 这意味着我们需要两个基本步骤：

    1. 通过暴露的构造函数之一创建实例。

    2. 实例化以呈现所有已暴露的属性。

    对象创建

    Spring Data 会自动尝试检测持久化实体中用于实例化该类型对象的构造函数。 解析算法的工作方式如下：

    1. 如果有无参构造函数，将使用它。 其他构造函数将被忽略。

    2. 如果存在一个接受参数的构造函数，它将使用该构造函数。

    3. 如果存在多个带参数的构造函数，Spring Data 将使用的构造函数必须标注为@PersistenceCreator。

    值解析假设构造函数参数名称与实体的属性名称相匹配，即解析过程将如同填充该属性一样执行，包括所有映射自定义（如不同的数据存储列或字段名等）。 此外，还要求类文件中提供参数名称信息，或者在构造函数上存在 `@ConstructorProperties` 注解。

    对象创建的内部机制

    为避免反射带来的开销，Spring Data 默认使用在运行时生成的工厂类来创建对象，该工厂类将直接调用领域类的构造函数。 即对于此示例类型：

    class Person {
  Person(String firstname, String lastname) { … }
}

    我们将在运行时创建一个语义上与此工厂类等效的工厂类：

    class PersonObjectInstantiator implements ObjectInstantiator {

  Object newInstance(Object... args) {
    return new Person((String) args[0], (String) args[1]);
  }
}

    这为我们带来了比反射间接高出约 10% 的性能提升。 要使领域类符合此类优化的条件，它需要遵守一组约束：

    • 它不能是私有类。

    • 它不能是非静态内部类。

    • 它不能是 CGLib 代理类。

    • Spring Data 所使用的构造函数不能是私有的。

    如果满足上述任一条件，Spring Data 将回退到通过反射进行实体实例化。

    属性集

    一旦创建了该实体的实例，Spring Data 会填充该类中所有剩余的持久化属性。 除非这些属性已由实体构造函数填充（即通过构造函数参数列表传入），否则标识符属性将被首先填充，以便解析循环对象引用。 随后，所有未被构造函数填充的非瞬态属性将被设置到实体实例上。 为此，我们采用以下算法：

    1. 如果属性是不可变的但暴露了 wither 方法（见下文），我们使用 wither 来创建一个具有新属性值的新实体实例。

    2. 如果定义了属性访问（即通过 getter 和 setter 进行访问），我们将调用 setter 方法。

    3. 默认情况下，我们直接设置字段值。

    属性人口内部结构

    与我们在对象构建优化中采用的方式类似，我们也使用 Spring Data 运行时生成的访问器类来与实体实例进行交互。

    class Person {

  private final Long id;
  private String firstname;
  private @AccessType(Type.PROPERTY) String lastname;

  Person() {
    this.id = null;
  }

  Person(Long id, String firstname, String lastname) {
    // Field assignments
  }

  Person withId(Long id) {
    return new Person(id, this.firstname, this.lastame);
  }

  void setLastname(String lastname) {
    this.lastname = lastname;
  }
}
    示例 1。生成的属性访问器
    class PersonPropertyAccessor implements PersistentPropertyAccessor {

  private static final MethodHandle firstname;              (2)

  private Person person;                                    (1)

  public void setProperty(PersistentProperty property, Object value) {

    String name = property.getName();

    if ("firstname".equals(name)) {
      firstname.invoke(person, (String) value);             (2)
    } else if ("id".equals(name)) {
      this.person = person.withId((Long) value);            (3)
    } else if ("lastname".equals(name)) {
      this.person.setLastname((String) value);              (4)
    }
  }
}
    1 PropertyAccessor 持有底层对象的可变实例。这是为了能够修改原本不可变的属性。
    2 默认情况下，Spring Data 使用字段访问方式来读写属性值。根据 private 字段的可见性规则，使用 MethodHandles 与字段进行交互。
    3 该类提供了一个 withId(…) 方法，用于设置标识符，例如当实例被插入数据存储且已生成标识符时。调用 withId(…) 会创建一个新的 Vertex 对象。随后的所有修改都将在新实例中进行，而不会改变之前的实例。
    4 使用属性访问允许直接调用方法，而无需使用 MethodHandles。

    这使我们获得了比反射间接高出约 25% 的性能提升。 要使领域类符合此类优化的条件，它必须遵守一组约束：

    • 类型不得位于默认包或java包下。

    • 类型及其构造函数必须是public的。

    • 作为内部类的类型，必须是static的。

    • 所使用的 Java 运行时必须允许在源 `ClassLoader` 中声明类。 Java 9 及更高版本施加了某些限制。

    默认情况下，Spring Data 会尝试使用生成的属性访问器；如果检测到限制，则回退到基于反射的访问器。

    让我们看看以下实体：

    示例 2。一个示例实体
    class Person {

  private final @Id Long id;                                                (1)
  private final String firstname, lastname;                                 (2)
  private final LocalDate birthday;
  private final int age; (3)

  private String comment;                                                   (4)
  private @AccessType(Type.PROPERTY) String remarks;                        (5)

  static Person of(String firstname, String lastname, LocalDate birthday) { (6)

    return new Person(null, firstname, lastname, birthday,
      Period.between(birthday, LocalDate.now()).getYears());
  }

  Person(Long id, String firstname, String lastname, LocalDate birthday, int age) { (6)

    this.id = id;
    this.firstname = firstname;
    this.lastname = lastname;
    this.birthday = birthday;
    this.age = age;
  }

  Person withId(Long id) {                                                  (1)
    return new Person(id, this.firstname, this.lastname, this.birthday);
  }

  void setRemarks(String remarks) {                                         (5)
    this.remarks = remarks;
  }
}
    1 标识符属性为 final 类型，但在构造函数中被设置为 null。该类提供了一个 withId(…) 方法用于设置标识符，例如当实例被插入数据存储且已生成标识符时。原始的 Vertex 实例保持不变，因为会创建一个新的实例。通常对其他由存储管理的属性也采用相同的模式，但在持久化操作中可能需要对此进行调整。
    2 firstname 和 lastname 属性是普通的不可变属性，可能通过 getter 方法暴露。
    3 age 属性是不可变的派生属性，源自 birthday 属性。按照所示的设计，数据库值将优先于默认值，因为 Spring Data 仅使用声明的构造函数。即使意图是优先采用计算结果，也重要的是该构造函数必须包含 age 作为参数（以便潜在地忽略它）；否则，属性填充步骤将尝试设置 age 字段，但由于其不可变且不存在 wither 方法而失败。
    4 comment 属性是可变的，通过直接设置其字段进行填充。
    5 remarks 属性是可变的，可以通过直接设置 comment 字段或调用 setter 方法进行填充。
    6 该类提供了一个工厂方法和一个构造函数用于对象创建。这里的核心思想是使用工厂方法而不是额外的构造函数，以避免通过 @PersistenceCreator 进行构造函数消歧的需要。相反，属性的默认值处理在工厂方法内部完成。

    一般建议

    • 尽量使用不可变对象——创建不可变对象非常简单，只需调用其构造函数即可完成对象的实例化。此外，这还能防止你的领域对象充斥着允许客户端代码操纵对象状态的 setter 方法。如果确实需要这些方法，建议将其设为包级私有（package protected），以便仅由有限的同包类型调用。仅通过构造函数进行对象实例化的速度比属性填充快高达 30%。

    • 提供一个全参构造函数——即使您无法或不愿将实体建模为不可变值，提供接受实体所有属性（包括可变属性）作为参数的构造函数仍然具有价值，因为这允许对象映射跳过属性填充过程，从而实现最佳性能。

    • 使用工厂方法替代重载构造函数，以避免使用 @PersistenceCreator——由于全参构造函数对于最佳性能是必需的，我们通常希望暴露更多针对特定应用场景的构造函数，这些构造函数会省略诸如自动生成的标识符等内容。采用静态工厂方法来暴露全参构造函数的各种变体，是一种成熟的模式。

    • 请确保遵守相关约束条件，以便生成的实例化器和属性访问器类能够正常使用。

    • 若要生成标识符，仍需使用最终字段并结合 wither 方法

    • 使用 Lombok 避免样板代码——由于持久化操作通常需要包含所有参数的构造函数，其声明往往沦为繁琐的样板式参数到字段赋值重复工作，而使用 Lombok 的 @AllArgsConstructor 可最佳地避免此类问题。

    关于不可变映射的说明

    尽管我们建议尽可能使用不可变映射和构建方式，但在映射方面仍存在某些限制。 假设存在一个双向关系：其中 A 对 B 拥有构造函数引用，而 B 又对 A 拥有引用；或者场景更为复杂。 这种“先有鸡还是先有蛋”的困境对于 Spring Data Neo4j 而言是无法解决的。 在实例化 A 时，它急切地需要一个完全实例化的 B，而另一方面，B 又需要一个实例（更准确地说，是同一个 A 的实例）。 SDN 通常允许此类模型，但如果从数据库返回的数据包含上述描述的结构，则会在运行时抛出 MappingException。 在无法预知返回数据具体形态的情况下或场景中，使用可变字段来表示关系更为合适。

    Kotlin 支持

    Spring Data 适配了 Kotlin 的具体特性，以支持对象的创建和修改。

    Kotlin 对象创建

    Kotlin 支持实例化类，所有类默认不可变，若要定义可变属性则需显式声明。 考虑以下 `` data` 类 `` Vertex`：

    data class Person(val id: String, val name: String)

    上述类编译为具有显式构造函数的典型类。我们可以通过添加另一个构造函数并用@PersistenceCreator注解它来指定构造函数偏好，从而自定义该类：

    data class Person(var id: String, val name: String) {

    @PersistenceCreator
    constructor(id: String) : this(id, "unknown")
}

    Kotlin 支持通过为参数提供默认值来实现参数的可选性。当 Spring Data 检测到具有参数默认值的构造函数时，如果数据存储未提供相应值（或简单地返回 null），则这些参数将保持缺失状态，以便 Kotlin 应用参数默认值机制。考虑以下对 name 参数应用默认值的类：

    data class Person(var id: String, val name: String = "unknown")

    每次 `name` 参数不在结果中或其值为 `null` 时，`name` 默认为 `unknown`。

    Kotlin 数据类的属性填充

    在 Kotlin 中，所有类默认都是不可变的，若要定义可变属性，则需显式声明。 考虑以下 data 类 Vertex：

    data class Person(val id: String, val name: String)

    该类实际上是不可变的。它允许创建新实例，因为 Kotlin 会生成一个 `copy(…)` 方法，该方法通过复制现有对象的所有属性值，并将作为参数提供的属性值应用其中，来创建新的对象实例。
