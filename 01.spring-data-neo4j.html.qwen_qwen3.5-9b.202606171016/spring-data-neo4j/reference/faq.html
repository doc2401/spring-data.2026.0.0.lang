    FAQ

    SDN 与 Neo4j-OGM 有何关系？

    Neo4j-OGM 是一个对象图映射库，主要用于旧版 Spring Data Neo4j 作为后端，负责将节点和关系映射到领域对象的繁重工作。 当前的 SDN 不需要 也不支持 Neo4j-OGM。 SDN 仅使用 Spring Data 的映射上下文来扫描类并构建元模型。

    虽然这将 SDN 绑定到 Spring 生态系统，但它具有诸多优势，其中包括更小的 CPU 和内存占用，尤其是拥有 Spring 映射上下文的所有功能。

    为什么我应该使用 SDN 而不是 SDN+OGM？

    SDN 具有若干在 SDN+OGM 中不存在的功能，特别是

    • 全面支持 Spring 响应式栈，包括响应式事务。

    • 完全支持示例查询

    • 完全支持完全不可变实体

    • 支持所有派生查找方法的修饰符和变体，包括空间查询。

    SDN 是否支持通过 HTTP 连接到 Neo4j？

    No.

    SDN 是否支持嵌入式 Neo4j？

    嵌入式 Neo4j 具有多个方面：

    SDN 是否为您的应用程序提供嵌入式实例？

    No.

    SDN 是否直接与嵌入式实例交互？

    否。 嵌入式数据库通常由 org.neo4j.graphdb.GraphDatabaseService 的一个实例表示，且默认不包含 Bolt 连接器。

    然而，SDN 可以与 Neo4j 的测试框架很好地协同工作，该测试框架专为作为真实数据库的直接替换方案而设计。 对 Neo4j 3.5、4.x 和 5.x 测试框架的支持是通过 驱动程序 Spring Boot Starter 实现的。 请查看相应的模块 org.neo4j.driver:neo4j-java-driver-test-harness-spring-boot-autoconfigure。

    可以使用哪个 Neo4j Java 驱动程序，如何使用？

    SDN 依赖 Neo4j Java 驱动。每个 SDN 发布版本均使用与其发布时间点可用的最新 Neo4j 兼容的 Neo4j Java 驱动版本。虽然 Neo4j Java 驱动的补丁版本通常是即插即用的替代品，但 SDN 会确保即使是次要版本也可互换使用；如有必要，它会检查是否存在方法或接口变更。

    因此，您可以使用任何 4.x 版本的 Neo4j Java 驱动与任何 6.x 版本的 SDN 配合使用，以及任何 5.x 版本的 Neo4j 驱动与任何 7.x 版本的 SDN 配合使用。

    Neo4j 4 支持多个数据库——如何使用它们？

    您可以静态配置数据库名称，也可以运行自己的数据库名称提供者。请注意，SDN 不会为您创建数据库。您可以借助 迁移工具 来完成此操作，当然也可以使用一个简单的初始脚本来实现。

    静态配置

    在 Spring Boot 配置中设置要使用的数据库名称，方式如下（当然，该属性同样适用于基于 YML 或环境的配置，并遵循 Spring Boot 的约定）：

    spring.data.neo4j.database = yourDatabase

    配置完成后，所有由 SDN 存储库实例（包括反应式和命令式）以及分别由 `ReactiveNeo4jTemplate` 和 `Neo4jTemplate` 生成的查询都将在数据库 `yourDatabase` 上执行。

    动态配置

    根据 Spring 应用程序的类型，提供一个类型为Neo4jDatabaseNameProvider或ReactiveDatabaseSelectionProvider的 Bean。

    该 Bean 可以使用 Spring 的安全上下文来检索租户。 以下是一个使用 Spring Security 保护的命令式应用程序的工作示例：

    Neo4jConfig.java
    import org.neo4j.springframework.data.core.DatabaseSelection;
import org.neo4j.springframework.data.core.DatabaseSelectionProvider;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContext;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.core.userdetails.User;

@Configuration
public class Neo4jConfig {
	@Bean
	DatabaseSelectionProvider databaseSelectionProvider() {

		return () -> Optional.ofNullable(SecurityContextHolder.getContext())
			.map(SecurityContext::getAuthentication)
			.filter(Authentication::isAuthenticated)
			.map(Authentication::getPrincipal)
			.map(User.class::cast)
			.map(User::getUsername)
			.map(DatabaseSelection::byName)
			.orElseGet(DatabaseSelection::undecided);
	}
}
    请注意，不要将从一个数据库检索到的实体与另一个数据库的实体混淆。 每次新事务都会请求数据库名称，因此在调用之间更改数据库名称时，您可能会得到比预期少或多的实体。 更糟糕的是，您不可避免地会将错误的实体存储到错误的数据库中。

    Spring Boot Neo4j 健康指示器针对的是默认数据库，如何更改它？

    Spring Boot 提供了命令式和响应式两种 Neo4j 健康指示器。 这两种变体均能够检测应用程序上下文中的多个 `org.neo4j.driver.Driver` Bean，并为每个实例提供对整体健康状况的贡献。 然而，Neo4j 驱动程序连接的是服务器，而非该服务器内的特定数据库。 Spring Boot 可以在不使用 Spring Data Neo4j 的情况下配置驱动程序；但由于要使用的数据库信息是与 Spring Data Neo4j 绑定的，因此内置的健康指示器无法获取这些信息。

    在许多部署场景中，这通常不是问题。 但如果配置的数据库用户没有至少对默认数据库的访问权限，健康检查将会失败。

    这可以通过自定义的、能够感知数据库选择的 Neo4j 健康贡献者来缓解。

    祈使变体

    import java.util.Optional;

import org.neo4j.driver.Driver;
import org.neo4j.driver.Result;
import org.neo4j.driver.SessionConfig;
import org.neo4j.driver.summary.DatabaseInfo;
import org.neo4j.driver.summary.ResultSummary;
import org.neo4j.driver.summary.ServerInfo;
import org.springframework.boot.actuate.health.AbstractHealthIndicator;
import org.springframework.boot.actuate.health.Health;
import org.springframework.data.neo4j.core.DatabaseSelection;
import org.springframework.data.neo4j.core.DatabaseSelectionProvider;
import org.springframework.util.StringUtils;

public class DatabaseSelectionAwareNeo4jHealthIndicator extends AbstractHealthIndicator {

    private final Driver driver;

    private final DatabaseSelectionProvider databaseSelectionProvider;

    public DatabaseSelectionAwareNeo4jHealthIndicator(
        Driver driver, DatabaseSelectionProvider databaseSelectionProvider
    ) {
        this.driver = driver;
        this.databaseSelectionProvider = databaseSelectionProvider;
    }

    @Override
    protected void doHealthCheck(Health.Builder builder) {
        try {
            SessionConfig sessionConfig = Optional
                .ofNullable(databaseSelectionProvider.getDatabaseSelection())
                .filter(databaseSelection -> databaseSelection != DatabaseSelection.undecided())
                .map(DatabaseSelection::getValue)
                .map(v -> SessionConfig.builder().withDatabase(v).build())
                .orElseGet(SessionConfig::defaultConfig);

            class Tuple {
                String edition;
                ResultSummary resultSummary;

                Tuple(String edition, ResultSummary resultSummary) {
                    this.edition = edition;
                    this.resultSummary = resultSummary;
                }
            }

            String query =
                "CALL dbms.components() YIELD name, edition WHERE name = 'Neo4j Kernel' RETURN edition";
            Tuple health = driver.session(sessionConfig)
                .writeTransaction(tx -> {
                    Result result = tx.run(query);
                    String edition = result.single().get("edition").asString();
                    return new Tuple(edition, result.consume());
                });

            addHealthDetails(builder, health.edition, health.resultSummary);
        } catch (Exception ex) {
            builder.down().withException(ex);
        }
    }

    static void addHealthDetails(Health.Builder builder, String edition, ResultSummary resultSummary) {
        ServerInfo serverInfo = resultSummary.server();
        builder.up()
            .withDetail(
                "server", serverInfo.version() + "@" + serverInfo.address())
            .withDetail("edition", edition);
        DatabaseInfo databaseInfo = resultSummary.database();
        if (StringUtils.hasText(databaseInfo.name())) {
            builder.withDetail("database", databaseInfo.name());
        }
    }
}

    响应式变体

    反应式变体基本相同，使用反应式类型和相应的反应式基础设施类：

    import reactor.core.publisher.Mono;
import reactor.util.function.Tuple2;

import org.neo4j.driver.Driver;
import org.neo4j.driver.SessionConfig;
import org.neo4j.driver.reactivestreams.RxResult;
import org.neo4j.driver.reactivestreams.RxSession;
import org.neo4j.driver.summary.DatabaseInfo;
import org.neo4j.driver.summary.ResultSummary;
import org.neo4j.driver.summary.ServerInfo;
import org.reactivestreams.Publisher;
import org.springframework.boot.actuate.health.AbstractReactiveHealthIndicator;
import org.springframework.boot.actuate.health.Health;
import org.springframework.data.neo4j.core.DatabaseSelection;
import org.springframework.data.neo4j.core.ReactiveDatabaseSelectionProvider;
import org.springframework.util.StringUtils;

public final class DatabaseSelectionAwareNeo4jReactiveHealthIndicator
    extends AbstractReactiveHealthIndicator {

    private final Driver driver;

    private final ReactiveDatabaseSelectionProvider databaseSelectionProvider;

    public DatabaseSelectionAwareNeo4jReactiveHealthIndicator(
        Driver driver,
        ReactiveDatabaseSelectionProvider databaseSelectionProvider
    ) {
        this.driver = driver;
        this.databaseSelectionProvider = databaseSelectionProvider;
    }

    @Override
    protected Mono<Health> doHealthCheck(Health.Builder builder) {
        String query =
            "CALL dbms.components() YIELD name, edition WHERE name = 'Neo4j Kernel' RETURN edition";
        return databaseSelectionProvider.getDatabaseSelection()
            .map(databaseSelection -> databaseSelection == DatabaseSelection.undecided() ?
                SessionConfig.defaultConfig() :
                SessionConfig.builder().withDatabase(databaseSelection.getValue()).build()
            )
            .flatMap(sessionConfig ->
                Mono.usingWhen(
                    Mono.fromSupplier(() -> driver.rxSession(sessionConfig)),
                    s -> {
                        Publisher<Tuple2<String, ResultSummary>> f = s.readTransaction(tx -> {
                            RxResult result = tx.run(query);
                            return Mono.from(result.records())
                                .map((record) -> record.get("edition").asString())
                                .zipWhen((edition) -> Mono.from(result.consume()));
                        });
                        return Mono.fromDirect(f);
                    },
                    RxSession::close
                )
            ).map((result) -> {
                addHealthDetails(builder, result.getT1(), result.getT2());
                return builder.build();
            });
    }

    static void addHealthDetails(Health.Builder builder, String edition, ResultSummary resultSummary) {
        ServerInfo serverInfo = resultSummary.server();
        builder.up()
            .withDetail(
                "server", serverInfo.version() + "@" + serverInfo.address())
            .withDetail("edition", edition);
        DatabaseInfo databaseInfo = resultSummary.database();
        if (StringUtils.hasText(databaseInfo.name())) {
            builder.withDetail("database", databaseInfo.name());
        }
    }
}

    Neo4j 4.4 及以上版本支持模拟不同用户——如何使用它们？

    用户模拟在大型多租户环境中尤为引人注目，在这种环境中，一个物理连接（或技术）用户可以代表多个租户。根据您的具体配置，这将大幅减少所需的物理驱动程序实例数量。

    该功能要求服务器端使用 Neo4j Enterprise 4.4 及以上版本，客户端需使用 4.4 及以上版本的驱动程序（org.neo4j.driver:neo4j-java-driver:4.4.0 或更高版本）。

    对于命令式和响应式版本，您分别需要提供 `UserSelectionProvider` 和 `ReactiveUserSelectionProvider`。 相同的实例需要传递给 `Neo4Client` 和 `Neo4jTransactionManager`，以及它们各自的响应式变体。

    在命令式和响应式配置中，您只需提供相应类型的 Bean：

    用户选择提供者 Bean
    import org.springframework.data.neo4j.core.UserSelection;
import org.springframework.data.neo4j.core.UserSelectionProvider;

public class CustomConfig {

    @Bean
    public UserSelectionProvider getUserSelectionProvider() {
        return () -> UserSelection.impersonate("someUser");
    }
}

    在典型的 Spring Boot 场景中，启用此功能需要额外的工作量，因为 Spring Boot 也支持不包含该功能的 SDN 版本。因此，针对用户选择提供者 Bean中的 Bean，您需要完全自定义客户端和事务管理器：

    Spring Boot 所需的自定义配置
    import org.neo4j.driver.Driver;

import org.springframework.data.neo4j.core.DatabaseSelectionProvider;
import org.springframework.data.neo4j.core.Neo4jClient;
import org.springframework.data.neo4j.core.UserSelectionProvider;
import org.springframework.data.neo4j.core.transaction.Neo4jTransactionManager;

import org.springframework.transaction.PlatformTransactionManager;

public class CustomConfig {

    @Bean
    public Neo4jClient neo4jClient(
        Driver driver,
        DatabaseSelectionProvider databaseSelectionProvider,
        UserSelectionProvider userSelectionProvider
    ) {

        return Neo4jClient.with(driver)
            .withDatabaseSelectionProvider(databaseSelectionProvider)
            .withUserSelectionProvider(userSelectionProvider)
            .build();
	}

    @Bean
    public PlatformTransactionManager transactionManager(
        Driver driver,
        DatabaseSelectionProvider databaseSelectionProvider,
        UserSelectionProvider userSelectionProvider
    ) {

        return Neo4jTransactionManager
            .with(driver)
            .withDatabaseSelectionProvider(databaseSelectionProvider)
            .withUserSelectionProvider(userSelectionProvider)
            .build();
	}
}

    使用 Spring Data Neo4j 中的 Neo4j 集群实例

    以下问题同样适用于 Neo4j AuraDB 以及本地部署的 Neo4j 集群实例。

    是否需要特定配置，才能使事务在 Neo4j 因果集群中无缝运行？

    不，您不需要。 SDN 在内部使用 Neo4j 因果集群书签，无需您在侧进行任何配置。 同一线程或同一响应式流中按顺序执行的事务将能够读取其先前更改的值，正如您所预期的那样。

    在 Neo4j 集群中使用只读事务是否重要？

    是的，确实如此。 Neo4j 集群架构采用因果一致性集群架构，并区分主服务器和从服务器。 主服务器可以是单实例或核心实例，两者均可响应读写操作。 写操作会在集群内部从核心实例传播到读副本，更一般地说是从属节点。 这些从属节点即为从服务器。 从服务器不响应写操作。

    在标准的部署场景中，集群内会包含一些核心实例和大量只读副本。因此，将操作或查询标记为只读至关重要，这样可以扩展集群规模，确保主节点不会被压垮，同时尽可能将查询分发到只读副本上。

    Spring Data Neo4j 和底层的 Java 驱动均不执行 Cypher 解析，且这两个构建块默认假设操作为写操作。做出这一决定是为了开箱即用地支持所有操作。如果堆栈中的某个组件默认假设为只读，则可能导致堆栈向只读副本发送写查询，从而在执行时失败。

    所有 findById、findAllById、findAll 以及预定义的生存性方法默认都标记为只读。

    以下是对部分选项的描述：

    将整个仓库设置为只读
    import org.springframework.data.neo4j.repository.Neo4jRepository;
import org.springframework.transaction.annotation.Transactional;

@Transactional(readOnly = true)
interface PersonRepository extends Neo4jRepository<Person, Long> {
}
    将选定的仓库方法设置为只读
    import org.springframework.data.neo4j.repository.Neo4jRepository;
import org.springframework.data.neo4j.repository.query.Query;
import org.springframework.transaction.annotation.Transactional;

interface PersonRepository extends Neo4jRepository<Person, Long> {

  @Transactional(readOnly = true)
  Person findOneByName(String name); (1)

  @Transactional(readOnly = true)
  @Query("""
    CALL apoc.search.nodeAll('{Person: "name",Movie: ["title","tagline"]}','contains','her')
    YIELD node AS n RETURN n""")
  Person findByCustomQuery(); (2)
}
    1 为什么默认不是只读？虽然对于上述派生查找器（我们实际上知道它是只读的）来说这样是可行的，但我们经常看到用户添加自定义的 `@Query` 并通过 `MERGE` 构造来实现它，这当然是一个写操作。 2 自定义过程可以做各种各样的事情，目前我们无法在此处检查它们是只读还是可写。
    从服务编排对存储库的调用。

    @Query 是使用自定义查询的唯一方式吗？

    不，@Query 并非执行自定义查询的唯一方式。 当您的自定义查询能够完整覆盖领域模型时，该注解使用起来非常便捷。 请记住，SDN 假定您映射的领域模型是真理。 这意味着，如果您通过 @Query 执行一个仅部分填充模型的自定义查询，您将面临风险：使用同一个对象将数据写回时，最终可能会擦除或覆盖您在查询中未考虑到的数据。

    因此，请始终使用仓储和声明式方法配合 `@Query` 注解，特别是在结果形状与您的领域模型一致，或您确定不会在写命令中使用部分映射模型的情况下。

        var p2 = node("Person").withProperties("name", parameter("person2"));
        var shortestPath = Cypher.shortestK(1).named("p").definedBy(p1.relationshipBetween(p2).unbounded());
        var p = shortestPath.getRequiredSymbolicName();
        var statement = Cypher.match(shortestPath)
            .with(p, listWith(name("n")).in(Cypher.nodes(shortestPath))
                .where(anyNode().named("n").hasLabels("Movie"))
                .returning()
                .as("mn"))
            .unwind(name("mn"))
            .as("m")
            .with(p, name("m"))
            .match(node("Person").named("d").relationshipTo(anyNode("m"), "DIRECTED").named("r"))
            .returning(p, Cypher.collect(name("r")), Cypher.collect(name("d")))
            .build();

        Map<String, Object> parameters = new HashMap<>();
        parameters.put("person1", from.getName());
        parameters.put("person2", to.getName());
        return this.neo4jTemplate.findAll(statement, parameters, MovieEntity.class); (2)
    }

}

    使用自定义查询和自定义映射

    通常情况下，自定义查询会返回自定义结果。是否应该将所有这些结果都映射为 `@Node`？当然不是！很多时候，这些对象代表的是读操作命令，并不适合作为写操作命令使用。此外，SDN 可能无法或不愿映射所有 Cypher 所能实现的功能。不过，它确实提供了多个钩子来执行您自己的映射逻辑：在 `Neo4jClient` 上。使用 SDN 的 `Neo4jClient` 而非驱动器的优势在于：

    • Neo4jClient 已集成 Spring 的事务管理功能。

    • 它提供了用于绑定参数的流式 API。

    • 它提供了一个流式 API，同时暴露记录数据和 Neo4j 类型系统，使您能够访问结果中的所有数据以执行映射。

import org.neo4j.driver.Driver;
import org.neo4j.driver.Session;
import org.neo4j.driver.summary.SummaryCounters;

class LowlevelInteractionsImpl implements LowlevelInteractions {

    private final Driver driver; (1)

    @Override
    public int deleteGraph() {

        try (Session session = this.driver.session()) {
            SummaryCounters counters = session.executeWrite(tx -> tx.run("MATCH (n) DETACH DELETE n").consume()) (2)
                .counters();
            return counters.nodesDeleted() + counters.relationshipsDeleted();

    }
