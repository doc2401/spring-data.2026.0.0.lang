    自定义查询

    与所有其他 Spring Data 模块一样，Spring Data Neo4j 允许您在仓库中指定自定义查询。当无法通过派生查询函数表达查找逻辑时，这些自定义查询非常有用。

    由于 Spring Data Neo4j 在底层主要采用面向记录的方式工作，因此需要牢记这一点，避免为同一个“根节点”构建包含多条记录的結果集。

    请同时查看常见问题解答，以了解从仓库使用自定义查询的替代形式，特别是如何使用自定义查询配合自定义映射：自定义查询与自定义映射。

    包含关系的查询

    小心笛卡尔积

    假设您有一个查询，例如 `MATCH (m:Movie{title: 'The Matrix'})←[r:ACTED_IN]-(p:Person) return m,r,p`，其结果如下所示：

    多条记录（简化版）
    +------------------------------------------------------------------------------------------+
| m        | r                                    | p                                      |
+------------------------------------------------------------------------------------------+
| (:Movie) | [:ACTED_IN {roles: ["Emil"]}]        | (:Person {name: "Emil Eifrem"})        |
| (:Movie) | [:ACTED_IN {roles: ["Agent Smith"]}] | (:Person {name: "Hugo Weaving})        |
| (:Movie) | [:ACTED_IN {roles: ["Morpheus"]}]    | (:Person {name: "Laurence Fishburne"}) |
| (:Movie) | [:ACTED_IN {roles: ["Trinity"]}]     | (:Person {name: "Carrie-Anne Moss"})   |
| (:Movie) | [:ACTED_IN {roles: ["Neo"]}]         | (:Person {name: "Keanu Reeves"})       |
+------------------------------------------------------------------------------------------+

    映射后的结果很可能无法使用。如果将其映射为列表，该列表中会出现多个Movie的重复项，但该电影实际上只有一个关联关系。

    为每个根节点获取一条记录

    要获取正确的对象，需要在查询中收集关系和相关节点：MATCH (m:Movie{title: 'The Matrix'})←[r:ACTED_IN]-(p:Person) return m,collect(r),collect(p)

    单条记录（简化版）
    +------------------------------------------------------------------------+
| m        | collect(r)                     | collect(p)                 |
+------------------------------------------------------------------------+
| (:Movie) | [[:ACTED_IN], [:ACTED_IN], ...]| [(:Person), (:Person),...] |
+------------------------------------------------------------------------+

    有了这一结果作为单条记录，Spring Data Neo4j 即可将所有相关节点正确添加到根节点。

    深入探索图结构

    上述示例假设您仅需获取第一级关联节点。 有时这还不够，图中可能存在更深层的节点也应包含在映射实例中。 实现这一目标有两种方式：数据库端缩减或客户端缩减。

    为此，上面的示例还应包含在初始返回的Movie中带有Movies的Persons。

    图 1。“黑客帝国”与“基努·里维斯”的示例

    数据库端缩减

    鉴于 Spring Data Neo4j 仅能正确处理基于记录的数据，单个实体实例的结果必须位于一条记录中。利用Cypher 的路径功能来获取图中所有分支是一个有效的选项。

    朴素的路径方法
    MATCH p=(m:Movie{title: 'The Matrix'})<-[:ACTED_IN]-(:Person)-[:ACTED_IN*..0]->(:Movie)
RETURN p;

    这将导致生成多条未合并到同一条记录中的路径。 可以调用 `collect(p)`，但 Spring Data Neo4j 在映射过程中并不理解“路径”这一概念。 因此，需要提取节点和关系以获取结果。

    提取节点和关系
    MATCH p=(m:Movie{title: 'The Matrix'})<-[:ACTED_IN]-(:Person)-[:ACTED_IN*..0]->(:Movie)
RETURN m, nodes(p), relationships(p);

    由于从《黑客帝国》到另一部电影存在多条路径，结果仍然不会是单条记录。 这时就需要用到Cypher 的 reduce 函数了。

    减少节点和关系
    MATCH p=(m:Movie{title: 'The Matrix'})<-[:ACTED_IN]-(:Person)-[:ACTED_IN*..0]->(:Movie)
WITH collect(p) as paths, m
WITH m,
reduce(a=[], node in reduce(b=[], c in [aa in paths | nodes(aa)] | b + c) | case when node in a then a else a + node end) as nodes,
reduce(d=[], relationship in reduce(e=[], f in [dd in paths | relationships(dd)] | e + f) | case when relationship in d then d else d + relationship end) as relationships
RETURN m, relationships, nodes;

    `reduce` 函数允许我们扁平化来自各种路径的节点和关系。因此，我们将得到一个与为每个根节点获取一条记录类似的元组，但其集合中混合了不同类型的关系或节点。

    客户端端缩减

    如果需要在客户端执行缩减操作，Spring Data Neo4j 允许您映射关系或节点的列表的列表。不过，返回的记录仍需包含所有必要信息，以便正确填充生成的实体实例。

    从路径中收集节点和关系
    MATCH p=(m:Movie{title: 'The Matrix'})<-[:ACTED_IN]-(:Person)-[:ACTED_IN*..0]->(:Movie)
RETURN m, collect(nodes(p)), collect(relationships(p));

    额外的 `collect` 语句会创建如下格式的列表：

    [[rel1, rel2], [rel3, rel4]]

    这些列表将在映射过程中被转换为一个扁平列表。

    选择使用客户端还是数据库端进行归约，取决于将生成的数据量。 当使用 reduce 函数时，所有路径都需要先在数据库内存中创建。 另一方面，需要在客户端合并的大量数据会导致该处的内存使用量更高。

    使用路径来填充并返回实体列表

    给定一个如下所示的图：

    图 2. 具有出向关系的图表

    以及一个如映射所示的领域模型（为简洁起见，已省略构造函数和访问器）：

    带有出向关系的图的域模型。
    @Node
public class SomeEntity {

    @Id
    private final Long number;

    private String name;

    @Relationship(type = "SOME_RELATION_TO", direction = Relationship.Direction.OUTGOING)
    private Set<SomeRelation> someRelationsOut = new HashSet<>();


}

@RelationshipProperties
public class SomeRelation {

    @RelationshipId
    private Long id;

    private String someData;

    @TargetNode
    private SomeEntity targetPerson;


}

    如您所见，这些关系仅为单向关联。生成的查找方法（包括 `findById`）将始终尝试匹配一个根节点以进行映射。从该根节点开始，所有相关对象都将被映射。对于仅返回单个对象的查询，将返回该根对象；而对于返回多个对象的查询，则返回所有匹配的对象。这些已返回对象的出向和入向关联关系自然也会被填充。

    假设以下 Cypher 查询：

    MATCH p = (leaf:SomeEntity {number: $a})-[:SOME_RELATION_TO*]-(:SomeEntity)
RETURN leaf, collect(nodes(p)), collect(relationships(p))

    这遵循了为根节点获取单条记录中的建议，并且对于您希望在此处匹配的叶节点效果极佳。然而：这种情况仅适用于返回 0 或 1 个映射对象的所有场景。虽然该查询会像之前一样填充所有关系，但它不会返回全部 4 个对象。

    可以通过返回完整路径来修改此行为：

    MATCH p = (leaf:SomeEntity {number: $a})-[:SOME_RELATION_TO*]-(:SomeEntity)
RETURN p

    这里我们确实希望利用路径p实际上返回包含到所有 4 个节点路径的 3 行这一事实。这 4 个节点都将被填充、相互链接并返回。

    自定义查询中的参数

    您执行此操作的方式与在 Neo4j Browser 或 Cypher-Shell 中发出标准 Cypher 查询时完全相同，使用 `$` 语法（从 Neo4j 4.0 开始，旧版用于 Cypher 参数的 `${foo}` 语法已从数据库中移除）。

    ARepository.java
    public interface ARepository extends Neo4jRepository<AnAggregateRoot, String> {

	@Query("MATCH (a:AnAggregateRoot {name: $name}) RETURN a") (1)
	Optional<AnAggregateRoot> findByCustomQuery(String name);

}
    1 这里我们使用参数名称来引用它。 你也可以使用 $0 等替代。
    您需要使用 -parameters 选项编译 Java 8+ 项目，以便无需额外注解即可使用命名参数。Spring Boot Maven 和 Gradle 插件会自动为您完成此操作。如果因任何原因无法实现这一点，您可以选择添加 @Param 并显式指定名称，或者使用参数索引。

    作为参数传递给带有自定义查询注解的函数时，所有映射实体（即包含 `@Node` 的内容）将被转换为嵌套 Map。以下示例展示了其作为 Neo4j 参数的结构。

    给定如下所示的电影模型中注释的Movie、Vertex和Actor类：

    “标准”电影模型
    @Node
public final class Movie {

    @Id
    private final String title;

    @Property("tagline")
    private final String description;

    @Relationship(value = "ACTED_IN", direction = Direction.INCOMING)
    private final List<Actor> actors;

    @Relationship(value = "DIRECTED", direction = Direction.INCOMING)
    private final List<Person> directors;
}

@Node
public final class Person {

    @Id @GeneratedValue
    private final Long id;

    private final String name;

    private Integer born;

    @Relationship("REVIEWED")
    private List<Movie> reviewed = new ArrayList<>();
}

@RelationshipProperties
public final class Actor {

	@RelationshipId
	private final Long id;

    @TargetNode
    private final Person person;

    private final List<String> roles;
}

interface MovieRepository extends Neo4jRepository<Movie, String> {

    @Query("MATCH (m:Movie {title: $movie.__id__})\n"
           + "MATCH (m) <- [r:DIRECTED|REVIEWED|ACTED_IN] - (p:Person)\n"
           + "return m, collect(r), collect(p)")
    Movie findByMovie(@Param("movie") Movie movie);
}

    自定义查询中的值表达式

    自定义查询中的 Spring 表达式语言

    Spring 表达式语言 (SpEL) 可用于 :#{} 内部的自定义查询中。此处的冒号表示参数，因此此类表达式应仅在参数有意义的地方使用。然而，在使用我们的字面量扩展时，您可以在标准 Cypher 不允许使用参数的位置（例如用于标签或关系类型）使用 SpEL 表达式。这是 Spring Data 定义查询中需经过 SpEL 评估的文本块的标准方式。

    下面的示例基本上定义了与上述相同的查询，但使用了一个 WHERE 子句来避免更多的花括号：

    ARepository.java
    public interface ARepository extends Neo4jRepository<AnAggregateRoot, String> {

	@Query("MATCH (a:AnAggregateRoot) WHERE a.name = :#{#pt1 + #pt2} RETURN a")
	Optional<AnAggregateRoot> findByCustomQueryWithSpEL(String pt1, String pt2);

}

    SpEL 阻塞以:#{开头，然后通过名称引用给定的参数（例如#pt1）。 请勿将其与上述 Cypher 语法混淆！ SpEL 表达式将两个参数拼接为一个单一值，该值最终传递给附录/neo4j-client.adoc#neo4j-client。 SpEL 块以}结束。

    SpEL 还解决了两个额外的问题。我们提供了两个扩展，允许将 `Sort` 对象传入自定义查询中。 还记得关于faq.adoc#custom-queries-with-page-and-slice-examples的自定义查询吗？ 通过 `orderBy` 扩展，您可以将一个带有动态排序的 `Pageable` 对象传入自定义查询：

    orderBy-Extension
    import org.springframework.data.domain.Pageable;
import org.springframework.data.domain.Sort;
import org.springframework.data.neo4j.repository.Neo4jRepository;
import org.springframework.data.neo4j.repository.query.Query;

public interface MyPersonRepository extends Neo4jRepository<Person, Long> {

    @Query(""
        + "MATCH (n:Person) WHERE n.name = $name RETURN n "
        + ":#{orderBy(#pageable)} SKIP $skip LIMIT $limit" (1)
    )
    Slice<Person> findSliceByName(String name, Pageable pageable);

    @Query(""
        + "MATCH (n:Person) WHERE n.name = $name RETURN n :#{orderBy(#sort)}" (2)
    )
    List<Person> findAllByName(String name, Sort sort);
}
    1 Pageable 在 SpEL 上下文中始终具有名称 pageable。
    2 Sort 在 SpEL 上下文中始终具有名称 sort。

    Spring 表达式语言扩展

    字面量扩展

    `literal` 扩展可用于在自定义查询中使标签或关系类型等元素呈现“动态”特性。由于 Cypher 无法对标签或关系类型进行参数化，因此必须将其作为字面量提供。

    literal-Extension
    interface BaseClassRepository extends Neo4jRepository<Inheritance.BaseClass, Long> {

    @Query("MATCH (n:`:#{literal(#label)}`) RETURN n") (1)
    List<Inheritance.BaseClass> findByLabel(String label);
}
    1 literal扩展将被替换为已评估参数的字面值。

    此处，literal 值已用于在 Label 上进行动态匹配。 如果将 SomeLabel 作为参数传递给该方法，则会生成 MATCH (n:SomeLabel) RETURN n。已添加转义符以正确转义值。SDN 不会自动执行此操作，因为在所有情况下这可能都不是您想要的行为。

    列出扩展

    对于多个值，存在 `allOf` 和 `anyOf`，它们会分别渲染为所有值的 `&`（与）或 `|`（或）连接的列表。

    列出扩展
    interface BaseClassRepository extends Neo4jRepository<Inheritance.BaseClass, Long> {

    @Query("MATCH (n:`:#{allOf(#label)}`) RETURN n")
    List<Inheritance.BaseClass> findByLabels(List<String> labels);

    @Query("MATCH (n:`:#{anyOf(#label)}`) RETURN n")
    List<Inheritance.BaseClass> findByLabels(List<String> labels);
}

    引用标签

    您已经知道如何将 Node 映射到领域对象：

    带有多个标签的节点
    @Node(primaryLabel = "Bike", labels = {"Gravel", "Easy Trail"})
public class BikeNode {
    @Id String id;

    String name;
}

    该节点具有多个标签，如果在自定义查询中每次都重复这些标签会非常容易导致错误：你可能会遗漏某个标签或拼写错误。为此，我们提供以下表达式来避免这种情况：#{#staticLabels}。请注意，此表达式不以冒号开头！你可以在带有 @Query 注解的仓库方法中使用它：

    #{#staticLabels} 在实战中的应用
    public interface BikeRepository extends Neo4jRepository<Bike, String> {

    @Query("MATCH (n:#{#staticLabels}) WHERE n.id = $nameOrId OR n.name = $nameOrId RETURN n")
    Optional<Bike> findByNameOrId(@Param("nameOrId") String nameOrId);
}

    该查询将解析为

    MATCH (n:`Bike`:`Gravel`:`Easy Trail`) WHERE n.id = $nameOrId OR n.name = $nameOrId RETURN n

    请注意我们如何使用标准参数作为 `nameOrId`：在大多数情况下，无需在此处通过添加 SpEL 表达式来使事情复杂化。

    自定义查询中的属性占位符解析

    在自定义查询中，可以在${}内使用 Spring 的属性占位符。

    ARepository.java
    @Query("MATCH (a:AnAggregateRoot) WHERE a.name = :${foo} RETURN a")
Optional<AnAggregateRoot> findByCustomQueryWithPropertyPlaceholder();

    在上面的示例中，如果属性foo被设置为bar，那么${foo}块将被解析为bar。
