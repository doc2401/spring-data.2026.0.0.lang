    入门指南

    我们提供用于 SDN 的 Spring Boot Starter。请通过依赖管理包含该 Starter 模块，并配置要使用的 Bolt URL，例如 `spring.neo4j.uri=bolt://localhost:7687`。该 Starter 假定服务器已禁用身份验证。由于 SDN Starter 依赖于 Java Driver Starter，因此上述所有关于配置的说明同样适用于此处。如需查看可用属性的参考，请在 IDE 中使用自动补全功能，在 `spring.neo4j` 命名空间中进行操作。

    软件定义网络（SDN）支持

    • 广为人知且易于理解的命令式编程模型（类似于 Spring Data JDBC 或 JPA）

    • 基于Reactive Streams的反应式编程，包括对反应式事务的完整支持。

    所有这些内容都包含在同一个二进制文件中。反应式编程模型需要在数据库端使用 4 个以上的 Neo4j 服务器，而在应用端则需使用反应式的 Spring。

    准备数据库

    在本示例中，我们继续使用电影图，因为它随每个 Neo4j 实例免费提供。

    如果您没有运行中的数据库，但已安装 Docker，请执行以下命令：

    在 Docker 中启动一个本地 Neo4j 实例。
    docker run --publish=7474:7474 --publish=7687:7687 -e 'NEO4J_AUTH=neo4j/secret' neo4j:5

    现在您可以访问 http://localhost:7474。 上述命令将服务器的密码设置为 secret。 请注意提示符中准备运行的命令 (:play movies)。 执行该命令以向数据库填充一些测试数据。

    创建新的 Spring Boot 项目

    设置 Spring Boot 项目最简单的方法是使用 start.spring.io（如果您不想使用网站，该工具也已集成到主流 IDE 中）。

    选择“Spring Web Starter”即可获得创建基于 Spring 的 Web 应用程序所需的所有依赖项。 Spring Initializr 将为您生成有效的项目结构，并为所选构建工具配置好所有文件和设置。

    使用 Maven

    您可以向 Spring Initializer 发出一个 curl 请求来创建一个基础 Maven 项目：

    使用 Spring Initializr 创建一个基础的 Maven 项目。
    curl https://start.spring.io/starter.tgz \
  -d dependencies=webflux,data-neo4j  \
  -d bootVersion=3.2.0 \
  -d baseDir=Neo4jSpringBootExample \
  -d name=Neo4j%20SpringBoot%20Example | tar -xzvf -

    这将创建一个新文件夹 Neo4jSpringBootExample。 由于该启动器尚未在初始化器中提供，您需要手动将以下依赖添加到您的 pom.xml 中：

    在 Maven 项目中引入 spring-data-neo4j-spring-boot-starter
    <dependency>
	<groupId>org.springframework.boot</groupId>
	<artifactId>spring-boot-starter-data-neo4j</artifactId>
</dependency>

    对于现有项目，您还需要手动添加该依赖。

    使用 Gradle

    思路相同，只需生成一个 Gradle 项目：

    使用 Spring Initializr 创建一个基本的 Gradle 项目。
    curl https://start.spring.io/starter.tgz \
  -d dependencies=webflux,data-neo4j \
  -d type=gradle-project \
  -d bootVersion=3.2.0 \
  -d baseDir=Neo4jSpringBootExampleGradle \
  -d name=Neo4j%20SpringBoot%20Example | tar -xzvf -

    Gradle 的依赖项如下所示，必须添加到 `build.gradle` 中：

    在 Gradle 项目中包含 spring-data-neo4j-spring-boot-starter
    dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-data-neo4j'
}

    对于现有项目，您还需要手动添加该依赖。

    配置项目

    现在在您喜欢的 IDE 中打开这些项目中的任意一个。 找到 `application.properties` 并配置您的 Neo4j 凭据：

    spring.neo4j.uri=bolt://localhost:7687
spring.neo4j.authentication.username=neo4j
spring.neo4j.authentication.password=verysecret

    这是连接 Neo4j 实例所需的最基本内容。

    使用此启动器时，无需添加任何驱动程序的编程配置。 SDN 仓库将自动启用。

    配置 Neo4j Cypher DSL

    根据您运行应用程序的 Neo4j 版本，建议配置 Cypher-DSL 所使用的方言。默认使用的方言针对 Neo4j 5（Neo4j 的长期支持版本）进行优化，与 Neo4j 5.23+ 和 Neo4j 2025.x 兼容。可以通过定义一个 Cypher-DSL `Configuration` Bean 来更改此设置。

    使 Cypher-DSL 使用 Neo4j 4 方言。
    @Bean
Configuration cypherDslConfiguration() {
	return Configuration.newConfig()
                .withDialect(Dialect.NEO4J_4).build();
}
    尽管 Spring Data Neo4j 已尽最大努力确保与 Neo4j 5 及默认方言的兼容性，但仍强烈建议显式指定方言。例如，这样做可以生成更优化的查询，并在较新版本的 Neo4j 中利用 elementId() 功能。

    在模块路径上运行

    Spring Data Neo4j 可以在模块路径上运行，其自动模块名称为 spring.data.neo4j。由于当前 Spring Data 构建设置的限制，它本身不提供模块。因此，它使用一个自动但稳定的模块名称。然而，它依赖于一个模块化库（Cypher-DSL）。由于上述限制导致缺少 module-info.java，我们无法代表您表达对该库的需求。

    因此，要在模块路径上运行 Spring Data Neo4j 6.1+，您的项目中所需的最低 `module-info.java` 如下：

    项目中使用模块路径的 Spring Data Neo4j 所需的 `module-info.java`
    module your.module {

	requires org.neo4j.cypherdsl.core;

	requires spring.data.commons;
	requires spring.data.neo4j;

	opens your.domain to spring.core; (1)

	exports your.domain; (2)
}
    1 Spring Data Neo4j 使用 Spring Data Commons 及其反射功能，因此您至少需要向 spring.core 开放您的领域包。
    2 此处我们假设 your.domain 中也包含存储库：这些存储库必须被导出，以便 spring.beans、spring.context 和 spring.data.commons 能够访问它们。如果您不想将它们导出到外部，可以将其限制在这些模块内。

    创建您的域

    我们的领域层应完成两项任务：

    • 将您的图映射为对象

    • 提供访问权限给那些人。

    示例节点 - 实体

    SDN 完全支持不可变实体，包括 Java 和 Kotlin 中的 ``data`类。因此，我们将在此处专注于不可变实体，MovieEntity.java 展示了一个此类实体。

    SDN 支持 Neo4j Java Driver 支持的所有数据类型，请参阅“Cypher 类型系统”章节中的将 Neo4j 类型映射到原生语言类型。 未来版本将支持额外的转换器。
    MovieEntity.java
    import java.util.ArrayList;
import java.util.List;

import org.springframework.data.neo4j.core.schema.Id;
import org.springframework.data.neo4j.core.schema.Node;
import org.springframework.data.neo4j.core.schema.Property;
import org.springframework.data.neo4j.core.schema.Relationship;
import org.springframework.data.neo4j.core.schema.Relationship.Direction;

@Node("Movie") (1)
public class MovieEntity {

	@Id (2)
	private final String title;

	@Property("tagline") (3)
	private final String description;

	@Relationship(type = "ACTED_IN", direction = Direction.INCOMING) (4)
	private List<Roles> actorsAndRoles = new ArrayList<>();


	@Relationship(type = "DIRECTED", direction = Direction.INCOMING)
	private List<PersonEntity> directors = new ArrayList<>();

	public MovieEntity(String title, String description) { (5)
		this.title = title;
		this.description = description;
	}

	// Getters omitted for brevity

}
    1 @Node 用于将此类标记为托管实体。它还可用于配置 Neo4j 标签。如果您仅使用普通的 @Node，则标签默认为类的名称。
    2 每个实体都必须具有一个 id。此处展示的 movie 类使用属性 title 作为唯一业务键。如果您没有这样的唯一键，可以使用 @Id 和 @GeneratedValue 的组合来配置 SDN 使用 Neo4j 的内部 id。我们还提供了 UUID 生成器。
    3 这展示了如何使用 @Property 为字段和图属性使用不同的名称。
    4 这定义了一个指向类型为 PersonEntity 的类的关系，以及关系类型 ACTED_IN。
    5 这是您的应用程序代码将使用的构造函数。

    作为一般性说明：使用内部生成 ID 的不可变实体存在一定矛盾，因为 SDN 需要一种方式将数据库生成的值设置到该字段中。

    如果您找不到合适的业务键，或者不想使用 ID 生成器，这里展示了同一实体：它使用内部生成的 ID，配合常规构造函数以及所谓的with-方法（该方法由 SDN 使用）：

    MovieEntity.java
    import org.springframework.data.neo4j.core.schema.GeneratedValue;
import org.springframework.data.neo4j.core.schema.Id;
import org.springframework.data.neo4j.core.schema.Node;
import org.springframework.data.neo4j.core.schema.Property;

import org.springframework.data.annotation.PersistenceConstructor;

@Node("Movie")
public class MovieEntity {

	@Id @GeneratedValue
	private Long id;

	private final String title;

	@Property("tagline")
	private final String description;

	public MovieEntity(String title, String description) { (1)
		this.id = null;
		this.title = title;
		this.description = description;
	}

	public MovieEntity withId(Long id) { (2)
		if (this.id.equals(id)) {
			return this;
		} else {
			MovieEntity newObject = new MovieEntity(this.title, this.description);
			newObject.id = id;
			return newObject;
		}
	}
}
    1 这是您的应用程序代码应使用的构造函数。它将 id 设置为 null，因为包含内部 id 的字段绝不应被修改。
    2 这是一个针对 id 属性的所谓“with”方法。它会创建一个新的实体并相应地设置该字段，而不会修改原始实体，从而使其具有不可变性。

    当然，您可以使用 SDN 配合 Kotlin，并利用 Kotlin 的数据类来建模您的领域。如果您希望或需要完全停留在 Java 环境中，Project Lombok 则是一个替代方案。

    声明 Spring Data 仓库

    您基本上有两个选择： 您可以以与存储无关的方式使用 SDN，并使您的特定领域扩展其中一个。

    • org.springframework.data.repository.Repository

    • org.springframework.data.repository.CrudRepository

    • org.springframework.data.repository.reactive.ReactiveCrudRepository

    • org.springframework.data.repository.reactive.ReactiveSortingRepository

    请根据情况选择命令式或响应式。

    虽然在技术上并未被禁止，但不建议在同一个应用程序中混合使用命令式和响应式数据库访问方式。 我们不会为这类场景提供支持。

    另一种选择是确定针对特定商店的实现方式，从而直接获得我们支持的所有方法。 这种方法的优势同时也是其最大的劣势：一旦实施，所有这些方法将成为您 API 的一部分。 通常情况下，事后移除功能比后续添加功能更为困难。 此外，使用特定于商店的实现会将您的商店逻辑泄露到业务领域层中。 从性能角度来看，这种方式没有任何开销。

    一个适用于上述任何电影实体的响应式仓储结构如下所示：

    MovieRepository.java
    import reactor.core.publisher.Mono;

import org.springframework.data.neo4j.repository.ReactiveNeo4jRepository;

public interface MovieRepository extends ReactiveNeo4jRepository<MovieEntity, String> {

	Mono<MovieEntity> findOneByTitle(String title);

}
    测试响应式代码需要使用 reactor.test.StepVerifier。 请查看 Project Reactor 的相应文档，或参考我们的示例代码。
