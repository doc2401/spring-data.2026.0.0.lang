    查询方法

    本节提供有关 Spring Data JDBC 实现和使用的具体信息。

    您在仓储上通常触发的绝大多数数据访问操作都会导致在数据库上执行查询。定义此类查询只需在仓储接口上声明一个方法，如下例所示：

    带查询方法的 PersonRepository
    interface PersonRepository extends PagingAndSortingRepository<Person, Long> {

    List<Person> findByFirstname(String firstname);                                   (1)

    List<Person> findByFirstnameOrderByLastname(String firstname, Pageable pageable); (2)

    Slice<Person> findByLastname(String lastname, Pageable pageable);                 (3)

    Page<Person> findByLastname(String lastname, Pageable pageable);                  (4)

    Person findByFirstnameAndLastname(String firstname, String lastname);             (5)

    Person findFirstByLastname(String lastname);                                      (6)

    @Query("SELECT * FROM person WHERE lastname = :lastname")
    List<Person> findByLastname(String lastname);                                     (7)
    @Query("SELECT * FROM person WHERE lastname = :lastname")
    Stream<Person> streamByLastname(String lastname);                                     (8)

    @Query("SELECT * FROM person WHERE username = :#{ principal?.username }")
    Person findActiveUser();															(9)
}
    1 该方法展示了查询所有具有给定 firstname 的人。该查询是通过解析方法名中的约束条件生成的，这些约束条件可以与 And 和 Or 连接。因此，方法名生成的查询表达式为 SELECT … FROM person WHERE firstname = :firstname。
    2 使用 Pageable 将偏移量和排序参数传递给数据库。
    3 返回一个 Slice<Person>。选择 LIMIT+1 行以确定是否还有更多数据需要消费。不支持 ResultSetExtractor 自定义。
    4 运行分页查询，返回 Page<Person>。仅选择给定页面范围内的数据，并可能执行计数查询以确定总数。不支持 ResultSetExtractor 自定义。
    5 根据给定条件查找单个实体。如果结果不唯一，将以 IncorrectResultSizeDataAccessException 完成。
    6 与 <5> 相反，即使查询产生更多结果，也会始终发出第一个实体。
    7 该方法展示了查询所有具有给定 lastname 的人。
    8 该 streamByLastname 方法返回一个 Stream，使得值在从数据库返回后即可使用。
    9 您可以使用 Spring 表达式语言动态解析参数。在示例中，使用 Spring Security 解析当前用户的用户名。

    下表显示了查询方法支持的关键词：

    表 1。查询方法支持的关键词
    关键字 示例 逻辑结果

    findByLastnameAndFirstname

    Or

    … WHERE lastname = :lastname OR firstname = :firstname

    … WHERE 姓名 = :firstname（或者如果参数为null，则使用… WHERE 姓名 IS NULL）

    Between

    findByStartDateBetween

    … WHERE startDate BETWEEN :startDate and :startDate1

    LessThan

    findByAgeLessThan

    … WHERE age < :age

    LessThanEqual

    findByAgeLessThanEqual

    … WHERE age <= :age

    GreaterThan

    findByAgeGreaterThan

    … WHERE age > :age

    GreaterThanEqual

    findByAgeGreaterThanEqual

    … WHERE age >= :age

    After

    findByStartDateAfter

    … WHERE startDate > :startDate

    Before

    findByStartDateBefore

    … WHERE startDate < :startDate

    IsNull, Null

    findByAge(Is)Null

    … WHERE age IS NULL

    IsNotNull, NotNull

    findByAge(Is)NotNull

    … WHERE age IS NOT NULL

    Like

    findByFirstnameLike

    … WHERE firstname LIKE :firstname

    NotLike

    findByFirstnameNotLike

    … WHERE firstname NOT LIKE :firstname

    StartingWith

    findByFirstnameStartingWith

    … WHERE 姓名 LIKE :firstname（参数绑定并追加了 %）

    EndingWith

    findByFirstnameEndingWith

    … WHERE 姓名 LIKE :firstname（参数绑定并前置了%）

    Containing

    findByFirstnameContaining

    … where UPPER(firstname) = UPPER(:firstname)
    查询推导仅限于那些可以在不使用连接的情况下用于 WHERE 子句的属性。

    查询查找策略

    JDBC 模块支持在 `@Query` 注解中手动将查询定义为字符串，或在属性文件中将其定义为命名查询。

    从方法名推导查询目前仅限于简单属性，即直接存在于聚合根中的属性。此外，此方法仅支持选择查询。

    Using @Query

    以下示例展示了如何使用 `@Query` 声明查询方法：

    使用 @Query 声明查询方法。
    interface UserRepository extends CrudRepository<User, Long> {

    @Query("SELECT first_name, last_name FROM user WHERE email_address = :email")
    User findByEmailAddress(@Param("email") String email);
}

    将查询结果转换为实体时，默认使用与 Spring Data JDBC 自身生成的查询相同的 `RowMapper`。您提供的查询必须符合 `RowMapper` 期望的格式。必须提供实体构造函数中所有属性对应的列。通过 setter、wither 或字段访问方式设置的属性对应的列为可选。结果集中没有匹配列的属性将不会被设置。该查询用于填充聚合根、嵌入实体以及一对一关系，包括作为 SQL 数组类型存储和加载的原生类型数组。对于映射、列表、集合和实体数组，会生成单独的查询。

    一对一关系的属性名称必须以关系名称加上_作为前缀。例如，如果上述示例中的User具有一个address属性，且该地址包含city属性，则对应city的列必须标记为address_city。

    请注意，基于字符串的查询不支持分页，也不接受 Sort、PageRequest 和 Limit 作为查询参数，因为这些查询需要重写。 如果您想应用限制，请使用 SQL 表达此意图，并自行将适当的参数绑定到查询中。

    查询可能包含 SpEL 表达式。 有两种变体，它们的评估方式不同。

    在第一种变体中，SpEL 表达式以前缀 `:` 开头，并像绑定变量一样使用。此类 SpEL 表达式将被替换为绑定变量，且该变量被绑定到 SpEL 表达式的结果。

    在查询中使用 SpEL
    @Query("SELECT * FROM person WHERE id = :#{#person.id}")
Person findWithSpEL(PersonRef person);

    这可用于访问参数的成员，如上例所示。 对于更复杂的用例，可以在应用程序上下文中提供 `EvaluationContextExtension`，进而使任何对象在 SpEL 中可用。

    另一种变体可用于查询中的任何位置，且评估该查询的结果将替换查询字符串中的表达式。

    在查询中使用 SpEL
    @Query("SELECT * FROM #{tableName} WHERE id = :id")
Person findWithSpEL(PersonRef person);

    它在首次执行前仅评估一次，并使用一个添加了两个变量tableName和qualifiedTableName的StandardEvaluationContext。 这种用法在表名本身也是动态时最为有用，因为它们同样使用 SpEL 表达式。

    Spring 完全支持基于 -parameters 编译器标志的 Java 8 参数名发现功能。 在构建中使用此标志作为调试信息的替代方案，您可以省略命名参数的 @Param 注解。
    Spring Data JDBC 仅支持命名参数。

    命名查询

    如果注解中未提供查询（如上一节所述），Spring Data JDBC 将尝试查找命名查询。 确定查询名称有两种方式。 默认情况下，采用查询的领域类（即仓库的聚合根）的简单名称，并追加方法名，两者之间用.分隔。 或者，可以使用@Query注解的name属性来指定要查找的查询名称。

    命名查询预期在类路径中的属性文件 `META-INF/jdbc-named-queries.properties` 中提供。

    该文件的位置可以通过设置 `@EnableJdbcRepositories.namedQueriesLocation` 的值来更改。

    命名查询的处理方式与通过注解提供的查询相同。

    自定义查询方法

    流式结果

    当您将查询方法的返回类型指定为 Stream 时，Spring Data JDBC 会立即返回可用的元素。在处理大量数据时，这种方式有助于降低延迟并减少内存需求。

    流包含一个指向数据库的开放连接。为避免内存泄漏，最终需要通过关闭流来关闭该连接。推荐的做法是使用 try-with-resource 语句。这也意味着，一旦数据库连接被关闭，流将无法获取更多元素，并很可能抛出异常。

    Custom RowMapper or ResultSetExtractor

    `@Query` 注解允许您指定要使用的自定义 `RowMapper` 或 `ResultSetExtractor`。 属性 `rowMapperClass` 和 `resultSetExtractorClass` 可用于指定要使用的类，这些类将通过默认构造函数进行实例化。 或者，您可以将 `rowMapperRef` 或 `resultSetExtractorRef` 设置为 Spring 应用程序上下文中的 Bean 名称。

    如果您希望使用某个特定的RowMapper不仅针对单个方法，而是针对所有返回特定类型的自定义查询方法，您可以注册一个QueryMappingConfiguration Bean，并为每个方法返回类型注册一个RowMapper。 以下示例展示了如何注册DefaultQueryMappingConfiguration：

    @Bean
QueryMappingConfiguration rowMappers() {
    return new DefaultQueryMappingConfiguration()
        .register(Person.class, new PersonRowMapper())
        .register(Address.class, new AddressRowMapper());
}

    在确定方法应使用哪个RowMapper时，会根据方法的返回类型遵循以下步骤：

    1. 如果类型是简单类型，则不使用RowMapper。

      相反，预期查询将返回包含单列的单行数据，并对该值应用转换以匹配返回类型。

    2. `QueryMappingConfiguration` 中的实体类会被遍历，直到找到一个是目标返回类型的超类或接口的类为止。 将为此类注册的 `RowMapper` 将被使用。

      迭代按注册顺序进行，因此请确保在特定类型之后注册更通用的类型。

    如果适用，包装类型（如集合或Optional）将被解包。因此，返回类型为Optional<Person>时，在之前的处理过程中会使用Person类型。

    通过 QueryMappingConfiguration 使用自定义的 RowMapper，或使用 @Query(rowMapperClass=…)，或自定义的 ResultSetExtractor，将禁用实体回调和生命周期事件，因为结果映射在需要时可以自行发出相应的事件/回调。

    修改查询

    您可以使用查询方法上的 `@Modifying` 标记将查询标识为修改查询，如下例所示：

    @Modifying
@Query("UPDATE DUMMYENTITY SET name = :name WHERE id = :id")
boolean updateName(@Param("id") Long id, @Param("name") String name);

    您可以指定以下返回类型：

    • void

    • （更新的记录数）

    • boolean(是否更新了记录)

    对查询的修改会直接作用于数据库。 不会触发任何事件或回调。 因此，如果审计注解中的字段未在注解的查询中被更新，这些字段也不会被更新。
