    Mapping

    MappingJdbcConverter 提供了丰富的映射支持。MappingJdbcConverter 拥有完善的元数据模型，能够将领域对象映射到数据行。该映射元数据模型通过您在领域对象上使用的注解进行填充。然而，基础设施并不局限于仅使用注解作为元数据的唯一来源。MappingJdbcConverter 还允许您遵循一系列约定，在无需提供任何额外元数据的情况下将对象映射到行。

    本节介绍 `MappingJdbcConverter` 的功能，包括如何使用约定将对象映射到行，以及如何通过基于注解的映射元数据覆盖这些约定。

    继续阅读对象映射基础，然后再继续本章内容。

    基于约定的映射

    当未提供额外的映射元数据时，`MappingJdbcConverter` 在将对象映射为行时遵循一些约定。这些约定如下：

    • 短 Java 类名按以下方式映射到表名。 com.bigbank.SavingsAccount 类映射到 SAVINGS_ACCOUNT 表名。 相同的名称映射规则也用于将字段映射到列名。 例如，firstName 字段映射到 FIRST_NAME 列。 您可以通过提供自定义的 NamingStrategy 来控制此映射。 有关更多详细信息，请参阅映射配置。 默认情况下，从属性名或类名派生的表和列名在 SQL 语句中使用引号。 您可以通过设置 JdbcMappingContext.setForceQuote(false) 来控制此行为，或使用 JdbcMappingContext.forPlainIdentifiers() 创建一个具有普通（未加引号）标识符的上下文。

    • 转换器使用通过CustomConversions注册的任意 Spring 转换器，以覆盖对象属性到行列和值的默认映射。

    • 对象的字段用于在行中的列之间进行转换。 不使用公共的 `JavaBean` 属性。

    • 如果存在一个具有单个非零参数的构造函数，且该构造函数的参数名称与行的顶级列名匹配，则使用该构造函数。否则，使用无参构造函数。如果存在多个具有非零参数的构造函数，将抛出异常。有关更多详细信息，请参阅对象创建。

    实体中支持的类型

    当前支持以下类型的属性：

    • 所有基本类型及其对应的包装类型（int、float、Integer、Float 等）

    • 枚举会被映射为其名称。

    • String

    • java.util.Date, java.time.LocalDate, java.time.LocalDateTime, and java.time.LocalTime

    • 如果数据库支持，上述类型的数组和集合可以映射为数组类型的列。

    • 数据库驱动程序接受的任何内容。

    • 对其他实体的引用。 它们被视为一对一关系或嵌入类型。 对于一对一关系的实体，id 属性是可选的。 预期被引用实体的表将包含一个额外列，其名称基于引用实体，参见 反向引用。 嵌入实体不需要 id。 如果存在，它将被映射为普通属性，没有任何特殊含义。

    • Set<some entity> 被视为一对多关系。 预期被引用实体的表将包含一个额外列，其名称基于引用实体，参见反向引用。

    • Map<简单类型，某些实体> 被视为合格的单向一对多关系。 预期被引用实体的表将包含两个额外的列：一列基于引用实体命名以表示外键（参见回引），另一列名称相同但附加 _key 后缀用于映射键。

    • >被映射为>。 预期包含相同的附加列，且列名可按相同方式自定义。

      对于 ``、`` 和 ``，可以通过分别实现 `NamingStrategy.getReverseColumnName(RelationalPersistentEntity owner)` 和 `NamingStrategy.getKeyColumn(RelationalPersistentProperty property)` 来控制反向引用的命名。 或者，您可以使用注解 `@MappedCollection(idColumn="your_column_name", keyColumn="your_key_column_name")` 来标注该属性。 为 `` 指定键列无效。

    • 已注册了合适的自定义转换器的类型。

    映射注解概述

    RelationalConverter 可以使用元数据来驱动对象到行的映射。 以下注解可用：

    • @Embedded：带有此注解的属性将被映射到父实体所在的表，而不是单独的表。 允许指定生成的列是否应具有公共前缀。 如果由该实体生成的所有列均为 null，则根据 @Embedded.onEmpty() 的值，该注解实体将变为 null 或空（即其所有属性均为 null）。 可与 @Id 组合使用以形成复合主键。

    • @Id：应用于字段级别，用于标记主键。 它可以与 @Embedded 结合使用以形成复合主键。

    • @InsertOnlyProperty：标记该属性仅在插入时写入。在聚合根上的此类属性将仅被写入一次，且永远不会被更新。请注意，对于嵌套实体，所有保存操作均被视为插入，因此该注解对嵌套实体的属性无效。

    • ：允许配置集合或单个嵌套实体的映射方式。idColumn 指定用于引用父实体主键的列。keyColumn 指定用于存储 List 索引或 Map 键的列。

    • @Sequence：指定用于为已注解属性生成值的数据库序列。

    • @Table：在类级别应用，表示该类是数据库映射的候选者。您可以指定存储该表的数据库名称。

    • @Transient：默认情况下，所有字段都会映射到行中。此注解会排除应用该注解的字段不被存储到数据库中。瞬态属性不能在持久化构造函数中使用，因为转换器无法为构造函数参数生成值。

    • @PersistenceCreator：标记一个给定的构造函数或静态工厂方法（即使是包级私有的），用于从数据库实例化对象。 构造函数的参数通过名称映射到检索到的行中的值。

    • @Value：此注解属于 Spring 框架。在映射框架中，它可以应用于构造函数参数。这使得您能够在使用检索到的数据库键值构建领域对象之前，使用 Spring 表达式语言语句对其进行转换。若要引用给定行中的某一列，需使用类似 @Value("#root.myProperty") 的表达式，其中 root 指代给定 Row 的根节点。

    • @Column：应用于字段级别，用于描述行中列的名称，使其可以与类的字段名不同。 当启用 forceQuote（默认情况下）时，使用 @Column 注解指定的名称会被加引号。 对于大多数数据库而言，加引号意味着这些名称是区分大小写的。 这也意味着您可以在这些名称中使用特殊字符。 然而，这不推荐，因为这可能会与其他工具产生问题。

    • @Version：在字段级别应用，用于乐观锁，并在保存操作时检查修改。 对于包装类型，值为 null（或对于基本类型为 zero）表示实体为新实体。 初始存储的值对于包装类型为 zero（对于基本类型为 one）。 每次更新时版本号会自动递增。

    有关更多参考，请参见乐观锁。

    映射元数据基础设施定义在独立的、与具体技术无关的 spring-data-commons 项目中。JDBC 支持使用特定的子类来支持基于注解的元数据。其他策略也可以根据需要被引入（如果有需求的话）。

    引用实体

    引用实体的处理受到限制。 这是基于上述描述的聚合根概念。 如果您引用另一个实体，那么根据定义，该实体即属于您的聚合部分。 因此，如果移除引用，先前被引用的实体将被删除。 这也意味着引用关系只能是 1-1 或 1-n，而不能是 n-1 或 n-m。

    如果您有 n-1 或 n-m 个引用，根据定义，您正在处理两个独立的聚合。这些聚合之间的引用可以编码为简单的 `id` 值，这些值能够与 Spring Data JDBC 正确映射。更好的编码方式是将它们实例化为 `AggregateReference`。AggregateReference 是一个包装器，它封装了一个 id 值，并标记该值为对另一个聚合的引用。此外，该聚合的类型也通过类型参数进行编码。

    反向引用

    聚合中的所有引用都会在数据库中形成反向的外键关系。 默认情况下，外键列的名称为引用实体的表名。

    如果引用的 ID 是 `@Embedded` ID，则回引用由多个列组成，每个列的名称由 `` + `_` + `` 拼接而成。例如，对于具有复合 ID 且属性为 `firstName` 和 `lastName` 的 `Person` 实体，其回引用将由两个列 `PERSON_FIRST_NAME` 和 `PERSON_LAST_NAME` 组成。

    或者，您可以选择使用引用实体的实体名称来命名它们，而忽略 `@Table` 注解。 您可以通过在 `DefaultNamingStrategy` 上调用 `setForeignKeyNaming(ForeignKeyNaming.IGNORE_RENAMING)` 来激活此行为。

    对于 `List` 和 `Map` 引用，需要额外添加一列用于存储列表索引或映射键。该列基于外键列，并附加了 `_KEY` 后缀。

    如果您希望以完全不同的方式命名这些反向引用，可以在您的实现中自定义NamingStrategy.getReverseColumnName(RelationalPersistentEntity<?> owner)方法，使其符合您的需求。

    声明并设置AggregateReference
    class Person {
    @Id long id;
    AggregateReference<Person, Long> bestFriend;
}

// ...

Person p1, p2 = // some initialization

p1.bestFriend = AggregateReference.to(p2.id);

    您不应在实体中使用属性来存储反向引用的实际值，也不应存储映射或列表的主键列。 如果您希望这些值在领域模型中可用，我们建议在AfterConvertCallback中执行此操作，并将这些值存储在瞬态属性中。

    命名策略

    按照约定，Spring Data 会应用一个 NamingStrategy 来确定表、列和模式名称，默认采用 蛇形命名法。 名为 firstName 的对象属性将变为 first_name。 您可以通过在应用程序上下文中提供一个 NamingStrategy 来调整此行为。

    覆盖表名

    当表命名策略与您的数据库表名不匹配时，您可以使用 Table 注解来覆盖表名。 该注解的 value 元素提供自定义表名。 以下示例将 MyEntity 类映射到数据库中的 CUSTOM_TABLE_NAME 表：

    @Table("CUSTOM_TABLE_NAME")
class MyEntity {
    @Id
    Integer id;

    String name;
}

    您可以使用Spring Data 的 SpEL 支持来动态创建表名。生成后的表名会被缓存，因此仅在映射上下文中是动态的。

    覆盖列名

    当列命名策略与数据库列名不匹配时，您可以使用 Column 注解覆盖列名。 该注解的 value 元素提供自定义列名。 以下示例将 MyEntity 类的 name 属性映射到数据库中的 CUSTOM_COLUMN_NAME 列：

    class MyEntity {
    @Id
    Integer id;

    @Column("CUSTOM_COLUMN_NAME")
    String name;
}

    `MappedCollection` 注解可用于 Set、List 和 Map（一对多关系）。该注解的 `idColumn` 元素可为引用另一表中 id 列的外键列指定自定义名称。它还可用于自定义单实体（一对一）引用的反向引用列名称。在以下示例中，与 `MySubEntity` 类对应的表包含一个 `NAME` 列，而 `MyEntity` 的 `CUSTOM_MY_ENTITY_ID_COLUMN_NAME` 列则因关系原因被用作 id：

    class MyEntity {
    @Id
    Integer id;

    @MappedCollection(idColumn = "CUSTOM_MY_ENTITY_ID_COLUMN_NAME")
    Set<MySubEntity> subEntities;
}

class MySubEntity {
    String name;
}

    在使用List和Map时，必须额外添加一列，用于表示数据集在List中的位置或实体在Map中的键值。 此附加列的名称可以通过MappedCollection注解的keyColumn元素进行自定义：

    class MyEntity {
    @Id
    Integer id;

    @MappedCollection(idColumn = "CUSTOM_COLUMN_NAME", keyColumn = "CUSTOM_KEY_COLUMN_NAME")
    List<MySubEntity> name;
}

class MySubEntity {
    String name;
}

    您可以使用Spring Data 的 SpEL 支持来动态创建列名。生成的名称会被缓存，因此仅在映射上下文中是动态的。

    嵌入实体

    嵌入式实体用于在 Java 数据模型中包含值对象，即使您的数据库中只有一个表。 在以下示例中可以看到，MyEntity 使用了 @Embedded 注解进行映射。 其结果是，数据库中将期望存在一个名为 my_entity 的表，该表包含两列：id 和 name（来自 EmbeddedEntity 类）。

    然而，如果结果集中的 `name` 列实际上为 `null`，则整个属性 `embeddedEntity` 将根据 `@Embedded` 的 `onEmpty` 设置为 null，该选项会在所有嵌套属性均为 null 时将对象置为 null。
    与这种行为相反，`USE_EMPTY` 尝试使用默认构造函数或接受来自结果集的可为空参数值的构造函数来创建新实例。

    示例 1。嵌入对象的示例代码。
    class MyEntity {

    @Id
    Integer id;

    @Embedded(onEmpty = USE_NULL) (1)
    EmbeddedEntity embeddedEntity;
}

class EmbeddedEntity {
    String name;
}
    1 如果name为null，则嵌入的embeddedEntity为Null。使用USE_EMPTY来实例化embeddedEntity，即使name属性的值可能为null。

    如果在实体中需要多次使用值对象，可以通过 `@Embedded` 注解的可选 `prefix` 元素来实现。该元素表示一个前缀，并将其附加到嵌入对象的每个列名之前。

    使用快捷方式@Embedded.Nullable和@Embedded.Empty来替代@Embedded(onEmpty = USE_NULL)和@Embedded(onEmpty = USE_EMPTY)，以减少冗长性，同时相应地设置 JSR-305 注解@javax.annotation.Nonnull。

    class MyEntity {

    @Id
    Integer id;

    @Embedded.Nullable (1)
    EmbeddedEntity embeddedEntity;
}
    1 @Embedded(onEmpty = USE_NULL) 的快捷方式。

    包含 `Collection` 或 `Map` 的嵌入式实体始终被视为非空，因为它们至少会包含一个空集合或映射。因此，即使在使用 `@Embedded(onEmpty = USE_NULL)` 时，此类实体也永远不会为 `null`。

    嵌入 ID

    标识符属性可以标注为 `@Embedded` 以支持复合主键。完整的嵌入实体被视为标识符，因此用于判断聚合根是新聚合（需要插入）还是已存在聚合（需要更新）的检查基于该实体本身，而非其元素。大多数使用场景都需要自定义一个 `BeforeConvertCallback` 来为新聚合设置标识符。

    具有复合主键的简单实体
    @Table("PERSON_WITH_COMPOSITE_ID")
record Person( (1)
    @Id @Embedded.Nullable Name pk, (2)
    String nickName,
    Integer age
) {
}

record Name(String first, String last) {
}
    简单实体与复合主键的匹配表
    CREATE TABLE PERSON_WITH_COMPOSITE_ID (
    FIRST VARCHAR(100),
    LAST VARCHAR(100),
    NICK_NAME VARCHAR(100),
    AGE INT,
    PRIMARY KEY (FIRST, LAST) (3)
);
    1 实体可以表示为记录，无需特殊考虑。
    2 pk 被标记为 id 并嵌入其中。
    3 来自嵌入式 Name 实体的两列构成了数据库中的主键。

    表创建的具体细节取决于所使用的数据库。

    只读属性

    使用 @ReadOnlyProperty 注解的属性不会被 Spring Data 写入数据库，但在加载实体时会被读取。

    Spring Data 在写入实体后不会自动重新加载该实体。因此，如果您希望查看数据库中为这些列生成的数据，必须显式地重新加载该实体。

    如果注释的属性是实体或实体集合，则它由不同表中的一个或多个独立行表示。 Spring Data 不会对这些行执行任何插入、删除或更新操作。

    仅插入属性

    使用 @InsertOnlyProperty 注解的属性，Spring Data 仅在插入操作时将其写入数据库。对于更新操作，这些属性将被忽略。

    @InsertOnlyProperty 仅支持聚合根。

    自定义对象构建

    映射子系统允许通过用@PersistenceConstructor注解构造函数来自定义对象构建。 用于解析构造函数参数的值的方式如下：

    • 如果参数被标注了 `@Value` 注解，则会评估给定的表达式，并将结果用作该参数的值。

    • 如果 Java 类型具有与输入行给定字段名称匹配的属性，则使用其属性信息来选择要传递输入字段值的适当构造函数参数。 此功能仅在 Java `.class` 文件中存在参数名信息时才能生效，您可以通过在编译源代码时包含调试信息，或在 Java 8 中使用 `javac` 的 `-parameters` 命令行开关来实现这一点。

    • 否则，将抛出MappingException以指示无法绑定给定的构造函数参数。

    class OrderItem {

    private @Id final String id;
    private final int quantity;
    private final double unitPrice;

    OrderItem(String id, int quantity, double unitPrice) {
        this.id = id;
        this.quantity = quantity;
        this.unitPrice = unitPrice;
    }

    // getters/setters omitted
}

    使用显式转换器覆盖映射

    Spring Data 允许注册自定义转换器，以影响数据库中的值映射方式。 目前，转换器仅在属性级别应用，即您只能将领域模型中的单个值转换为数据库中的单个值，反之亦然。 不支持在复杂对象与多个列之间进行转换。

    使用已注册的 Spring 转换器编写属性

    下面的示例展示了如何将一个 Boolean 对象转换为 String 值的 Converter 实现：

    import org.springframework.core.convert.converter.Converter;

@WritingConverter
public class BooleanToStringConverter implements Converter<Boolean, String> {

    @Override
    public String convert(Boolean source) {
        return source != null && source ? "T" : "F";
    }
}

    这里有几点需要注意：Boolean和String都是简单类型，因此Spring Data需要提示该转换器应朝哪个方向应用（读取或写入）。通过用@WritingConverter注解此转换器，您指示Spring Data将每个Boolean属性以String形式写入数据库。

    使用 Spring 转换器进行读取

    下面的示例展示了如何将 `String` 转换为 `Boolean` 值的 `Converter` 实现：

    @ReadingConverter
public class StringToBooleanConverter implements Converter<String, Boolean> {

    @Override
    public Boolean convert(String source) {
        return source != null && source.equalsIgnoreCase("T") ? Boolean.TRUE : Boolean.FALSE;
    }
}

    这里有几点需要注意：String 和 Boolean 都是简单类型，因此 Spring Data 需要提示该转换器的应用方向（读取或写入）。通过用 @ReadingConverter 注解此转换器，您指示 Spring Data 将数据库中应赋值给 Boolean 属性的每个 String 值进行转换。

    使用 JdbcConverter 注册 Spring 转换器

    class MyJdbcConfiguration extends AbstractJdbcConfiguration {

    // …

    @Override
    protected List<?> userConverters() {
        return Arrays.asList(new BooleanToStringConverter(), new StringToBooleanConverter());
    }

}
    在 Spring Data JDBC 的早期版本中，建议直接覆盖 AbstractJdbcConfiguration.jdbcCustomConversions()。 现在已不再需要这样做，甚至不推荐，因为该方法会组装适用于所有数据库的转换、由所使用的 JdbcDialect 注册的转换以及用户注册的转换。 如果您是从 Spring Data JDBC 的旧版本迁移而来并覆盖了 AbstractJdbcConfiguration.jdbcCustomConversions()，则您的 JdbcDialect 中的转换将无法注册。

    如果您希望依赖 Spring Boot 来引导 Spring Data JDBC，但仍想覆盖某些配置方面，您可能需要暴露相应类型的 Bean。 对于自定义转换，您可以选择注册一个类型为 JdbcCustomConversions 的 Bean，该 Bean 将被启动基础设施自动拾取。 如需了解更多相关信息，请务必阅读 Spring Boot 参考文档。

    JdbcValue

    值转换使用 `JdbcValue` 来丰富传播到 JDBC 操作的值，并添加一个 `java.sql.Types` 类型。如果您需要指定特定的 JDBC 类型而不是使用类型推导，请注册自定义写入转换器。该转换器应将值转换为 `JdbcValue`，其中包含用于值的字段和实际的 `JDBCType` 字段。
