    持久实体

    `R2dbcEntityTemplate` 是 Spring Data R2DBC 的核心入口点。它提供了面向实体的直接方法，以及针对典型临时用例（如查询、插入、更新和删除数据）更简洁的流式接口。

    入口点（如insert()、select()、update()、upsert()等）遵循基于要执行的操作的自然命名约定。 从入口点出发，API 仅提供上下文相关的方法，这些方法最终会导向一个终止方法，用于创建并执行 SQL 语句。 Spring Data R2DBC 使用R2dbcDialect抽象来确定绑定标记、分页支持以及底层驱动原生支持的数据类型。

    所有终端方法始终返回一个 Publisher 类型，该类型代表所需的操作。 实际语句将在订阅时发送到数据库。

    用于插入和更新实体的方法

    `R2dbcEntityTemplate` 提供了多种便捷的方法来保存和插入对象。 若需对转换过程进行更细粒度的控制，您可以使用 `R2dbcCustomConversions` 注册 Spring 转换器——例如 `Converter` 和 `Converter`。

    使用保存操作的简单情况是保存一个 POJO。 在这种情况下，表名由类的名称（非限定名）决定。 您也可以调用保存操作并指定集合名称。 您可以使用映射元数据来覆盖存储对象的集合。

    在插入或保存时，如果未设置 `Id` 属性，则假定其值将由数据库自动生成。因此，对于自动生成的场景，您类中的 `Id` 属性或字段的类型必须是数值类型，例如 `Long` 或 `Integer`。

    以下示例演示了如何插入一行并检索其内容：

    使用 R2dbcEntityTemplate 插入和检索实体
    Person person = new Person("John", "Doe");

Mono<Person> saved = template.insert(person);
Mono<Person> loaded = template.selectOne(query(where("firstname").is("John")),
		Person.class);

    可用的插入和更新操作如下：

    • Mono<T> insert (T objectToSave)：将对象插入默认表。

    • Mono<T> update (T objectToSave)：在默认表中更新对象。

    • Mono<T> upsert (T objectToSave)：将对象合并（上载）到默认表中。

    可以使用流式 API 自定义表名。

    选择数据

    `R2dbcEntityTemplate` 上的 `select(…)` 和 `selectOne(…)` 方法用于从表中选择数据。 这两个方法都接受一个 `Query` 对象，该对象定义了字段投影、`WHERE` 子句、`ORDER BY` 子句以及限制/偏移分页。 限制/偏移功能对应用程序是透明的，无论底层数据库如何。 此功能由 `R2dbcDialect 抽象` 提供支持，以适应不同 SQL 方言之间的差异。

    使用 R2dbcEntityTemplate 选择实体
    Flux<Person> loaded = template.select(query(where("firstname").is("John")),
		Person.class);

    流式 API

    本节介绍流式 API 的使用方法。 考虑以下简单查询：

    Flux<Person> people = template.select(Person.class) (1)
		.all(); (2)
    1 使用带有 select(…) 方法的 Person 会将表结果映射到 Person 结果对象上。
    2 获取 all() 所有行会返回一个不限制结果的 Flux<Person>。

    下面的示例声明了一个更复杂的查询，该查询通过表名指定了表、包含一个 `WHERE` 条件以及一个 `ORDER BY` 子句：

    Mono<Person> first = template.select(Person.class)	(1)
	.from("other_person")
	.matching(query(where("firstname").is("John")			(2)
		.and("lastname").in("Doe", "White"))
	  .sort(by(desc("id"))))						(3)
	.one();											(4)
    1 按名称从表中选择会返回使用给定域类型的行结果。
    2 发出的查询在 firstname 和 lastname 列上声明了 WHERE 条件以过滤结果。
    3 结果可以按单个列名排序，从而生成 ORDER BY 子句。
    4 选择单个结果仅获取一行。 这种消费行的方式期望查询恰好返回一个结果。 如果查询返回多于一个结果，Mono 将抛出 IncorrectResultSizeDataAccessException。
    您可以通过 select(Class<?>) 提供目标类型，直接对结果应用投影。

    您可以通过以下终止方法在检索单个实体和检索多个实体之间进行切换：

    • first()：仅消费第一行，返回一个 Mono。如果查询未返回任何结果，则返回的 Mono 会在不发出对象的情况下完成。

    • one(): 精确消费一行，返回一个 Mono。 如果查询未返回任何结果，则返回的 Mono 在完成时不发射对象。 如果查询返回多于一行，Mono 将异常完成并发射 IncorrectResultSizeDataAccessException。

    • all()：消费所有返回的行并返回一个 Flux。

    • count()：应用计数投影，返回 Mono<Long>。

    • exists()：通过返回 Mono<Boolean> 来指示查询是否产生任何行。

    您可以使用 `select()` 入口点来表达您的 `SELECT` 查询。 生成的 `SELECT` 查询支持常用的子句（如 `WHERE` 和 `ORDER BY`），并支持分页功能。 流式 API 风格允许您链式调用多个方法，同时保持代码易于理解。 为了提高可读性，您可以使用静态导入来避免在创建 `Criteria` 实例时使用 'new' 关键字。

    Criteria 类的方法

    `Criteria` 类提供以下方法，它们均对应于 SQL 运算符：

    • Criteria and (String column)：将具有指定 property 的链式 Criteria 添加到当前 Criteria，并返回新创建的实例。

    • Criteria 或 (String column)：向当前 Criteria 添加一个带有指定 property 的链式 Criteria，并返回新创建的实例。

    • Criteria greaterThan (Object o)：使用 > 运算符创建条件。

    • Criteria greaterThanOrEquals (Object o)：使用 >= 运算符创建条件。

    • Criteria in (Object…​ o)：使用 IN 运算符为可变参数创建条件。

    • Criteria in (Collection<?> collection)：使用集合通过 IN 运算符创建条件。

    • Criteria 是 (Object o)：通过使用列匹配（property = value）创建标准。

    • Criteria isNull ()：使用 IS NULL 运算符创建条件。

    • Criteria isNotNull ()：使用 IS NOT NULL 运算符创建条件。

    • Criteria lessThan (Object o)：使用 < 运算符创建条件。

    • Criteria lessThanOrEquals (Object o)：使用 ⇐ 运算符创建条件。

    • Criteria like (Object o)：使用 LIKE 运算符创建条件，且不进行转义字符处理。

    • Criteria not (Object o)：通过使用 != 运算符创建条件。

    • Criteria notIn (Object…​ o)：使用 NOT IN 运算符为变长参数创建条件。

    • Criteria notIn (Collection<?> collection)：使用集合创建基于 NOT IN 操作符的条件。 您可以在 SELECT、UPDATE 和 DELETE 查询中使用 Criteria。

    插入数据

    您可以使用 `insert()` 入口点来插入数据。

    考虑以下简单的类型化插入操作：

    Mono<Person> insert = template.insert(Person.class)	(1)
		.using(new Person("John", "Doe")); 			(2)
    1 使用带有 into(…) 方法的 Person 会根据映射元数据设置 INTO 表，并准备接受 Person 对象的插入语句。
    2 提供一个标量 Person 对象。或者，您可以提供一个 Publisher 来执行一系列 INSERT 语句。此方法会提取所有非 null 的值并将其插入。

    更新数据

    您可以使用 `update()` 入口点来更新行。 更新数据首先通过接受指定赋值的 `Update`》来指定要更新的表。 它还接受 `Query`》以创建 `WHERE`》子句。

    考虑以下简单的类型化更新操作：

    Person modified = …

		Mono<Long> update = template.update(Person.class)	(1)
				.inTable("other_table")						(2)
				.matching(query(where("firstname").is("John")))		(3)
				.apply(update("age", 42));					(4)
    1更新 Person 对象并基于映射元数据应用映射。
    2通过调用 inTable(…) 方法设置不同的表名。
    3指定一个可转换为 WHERE 子句的查询。
    4应用 Update 对象。 在此情况下，将 age 设置为 42，并返回受影响的行数。

    插入或更新数据

    `R2dbcEntityOperations` 提供了一个 `upsert(instance)` 操作，用于在无需预先检查是否存在的情况下，以单次数据库往返操作持久化实体。该操作执行原生数据库的“插入或更新”（upsert）：当不存在关联主键的匹配行时插入该行，否则则更新它。

    请注意，此操作要求实体实例具有标识符值。此外，还需要支持相应的数据库方言：该功能适用于 PostgreSQL、H2、MySQL、MariaDB、SQL Server、Oracle 和 HSQLDB。

    目前，Upserts 不支持乐观锁。

    上写操作始于通过接受objectToSave来指定要上写的对象。 考虑以下上写操作：

    Person modified = …

		Mono<Person> update = template.upsert(Person.class)	(1)
				.inTable("other_table")						(2)
				.one(modified);
    1 更新 Person 对象，并根据映射元数据应用映射。
    2 提供要执行 upsert 操作的对象。

    删除数据

    您可以使用 `delete()` 入口点来删除行。删除数据始于指定要从中删除的表，并可选地接受一个 `Criteria` 以创建 `WHERE` 子句。

    考虑以下简单的删除操作：

    		Mono<Long> delete = template.delete(Person.class)	(1)
				.from("other_table")						(2)
				.matching(query(where("firstname").is("John")))		(3)
				.all();										(4)
    1 删除Person对象，并根据映射元数据应用映射。
    2 通过调用from(…)方法设置不同的表名。
    3 指定一个可转换为WHERE子句的查询。
    4 执行删除操作并返回受影响的行数。

    使用仓储（Repositories）时，可以通过 `ReactiveCrudRepository.save(…)` 方法保存实体。如果该实体是新的，这将导致对该实体执行插入操作。

    如果该实体不是新的，则对其进行更新。 请注意，实例是否为新的是实例状态的一部分。

    这种方法存在一些明显的缺点。如果只有少数被引用的实体实际发生了变更，那么执行删除和插入操作就是浪费资源。虽然此过程可能并且很可能会得到改进，但 Spring Data R2DBC 所提供的功能确实存在一定的局限性。它无法知晓聚合体的先前状态。因此，任何更新过程都必须从数据库中读取当前数据，并将其转换为传递给 save 方法的实体的状态。

    主键生成

    Spring Data 使用标识符属性来识别实体。也就是说，用于查找或创建针对特定行的语句。实体的 ID 必须使用 Spring Data 的 @Id 注解进行标注。

    当数据库的 ID 列具有自增属性时，在将实体插入数据库后，生成的值会被设置到该实体中。

    如果额外使用 @Sequence 注解标识符属性，则当底层 Dialect 支持序列时，将使用数据库序列来获取 id 的值。

    否则，如果实体是新的且标识符字段的值默认为其初始值，Spring Data 将不会尝试插入这些标识符列的值。也就是说，对于基本类型，该值为0；如果标识符属性使用的是数值包装类型（如Long），则该值为null。

    实体状态检测详细解释了检测实体是新实体还是预期存在于数据库中的策略。

    一个重要的约束是，在保存实体后，该实体不能再是新实体。 请注意，实体是否为新实体是其状态的一部分。 在使用自增列时，这一过程会自动完成，因为 Spring Data 会从 ID 列中获取值来设置 ID。

    乐观锁

    Spring Data 通过在聚合根上标注带有 @Version 的数值属性来支持乐观锁。每当 Spring Data 保存具有此类版本属性的聚合时，会发生以下两件事：

    • 聚合根的更新语句将包含一个 WHERE 子句，用于检查数据库中存储的版本号是否确实未发生变化。

    • 如果并非如此，将抛出OptimisticLockingFailureException异常。

    此外，实体和数据库中的版本号属性都会增加，因此并发操作会检测到该变更，并在适用时抛出上述描述的OptimisticLockingFailureException异常。

    该过程同样适用于插入新聚合体，其中 `null` 或 `0` 版本表示一个新实例，随后递增的实例标记则表明该实例不再为新，这使得该方法在处理 ID 在对象构建期间生成的情况（例如使用 UUID 时）尤为有效。

    删除期间同样适用版本检查，但版本号不会增加。

    @Table
class Person {

    @Id Long id;
    String firstname;
    String lastname;
    @Version Long version;
}

R2dbcEntityTemplate template = …;

Mono<Person> daenerys = template.insert(new Person("Daenerys"));                      (1)

Person other = template.select(Person.class)
                 .matching(query(where("id").is(daenerys.getId())))
                 .first().block();                                                    (2)

daenerys.setLastname("Targaryen");
template.update(daenerys);                                                            (3)

template.update(other).subscribe(); // emits OptimisticLockingFailureException        (4)
    1 最初插入行。version 被设置为 0。
    2 加载刚刚插入的行。version 仍为 0。
    3 使用 version = 0 更新该行。设置 lastname 并将 version 提升至 1。
    4 尝试更新之前加载的行，该行仍具有 version = 0。操作失败并抛出 OptimisticLockingFailureException，因为当前的 version 为 1。
