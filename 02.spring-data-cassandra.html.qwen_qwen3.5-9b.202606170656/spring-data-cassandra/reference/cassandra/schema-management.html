    架构管理

    Apache Cassandra 是一个需要在任何数据交互之前定义模式的存储系统。 Spring Data for Apache Cassandra 可以协助您创建模式。

    CQL 规范

    CQL 规范是一种抽象表示，用于描述 CQL DDL 操作，例如创建表或删除键空间。 以下 CQL 对象类型提供相应的规范：

    • Keyspace

    • Table

    • Index

    • 用户定义类型

    Cassandra 的变体可以支持物化视图、用户定义函数、角色以及更多对象类型。 Spring Data for Apache Cassandra 仅提供上述类型的规范。

    这些可以通过流式接口用于创建、修改和删除 CQL 对象。SpecificationBuilder 是构建此类规范类的入口点。 您可以在稍后使用 CqlGenerator.toCql(…) 轻松从规范类生成 CQL。

    请参照以下示例，创建键空间（keyspace）、表（table）和索引（index）的创建规范。

    示例 1：指定 Cassandra 键空间
    Java
    CqlSpecification createKeyspace = SpecificationBuilder.createKeyspace("my_keyspace")
		.with(KeyspaceOption.REPLICATION, KeyspaceAttributes.newSimpleReplication())
		.with(KeyspaceOption.DURABLE_WRITES, true);

// results in CREATE KEYSPACE my_keyspace WITH replication = {'class': 'SimpleStrategy', 'replication_factor': '1'} AND durable_writes = true
String cql = CqlGenerator.toCql(createKeyspace);
    示例 2：指定 Cassandra 表
    Java
    CreateTableSpecification createTable = CreateTableSpecification.createTable("my_table")
		.partitionKeyColumn("last_name", DataTypes.TEXT)
		.partitionKeyColumn("first_name", DataTypes.TEXT)
		.column("age", DataTypes.INT);

// results in CREATE TABLE my_table (last_name text, first_name text, age int, PRIMARY KEY(last_name, first_name))
String cql = CqlGenerator.toCql(createTable);
    示例 3：指定 Cassandra 索引
    Java
    CreateIndexSpecification spec = SpecificationBuilder.createIndex()
		.tableName("mytable").keys().columnName("column");

// results in CREATE INDEX ON mytable (KEYS(column))
String cql = CqlGenerator.toCql(createTable);

    您可以结合规范与配置 API 来定义键空间创建和模式操作。

    命名空间与生命周期脚本

    首先，需要创建一个 Cassandra 键空间（keyspace）。 键空间是共享相同复制因子和复制策略的表的逻辑分组。 键空间管理位于 `CqlSession` 配置中，包含 `KeyspaceSpecification` 以及启动和关闭 CQL 脚本的执行功能。

    声明带有规格说明的键空间，可以创建和删除该键空间。 它从规格说明中派生 CQL，因此您无需手动编写 CQL。 以下示例使用 XML 指定一个 Cassandra 键空间：

    示例 4：指定 Cassandra 键空间
    Java
    @Configuration
public class CreateKeyspaceConfiguration extends AbstractCassandraConfiguration implements BeanClassLoaderAware {

	@Override
	protected List<CreateKeyspaceSpecification> getKeyspaceCreations() {

		CreateKeyspaceSpecification specification = SpecificationBuilder.createKeyspace("my_keyspace")
				.with(KeyspaceOption.DURABLE_WRITES, true)
				.withNetworkReplication(DataCenterReplication.of("foo", 1), DataCenterReplication.of("bar", 2));

		return Arrays.asList(specification);
	}

	@Override
	protected List<DropKeyspaceSpecification> getKeyspaceDrops() {
		return Arrays.asList(DropKeyspaceSpecification.dropKeyspace("my_keyspace"));
	}

	// ...
}
    XML
    <?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xmlns:cassandra="http://www.springframework.org/schema/data/cassandra"
  xsi:schemaLocation="
    http://www.springframework.org/schema/data/cassandra
    https://www.springframework.org/schema/data/cassandra/spring-cassandra.xsd
    http://www.springframework.org/schema/beans
    https://www.springframework.org/schema/beans/spring-beans.xsd">

    <cassandra:session>

        <cassandra:keyspace action="CREATE_DROP" durable-writes="true" name="my_keyspace">
            <cassandra:replication class="NETWORK_TOPOLOGY_STRATEGY">
              <cassandra:data-center name="foo" replication-factor="1" />
              <cassandra:data-center name="bar" replication-factor="2" />
            </cassandra:replication>
      </cassandra:keyspace>

    </cassandra:session>
</beans>
    创建键空间可实现快速引导，无需外部键空间管理。这在某些场景下非常有用，但需谨慎使用。在应用程序关闭时删除键空间会移除该键空间及其表中所有数据。

    初始化 SessionFactory

    org.springframework.data.cassandra.core.cql.session.init 包提供了初始化现有 SessionFactory 的支持。 您可能有时需要初始化运行在某个服务器上的键空间。

    初始化键空间

    您可以在配置的键空间中，在 `CqlSession` 初始化及关闭时执行任意 CQL，如下面的 Java 配置示例所示：

    Java
    @Configuration
public class KeyspacePopulatorConfiguration extends AbstractCassandraConfiguration {

	@Nullable
	@Override
	protected KeyspacePopulator keyspacePopulator() {
		return new ResourceKeyspacePopulator(new ClassPathResource("com/foo/cql/db-schema.cql"),
				new ClassPathResource("com/foo/cql/db-test-data.cql"));
	}

	@Nullable
	@Override
	protected KeyspacePopulator keyspaceCleaner() {
		return new ResourceKeyspacePopulator(scriptOf("DROP TABLE my_table;"));
	}

	// ...
}
    XML
    <cassandra:initialize-keyspace session-factory-ref="cassandraSessionFactory">
    <cassandra:script location="classpath:com/foo/cql/db-schema.cql"/>
    <cassandra:script location="classpath:com/foo/cql/db-test-data.cql"/>
</cassandra:initialize-keyspace>

    前面的示例针对键空间运行了两个指定的脚本。第一个脚本创建模式，第二个脚本用测试数据集填充表。脚本位置也可以是带有通配符的模式，采用 Spring 中用于资源的常规 Ant 风格（例如 classpath*:/com/foo/**/cql/*-data.cql）。如果使用模式，则按 URL 或文件名的字典顺序运行这些脚本。

    Keyspace 初始化器的默认行为是无条件地运行所提供的脚本。这并不总是您想要的——例如，如果您在已包含测试数据的键空间中运行这些脚本。遵循常见的模式（如前所示）先创建表再插入数据，可以降低意外删除数据的可能性。如果表已存在，第一步将会失败。

    然而，为了更灵活地控制现有数据的创建与删除，XML 命名空间提供了一些额外的选项。 第一个选项是一个用于开启或关闭初始化的标志。 您可以根据环境设置此标志（例如从系统属性或环境 Bean 中读取布尔值）。 以下示例展示了如何从系统属性中获取该值：

    <cassandra:initialize-keyspace session-factory-ref="cassandraSessionFactory"
    enabled="#{systemProperties.INITIALIZE_KEYSPACE}">    (1)
    <cassandra:script location="..."/>
</cassandra:initialize-database>
    1 从名为INITIALIZE_KEYSPACE的系统属性中获取enabled的值。

    控制现有数据处理方式的第二种选项是更加容忍错误。为此，您可以控制初始化器忽略从脚本中执行的 CQL 语句时某些错误的能力，如下例所示：

    Java
    @Configuration
public class KeyspacePopulatorFailureConfiguration extends AbstractCassandraConfiguration {

	@Nullable
	@Override
	protected KeyspacePopulator keyspacePopulator() {

		ResourceKeyspacePopulator populator = new ResourceKeyspacePopulator(
				new ClassPathResource("com/foo/cql/db-schema.cql"));

		populator.setIgnoreFailedDrops(true);

		return populator;
	}

	// ...
}
    XML
    <cassandra:initialize-keyspace session-factory-ref="cassandraSessionFactory" ignore-failures="DROPS">
    <cassandra:script location="..."/>
</cassandra:initialize-database>

    在前面的示例中，我们表示预期有时脚本会在空的键空间中运行，而脚本中包含一些 `DROP` 语句，因此这些语句将会失败。 所以失败的 CQL `DROP` 语句将被忽略，但其他类型的失败将引发异常。 如果您不想使用支持 `DROP … IF EXISTS`（或类似语法）的功能，但又希望在重新创建数据之前无条件地删除所有测试数据，这种情况就非常有用。 在这种情况下，第一个脚本通常是一组 `DROP` 语句，随后跟着一组 `CREATE` 语句。

    `ignore-failures` 选项可设置为 `NONE`（默认值）、`DROPS`（忽略失败的投递）或 `ALL`（忽略所有失败）。

    每个语句之间应使用;分隔；如果脚本中完全没有;字符，则使用换行符分隔。您可以全局控制此设置，或针对每个脚本单独控制，如下例所示：

    Java
    @Configuration
public class SessionFactoryInitializerConfiguration extends AbstractCassandraConfiguration {

	@Bean
	SessionFactoryInitializer sessionFactoryInitializer(SessionFactory sessionFactory) {

		SessionFactoryInitializer initializer = new SessionFactoryInitializer();
		initializer.setSessionFactory(sessionFactory);

		ResourceKeyspacePopulator populator1 = new ResourceKeyspacePopulator();
		populator1.setSeparator(";");
		populator1.setScripts(new ClassPathResource("com/myapp/cql/db-schema.cql"));

		ResourceKeyspacePopulator populator2 = new ResourceKeyspacePopulator();
		populator2.setSeparator("@@");
		populator2.setScripts(new ClassPathResource("classpath:com/myapp/cql/db-test-data-1.cql"), //
				new ClassPathResource("classpath:com/myapp/cql/db-test-data-2.cql"));

		initializer.setKeyspacePopulator(new CompositeKeyspacePopulator(populator1, populator2));

		return initializer;
	}

	// ...
}
    XML
    <cassandra:initialize-keyspace session-factory-ref="cassandraSessionFactory" separator="@@">
    <cassandra:script location="classpath:com/myapp/cql/db-schema.cql" separator=";"/>
    <cassandra:script location="classpath:com/myapp/cql/db-test-data-1.cql"/>
    <cassandra:script location="classpath:com/myapp/cql/db-test-data-2.cql"/>
</cassandra:initialize-keyspace>

    在此示例中，两个 `test-data` 脚本使用 `@@` 作为语句分隔符，而只有 `db-schema.cql` 使用 `;`。此配置指定默认分隔符为 `@@`，并针对 `db-schema` 脚本覆盖该默认设置。

    如果您需要比 XML 命名空间提供的更多控制，您可以直接使用SessionFactoryInitializer，并将其作为组件定义在您的应用程序中。

    初始化依赖于键空间的其他组件

    大多数应用程序（那些在 Spring 上下文启动之后才使用数据库的应用）可以无需额外配置即可使用数据库初始化器。 如果您的应用程序不属于此类，您可能需要阅读本节的其余部分。

    数据库初始化器依赖于一个 SessionFactory 实例，并执行其初始化回调中提供的脚本（类似于 XML bean 定义中的init-method、组件中的@PostConstruct方法，或实现了InitializingBean接口的组件中的afterPropertiesSet()方法）。 如果其他 bean 也依赖于相同的数据源并在初始化回调中使用会话工厂，则可能会出现问题，因为此时数据尚未初始化。 一个常见的例子是缓存：它在启动时急切初始化，并从数据库加载数据。

    为了解决此问题，您有两个选择：将缓存初始化策略推迟到更晚的阶段执行，或确保键空间初始化器首先被初始化。

    如果您的应用程序由您自行控制，则更改缓存初始化策略可能较为简单；否则则不然。 以下是一些关于如何实现此目标的建议：

    • 使缓存在使用时进行惰性初始化，从而提升应用程序的启动速度。

    • 您的缓存或负责初始化缓存的独立组件是否实现了 `Lifecycle` 或 `SmartLifecycle` 接口。当应用程序上下文启动时，您可以通过设置其 `autoStartup` 标志来自动启动一个 `SmartLifecycle` 组件，也可以通过在外部上下文中调用 `ConfigurableApplicationContext.start()` 来手动启动一个 `Lifecycle` 组件。

    • 使用 Spring 的 `ApplicationEvent` 或类似的自定义观察者机制来触发缓存初始化。当上下文准备就绪（即所有 Bean 初始化完成后），上下文总是会发布 `ContextRefreshedEvent`，因此这通常是一个非常有用的钩子（`SmartLifecycle` 默认就是如此工作的）。

    确保键空间初始化器首先被初始化也可以很简单。 以下是一些关于如何实现此功能的建议：

    • 依赖 Spring `BeanFactory` 的默认行为，即按注册顺序初始化 Bean。您可以通过采用在 XML 配置中使用一组 `<import/>` 元素的常见做法来轻松实现这一点，该做法用于编排您的应用程序模块，并确保将数据库和数据库初始化部分列在最前面。

    • 将使用 `SessionFactory` 的业务组件与其分离，并通过将它们置于不同的 `ApplicationContext`》实例中来控制启动顺序（例如，父上下文包含 `SessionFactory`，子上下文包含业务组件）。这种结构在 Spring Web 应用程序中很常见，但也可以更广泛地应用。

    • 使用表和自定义类型中的模式管理功能，利用 Spring Data Cassandra 内置的模式生成器初始化键空间。

    表和自定义类型

    Spring Data for Apache Cassandra 采用与您的数据模型相匹配的映射实体类来处理数据访问。您可以使用这些实体类来创建 Cassandra 表规格和用户类型定义。

    Schema 的创建与通过 SchemaAction 初始化 CqlSession 相关联。 支持以下操作：

    • SchemaAction.NONE：不创建或删除任何表或类型。 这是默认设置。

    • SchemaAction.CREATE：从带有 @Table 注解的实体和带有 @UserDefinedType 注解的类型创建表、索引和用户定义类型。如果尝试创建该类型时已存在表或类型，则会引发错误。

    • SchemaAction.CREATE_IF_NOT_EXISTS：类似于SchemaAction.CREATE，但应用了IF NOT EXISTS。现有的表或类型不会引发任何错误，但可能会保持陈旧状态。

    • SchemaAction.RECREATE：删除并重新创建已知正在使用的表和类型。 未在应用程序中配置的表和类型不会被删除。

    • SchemaAction.RECREATE_DROP_UNUSED：删除所有表和类型，仅重新创建已知的表和类型。

    SchemaAction.RECREATE 和 SchemaAction.RECREATE_DROP_UNUSED 会删除您的表并丢失所有数据。 RECREATE_DROP_UNUSED 还会删除应用程序未知的表和类型。

    启用表和用户定义类型以进行架构管理

    基于元数据的映射 介绍了使用约定和注解进行对象映射的方法。为了防止不需要的类被创建为表或类型，模式管理仅对标注了 @Table 的实体以及标注了 @UserDefinedType 的用户定义类型生效。 实体是通过扫描类路径发现的。 实体扫描需要一个或多个基础包。 使用 TupleValue 的元组类型列不提供任何类型详细信息。 因此，您必须用 @CassandraType(type = TUPLE, typeArguments = …) 注解此类列属性，以指定所需的列类型。

    以下示例展示了如何在 XML 配置中指定实体基础包：

    示例 5：指定实体基础包
    Java
    @Configuration
public class EntityBasePackagesConfiguration extends AbstractCassandraConfiguration {

	@Override
	public String[] getEntityBasePackages() {
		return new String[] { "com.foo", "com.bar" };
	}

	// ...
}
    XML
    <?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xmlns:cassandra="http://www.springframework.org/schema/data/cassandra"
  xsi:schemaLocation="
    http://www.springframework.org/schema/data/cassandra
    https://www.springframework.org/schema/data/cassandra/spring-cassandra.xsd
    http://www.springframework.org/schema/beans
    https://www.springframework.org/schema/beans/spring-beans.xsd">

    <cassandra:mapping entity-base-packages="com.foo,com.bar"/>
</beans>
