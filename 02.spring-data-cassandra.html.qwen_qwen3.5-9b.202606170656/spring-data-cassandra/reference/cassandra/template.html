    持久实体

    位于 `org.springframework.data.cassandra` 包中的 `CassandraTemplate` 类（及其响应式变体 `ReactiveCassandraTemplate`）是 Spring 对 Cassandra 支持的核心类，提供了丰富的功能集以与数据库进行交互。该模板提供了创建、更新、删除和查询 Cassandra 的便捷操作，并在您的领域对象与 Cassandra 表中的行之间建立映射关系。

    配置完成后，模板实例是线程安全的，可在多个实例中重复使用。

    Cassandra 行与应用领域类之间的映射是通过委托给 CassandraConverter 接口的实现来完成的。Spring 提供了一个默认实现 MappingCassandraConverter，但您也可以编写自己的自定义转换器。有关更详细的信息，请参阅Cassandra 转换部分。

    `CassandraTemplate` 类实现了 `CassandraOperations` 接口，而其响应式变体 `ReactiveCassandraTemplate` 则实现了 `ReactiveCassandraOperations` 接口。 在尽可能多的情况下，`[Reactive]CassandraOperations` 上的方法命名与 Cassandra 中可用的方法保持一致，以便让熟悉 Cassandra 的开发者能够轻松理解该 API。

    例如，您可以找到诸如select、insert、delete和update等方法。 设计目标是尽可能简化在基础 Cassandra 驱动与[Reactive]CassandraOperations之间进行切换的过程。 这两个 API 之间的一个主要区别在于，CassandraOperations可以传递领域对象，而不是 CQL 和查询对象。

    引用 [Reactive]CassandraTemplate 实例上操作的首选方式是通过 [Reactive]CassandraOperations 接口。

    [Reactive]CassandraTemplate 使用的默认转换器实现是 MappingCassandraConverter。 虽然 MappingCassandraConverter 可以使用额外的元数据来指定对象到行的映射，但它也可以利用字段和表名映射的一些约定，来转换不包含额外元数据的对象。 这些约定以及映射注解的使用方式，在“映射”章节中有详细说明。

    [Reactive]CassandraTemplate 的另一个核心特性是将 Cassandra Java 驱动抛出的异常转换为 Spring 可移植的数据访问异常层次结构。有关更多信息，请参阅异常转换部分。

    模板 API 具有不同的执行模型类型。 基本的 `CassandraTemplate` 使用阻塞（命令式同步）执行模型。 您可以使用 `AsyncCassandraTemplate` 进行异步执行，并通过 `CompletableFuture` 实例进行同步；或者使用 `ReactiveCassandraTemplate` 进行响应式执行。

    Instantiating CassandraTemplate

    `CassandraTemplate` 应始终配置为 Spring Bean，尽管我们之前展示了一个可以直接实例化它的示例。然而，由于我们假设的是构建 Spring 模块的上下文，因此我们假定存在 Spring 容器。

    获取 `CassandraTemplate` 有两种方式，具体取决于您加载 Spring `ApplicationContext` 的方式：

    • Autowiring

    • 使用 ApplicationContext 查找 Bean

    Autowiring

    您可以将 [Reactive]CassandraOperations 自动注入到您的项目中，示例如下：

    • Imperative

    • Reactive

    @Autowired
private CassandraOperations cassandraOperations;
    @Autowired
private ReactiveCassandraOperations reactiveCassandraOperations;

    与所有 Spring 自动装配一样，这假设在 `ApplicationContext` 中只有一个类型为 `[Reactive]CassandraOperations` 的 Bean。 如果您有多个 `[Reactive]CassandraTemplate` Bean（例如在同一项目中处理多个 keyspace 时），则可以使用 `@Qualifier` 注解来指定要自动装配的 Bean。

    • Imperative

    • Reactive

    @Autowired
@Qualifier("keyspaceOneTemplateBeanId")
private CassandraOperations cassandraOperations;
    @Autowired
@Qualifier("keyspaceOneTemplateBeanId")
private ReactiveCassandraOperations reactiveCassandraOperations;

    使用 ApplicationContext 进行 Bean 查找

    此外，还可以从ApplicationContext中查找[Reactive]CassandraTemplatebean，示例如下：

    • Imperative

    • Reactive

    CassandraOperations cassandraOperations = applicationContext.getBean("cassandraTemplate", CassandraOperations.class);
    ReactiveCassandraOperations cassandraOperations = applicationContext.getBean("ReactiveCassandraOperations", ReactiveCassandraOperations.class);

    查询行

    您可以使用Query和Criteria类来表达查询，这些类的名称反映了原生 Cassandra 谓词操作符的名称，例如lt、lte、is等。

    `Query` 和 `Criteria` 类采用流式 API 风格，使您可以轻松地将多个方法条件和查询串联起来，同时保持代码易于理解。在 Java 中创建 `Query` 和 `Criteria` 实例时，使用静态导入可以提高可读性。

    查询表中的行

    在前面的章节中，我们了解了如何使用 [Reactive]CassandraTemplate 上的 selectOneById 方法来检索单个对象。这样做会返回一个单一的领域对象。我们也可以查询一组行，并将其作为领域对象的列表返回。假设我们有多个 Person 对象，其姓名和年龄值以行的形式存储在表中，并且每个人都有一个账户余额，那么我们可以使用以下代码运行查询：

    使用 `[Reactive]CassandraTemplate` 查询行数据

    • Imperative

    • Reactive

    import static org.springframework.data.cassandra.core.query.Criteria.where;
import static org.springframework.data.cassandra.core.query.Query.query;

…

List<Person> result = cassandraTemplate.select(query(where("age").is(50))
  .and(where("balance").gt(1000.00d)).withAllowFiltering(), Person.class);
    import static org.springframework.data.cassandra.core.query.Criteria.where;
import static org.springframework.data.cassandra.core.query.Query.query;

…

Flux<Person> result = reactiveCassandraTemplate.select(query(where("age").is(50))
  .and(where("balance").gt(1000.00d)).withAllowFiltering(), Person.class);

    `select`、`selectOne` 和 `stream` 方法均接受一个 `Query` 对象作为参数。该对象定义了执行查询时所使用的条件和选项。条件是通过使用名为 `where` 的静态工厂方法来实例化的一个新 `Criteria` 对象来指定的。我们建议使用静态导入 `org.springframework.data.cassandra.core.query.Criteria.where` 和 `Query.query`，以使查询更易读。

    该查询应返回符合指定条件的 Person 对象列表。 Criteria 类包含以下方法，分别对应 Apache Cassandra 提供的运算符：

    Criteria 类的方法

    • CriteriaDefinition gt (Object value)：使用 > 运算符创建条件。

    • CriteriaDefinition gte (Object value)：使用 >= 运算符创建条件。

    • CriteriaDefinition in (Object…​ values)：使用 IN 运算符为变长参数创建条件。

    • CriteriaDefinition in (Collection<?> collection)：使用集合通过 IN 操作符创建条件。

    • CriteriaDefinition 是 (Object value)：通过字段匹配（column = value）创建条件。

    • CriteriaDefinition lt (Object value)：使用 < 运算符创建条件。

    • CriteriaDefinition lte (Object value)：使用 ⇐ 运算符创建条件。

    • CriteriaDefinition like (Object value)：使用 LIKE 运算符创建条件。

    • CriteriaDefinition 包含 (Object value)：使用 CONTAINS 运算符创建条件。

    • CriteriaDefinition 的 containsKey (Object key)：使用 CONTAINS KEY 运算符创建条件。

    Criteria 在创建后是不可变的。

    Query 类的方法

    `Query` 类包含一些额外的方法，可用于为查询提供选项：

    • Query 通过 (CriteriaDefinition…​ criteria) 创建：用于创建 Query 对象。

    • Query 与 (CriteriaDefinition criteria)：用于向查询添加附加条件。

    • Query columns (Columns columns)：用于定义要包含在查询结果中的列。

    • Query limit (Limit limit)：用于将返回结果的大小限制为提供的 limit（用于 SELECT 语句的限制）。

    • Query limit (long limit)：用于将返回结果的大小限制为提供的 limit（用于 SELECT 语句的结果限制）。

    • Query pageRequest (Pageable pageRequest)：用于将 Sort、PagingState 和 fetchSize 与查询关联（用于分页）。

    • 查询 分页状态 (CassandraScrollPosition 分页状态)：用于将 CassandraScrollPosition 与查询关联（用于分页）。

    • Query pagingState (ByteBuffer pagingState)：用于将原始 ByteBuffer 与查询关联（用于分页）。

    • Query queryOptions (QueryOptions queryOptions)：用于将 QueryOptions 与查询关联。

    • Query sort (Sort sort)：用于为结果提供排序定义。

    • Query withAllowFiltering ()：用于渲染带有 ALLOW FILTERING 的查询。

    `Query` 在创建后是不可变的。 调用方法会生成新的不可变（中间）`Query` 对象。

    查询行的方法

    `Query` 类包含以下用于返回行的方法：

    • List<T> select (Query query, Class<T> entityClass): 从表中查询类型为 T 的对象列表。

    • T selectOne (Query query, Class<T> entityClass)：从表中查询类型为 T 的单个对象。

    • Slice<T> slice (Query query, Class<T> entityClass): 开始或继续分页，从表中查询类型为 T 的对象的 Slice。

    • Stream<T> stream (Query query, Class<T> entityClass)：从表中查询类型为 T 的对象的流。

    • List<T> select (String cql, Class<T> entityClass): 通过提供 CQL 语句，从表中查询类型为 T 的对象的临时列表。

    • T selectOne (String cql, Class<T> entityClass)：通过提供 CQL 语句，从表中查询单个类型为 T 的对象的临时查询。

    • Stream<T> stream (String cql, Class<T> entityClass)：通过提供 CQL 语句，从表中查询类型为 T 的对象的流式结果。

    查询方法必须指定返回的目标类型。

    列投影

    当未指定 `Query.columns(…)` 时，将选择所有列（即执行 `SELECT * FROM …`），以便通过 `@Value(…)` 和开放投影访问实体中的所有可用列。

    如果您向查询提供更多信息（例如，在使用通过Fluent 模板 API的封闭 DTO 或接口投影时），列选择将受到限制。

    您可以为每个 `CassandraTemplate` 实例在 `StatementFactory` 上配置默认的 `ProjectionFunction`，以影响默认列的选择：

    CassandraTemplate template = …;
template.getStatementFactory().setProjectionFunction(ProjectionFunction.mappedProperties());

    通过显式指定 `ProjectionFunctions.mappedProperties()` 中的列，将把选择范围限制在实体类型的映射属性上；其显式的特性会在执行查询时针对实体映射验证查询，任何不期望的架构变更都可通过异常显现。 请注意，任何未映射的属性对 `@Value(…)` 均不可用。

    通过显式使用 `Query.columns(…)` 进行列选择，将绕过由投影函数执行的 `Columns` 计算。

    流式模板 API

    [Reactive]CassandraOperations 接口是进行更底层 Apache Cassandra 交互时的核心组件之一。 它提供了广泛的方法集。 每个方法都有多个重载版本。 其中大多数覆盖了 API 的可选（可为 null）部分。

    FluentCassandraOperations 及其响应式变体 ReactiveFluentCassandraOperations 为 [Reactive]CassandraOperations 的常用方法提供了更窄的接口，从而提供更可读、更具流畅性的 API。 入口点（query(…)、insert(…)、update(…) 和 delete(…)）采用基于所执行操作的命名方案，符合自然命名规范。 从入口点开始，该 API 仅提供上下文相关的方法，引导开发者调用实际执行操作的 [Reactive]CassandraOperations 终止方法。 以下示例展示了流畅式 API：

    • Imperative

    • Reactive

    List<SWCharacter> all = ops.query(SWCharacter.class)
  .inTable("star_wars")                        (1)
  .all();
    1 如果 SWCharacter 使用 @Table 定义了表名，或者直接使用类名作为表名没有问题，则跳过此步骤 
    Flux<SWCharacter> all = ops.query(SWCharacter.class)
  .inTable("star_wars")                        (1)
  .all();
    1 如果 SWCharacter 使用 @Table 定义了表名，或者直接使用类名作为表名没有问题，则跳过此步骤

    如果 Cassandra 表中的实体类型不同，例如在 SWCharacters 表中包含一个 Jedi 实体，您可以使用不同的类型来映射查询结果。 您可以使用 as(Class<?> targetType) 将结果映射到不同的目标类型，而 query(Class<?> entityType) 仍然适用于查询和表名。 以下示例展示了如何使用 query 和 as 方法：

    • Imperative

    • Reactive

    List<Jedi> all = ops.query(SWCharacter.class)    (1)
  .as(Jedi.class)                                (2)
  .matching(query(where("jedi").is(true)))
  .all();
    1 查询字段映射到 `SWCharacter` 类型。 2 结果行被映射为 `Jedi`。
    Flux<Jedi> all = ops.query(SWCharacter.class)    (1)
  .as(Jedi.class)                                (2)
  .matching(query(where("jedi").is(true)))
  .all();
    1 查询字段映射到 `SWCharacter` 类型。 2 结果行被映射为 `Jedi`。
    您可以通过仅通过 as(Class<?>) 提供 interface 类型，直接将投影 (Projections)应用于生成的文档。

    终止方法（`first()`、`one()`、`all()` 和 `stream()`）用于处理在检索单个实体与检索多个实体（如作为 `List` 或 `Stream` 等）之间的切换。

    新的流式模板 API 方法（即 `query(…)`、`insert(…)`、`update(…)` 和 `delete(…)`）使用有效的线程安全支持对象来组合 CQL 语句。然而，这种设计基于各种 CQL 语句组件的最终字段以及可变性构建，因此会带来额外的年轻代 JVM 堆开销。在可能插入或删除大量对象时（例如在循环中），请格外小心。

    向量搜索查询

    投影是查询以不同于实体形式返回的数据的基础。 虽然 Cassandra 的主要用例遵循键值模型——存储您检索的内容——但向量搜索则不同。 运行向量搜索查询通常会产生聚合或类似报表的结果集。 典型的查询会返回某种形式的内容（例如 `text` 列）及其与真实向量的得分（或距离）。

    考虑以下领域模型：

    示例 1。向量搜索模型
    @Table
class Comments {

	@Id UUID id;
	String comment;

	@VectorType(dimensions = 5)
	@SaiIndexed Vector vector;
}

class CommentSearch {

	String comment;

	float similarity;
}

    `Comments` 是定义向量列和 `comment` 列的领域类型。

    运行向量搜索需要使用ANN排序，并通常定义一个相似度函数来确定其与给定向量的距离。

    示例 2：使用向量搜索
    Columns columns = Columns.from("comment")                                                (1)
                     .select("vector", builder -> builder.similarity(vector)
                                                         .cosine().as("similarity"));    (2)

Query query = Query.select(columns)
                   .limit(3)
                   .sort(VectorSort.ann("vector", vector));                              (3)

template.query(Comments.class)
        .as(CommentSearch.class)                                                         (4)
        .matching(query)
        .all();
    1 选择要查询的列。 2 包含对 `similarity_cosine(vector, […])` 的函数调用。`Columns.select(…)` 使用选择器构建自定义器来配置实际的选择。确保声明一个别名以将结果映射到 `CommentSearch.similarity`，因为结果映射使用列名。 3 使用 `VectorSort.ann(…)` 定义相对于给定向量的排序顺序。 4 定义目标类型以将结果映射到该类型。`CommentSearch` 类型是结果投影类型，定义了映射结果的列。

    保存、更新和删除行

    [Reactive]CassandraTemplate 提供了一种简单的方法，用于保存、更新和删除您的领域对象，并将这些对象映射到 Cassandra 中管理的表。

    类型映射

    Spring Data for Apache Cassandra 依赖 DataStax Java 驱动程序的 `CodecRegistry` 来确保类型支持。 当添加或更改类型时，Spring Data for Apache Cassandra 模块将继续正常工作，无需进行任何修改。 请参阅 CQL 数据类型 以及"数据映射与类型转换"以获取当前的类型映射矩阵。

    插入和更新行的方法

    [Reactive]CassandraTemplate 提供了多种便捷的方法来保存和插入对象。 若需对转换过程进行更精细的控制，您可以将 Spring Converter 实例注册到 MappingCassandraConverter 中（例如 Converter<Row, Person>）。

    INSERT 操作与 UPDATE 操作的差异在于，INSERT 操作不会插入 null 值。

    使用 `INSERT` 操作的简单情况是保存一个 POJO。 在这种情况下，表名由简单的类名决定（而非完全限定类名）。 可以通过映射元数据覆盖用于存储对象的表。

    插入或更新时，必须设置 `id` 属性。 Apache Cassandra 没有生成 ID 的机制。

    以下示例使用保存操作并检索其内容：

    使用 `[Reactive]CassandraTemplate` 插入和检索对象

    • Imperative

    • Reactive

    import static org.springframework.data.cassandra.core.query.Criteria.where;
import static org.springframework.data.cassandra.core.query.Query.query;
…

Person bob = new Person("Bob", 33);
cassandraTemplate.insert(bob);

Person queriedBob = cassandraTemplate.selectOneById(query(where("age").is(33)), Person.class);
    import static org.springframework.data.cassandra.core.query.Criteria.where;
import static org.springframework.data.cassandra.core.query.Query.query;
…

Person bob = new Person("Bob", 33);
cassandraTemplate.insert(bob);

Mono<Person> queriedBob = reactiveCassandraTemplate.selectOneById(query(where("age").is(33)), Person.class);

    您可以使用以下操作进行插入和保存：

    • void insert (Object objectToSave)：将对象插入到 Apache Cassandra 表中。

    • WriteResult insert (Object objectToSave, InsertOptions options)：将对象插入到 Apache Cassandra 表中并应用 InsertOptions。

    您可以使用以下更新操作：

    • void update (Object objectToSave)：更新 Apache Cassandra 表中的对象。

    • WriteResult update (Object objectToSave, UpdateOptions options)：更新 Apache Cassandra 表中的对象并应用 UpdateOptions。

    您还可以采用传统方式，自行编写 CQL 语句，如下例所示：

    • Imperative

    • Reactive

    String cql = "INSERT INTO person (age, name) VALUES (39, 'Bob')";

cassandraTemplate().getCqlOperations().execute(cql);
    String cql = "INSERT INTO person (age, name) VALUES (39, 'Bob')";

Mono<Boolean> applied = reactiveCassandraTemplate.getReactiveCqlOperations().execute(cql);

    在使用InsertOptions和UpdateOptions时，您还可以配置其他选项，例如TTL、一致性级别和轻量级事务。

    我的行被插入到哪个表中？

    您可以通过两种方式来管理用于操作表的表名。 默认表名是将简单的类名转换为以小写字母开头的形式。因此，com.example.Person 类的实例将存储在 person 表中。 第二种方式是在 @Table 注解中指定表名。

    在批处理中插入、更新和删除单个对象

    Cassandra 协议支持通过批处理一次性插入多行数据。

    [Reactive]CassandraTemplate 接口中的以下方法支持此功能：

    • batchOps：创建一个新的 [Reactive]CassandraBatchOperations 以填充批处理操作。

    [Reactive]CassandraBatchOperations

    • insert：接受单个对象、数组（可变参数）或对象的 Iterable 以执行插入操作。

    • update：接受单个对象、数组（可变参数）或对象的 Iterable 集合以进行更新。

    • delete：接受单个对象、数组（可变参数）或对象的 Iterable 以执行删除操作。

    • withTimestamp：为批次应用 TTL。

    • execute：执行批处理。

    更新表中的行

    若要更新，您可以选择更新多行。

    以下示例展示了通过添加一次性 50.00 美元奖金到余额中，使用 `+` 赋值运算符来更新单个账户对象：

    使用 `[Reactive]CasandraTemplate` 更新行数据

    • Imperative

    • Reactive

    import static org.springframework.data.cassandra.core.query.Criteria.where;
import org.springframework.data.cassandra.core.query.Query;

    除了前面讨论的Query，我们还通过Update对象提供更新定义。 Update类提供了与Apache Cassandra中可用的更新赋值相匹配的方法。

    大多数方法会返回 `Update` 对象，以便为代码风格提供流式 API。

    执行行更新的命令

    update 方法可以更新行，如下所示：

    • boolean update (Query query, Update update, Class<?> entityClass)：更新 Apache Cassandra 表中的选定对象。

    Update 类的方法

    `Update` 类可以配合少量“语法糖”使用，因为其方法设计为可链式调用。此外，您可以利用静态方法 `public static Update update(String key, Object value)` 以及静态导入来快速创建新的 `Update` 实例。

    `Update` 类具有以下方法：

    • AddToBuilder addTo (String columnName) AddToBuilder entry-point:

      • 更新 prepend(Object value)：通过使用 + 更新赋值操作符，将集合值添加到现有集合的开头。

      • 更新 prependAll(Object…​ values)：通过使用 + 更新赋值，将所有集合值添加到现有集合的前面。

      • 更新 append(Object value)：使用 + 更新赋值将集合值追加到现有集合中。

      • 更新 append(Object…​ values)：使用 + 更新赋值将所有集合值追加到现有集合中。

      • 更新 entry(Object key, Object value)：使用 + 更新赋值添加映射条目。

      • 更新 addAll(Map<? extends Object, ? extends Object> map)：使用 + 更新赋值操作符将所有映射条目添加到该映射中。

    • Update remove (String columnName, Object value)：使用 `-` 更新赋值从集合中移除该值。

    • Update clear (String columnName)：清空集合。

    • Update increment (String columnName, Number delta)：使用 `+` 更新赋值进行更新。

    • Update decrement (String columnName, Number delta)：使用减号（-）更新赋值进行更新。

    • Update set (String columnName, Object value)：使用 = 赋值运算符进行更新。

    • SetBuilder set (String columnName) SetBuilder entry-point:

      • 更新atIndex(int index).to(Object value)：使用=赋值操作符将集合在给定索引处设置为指定值。

      • 更新atKey(String object).to(Object value)：在指定键处设置一个使用=更新赋值运算符的值。

    以下列表展示了一些更新示例：

    // UPDATE … SET key = 'Spring Data';
Update.update("key", "Spring Data")

// UPDATE … SET key[5] = 'Spring Data';
Update.empty().set("key").atIndex(5).to("Spring Data");

// UPDATE … SET key = key + ['Spring', 'DATA'];
Update.empty().addTo("key").appendAll("Spring", "Data");

    请注意，Update 一旦创建即为不可变对象。 调用方法会生成新的不可变（中间）Update 对象。

    删除行的方法

    您可以使用以下重载方法来从数据库中删除对象：

    • boolean delete (Query query, Class<?> entityClass)：删除由 Query 选中的对象。

    • T delete (T entity)：删除给定对象。

    • T delete (T entity, QueryOptions queryOptions)：应用 QueryOptions 删除给定对象。

    • boolean deleteById (Object id, Class<?> entityClass)：使用给定的 ID 删除对象。

    乐观锁

    @Version 注解在 Cassandra 上下文中提供了与 JPA 相似的语法，并确保更新仅应用于具有匹配版本的行。 乐观锁利用 Cassandra 的轻量级事务来有条件地插入、更新和删除行。 因此，INSERT 语句会配合 IF NOT EXISTS 条件执行。 对于更新和删除操作，会将版本属性的实际值添加到 UPDATE 条件中，使得如果在此期间有其他操作修改了该行，则该修改将不产生任何效果。 在这种情况下，会抛出 OptimisticLockingFailureException 异常。 以下示例展示了这些功能：

    @Table
class Person {

  @Id String id;
  String firstname;
  String lastname;
  @Version Long version;
}

Person daenerys = template.insert(new Person("Daenerys"));                            (1)

Person tmp = template.findOne(query(where("id").is(daenerys.getId())), Person.class); (2)

daenerys.setLastname("Targaryen");
template.save(daenerys);                                                              (3)

template.save(tmp); // throws OptimisticLockingFailureException                       (4)
    1 最初插入文档。version 被设置为 0。
    2 加载刚刚插入的文档。version 仍然是 0。
    3 使用 version = 0 更新文档。 设置 lastname 并将 version 提升至 1。
    4 尝试更新之前加载的文档，该文档仍具有 version = 0。 由于当前的 version 为 1，操作失败并抛出 OptimisticLockingFailureException。

    乐观锁仅支持单实体操作，不支持批量操作。
