    Mapping

    MappingCassandraConverter 提供了丰富的对象映射支持。MappingCassandraConverter 拥有完善的元数据模型，能够完整实现将领域对象映射到 CQL 表的功能。

    映射元数据模型是通过在域对象上使用注解来填充的。 然而，基础设施并不局限于仅使用注解作为元数据的唯一来源。 `MappingCassandraConverter` 还允许您遵循一组约定，将域对象映射到表，而无需提供任何额外的元数据。

    在本章中，我们将介绍 `MappingCassandraConverter` 的特性，如何使用约定将领域对象映射到表，以及如何通过基于注解的映射元数据覆盖这些约定。

    对象映射基础

    本节涵盖 Spring Data 对象映射、对象创建、字段和属性访问以及可变性与不可变性的基础知识。请注意，本节仅适用于不使用底层数据存储（如 JPA）的对象映射的 Spring Data 模块。此外，请务必查阅针对特定存储的章节，以了解特定于存储的对象映射内容，例如索引、自定义列或字段名称等。

    Spring Data 对象映射的核心职责是创建领域对象实例，并将存储原生的数据结构映射到这些对象上。 这意味着我们需要两个基本步骤：

    1. 通过暴露的构造函数之一创建实例。

    2. 实例化以具象化所有已公开的属性。

    对象创建

    Spring Data 会自动尝试检测持久化实体中用于实例化该类型对象的构造函数。 解析算法的工作方式如下：

    1. 如果存在一个带有@PersistenceCreator注解的单个静态工厂方法，则使用该方法。

    2. 如果有单个构造函数，则使用它。

    3. 如果存在多个构造函数且其中恰好有一个被标注为@PersistenceCreator，则使用该构造函数。

    4. 如果类型是 Java 的Record，则使用规范构造函数。

    5. 如果有无参构造函数，则使用它。 其他构造函数将被忽略。

    值解析假定构造函数/工厂方法的参数名称与实体属性名称相匹配，即解析过程将如同该属性正在被填充一样执行，包括所有映射自定义（如不同的数据存储列或字段名等）。 此外，还要求类文件中提供参数名称信息，或者在构造函数上存在 `@ConstructorProperties` 注解。

    可以通过使用 Spring Framework 的 `@Value` 注解及特定于存储库的 SpEL 表达式来自定义值解析。有关更多详细信息，请参阅关于存储库特定映射的部分。

    对象创建的内部机制

    为避免反射带来的开销，Spring Data 默认使用在运行时生成的工厂类来创建对象，该工厂类将直接调用领域类的构造函数。 即对于此示例类型：

    class Person {
  Person(String firstname, String lastname) { … }
}

    我们将在运行时创建一个语义上与此类等效的工厂类：

    class PersonObjectInstantiator implements ObjectInstantiator {

  Object newInstance(Object... args) {
    return new Person((String) args[0], (String) args[1]);
  }
}

    这为我们带来了比反射大约 10% 的性能提升。 要使领域类符合此类优化的条件，它需要遵守一组约束：

    • 它不能是私有类。

    • 它不能是非静态内部类。

    • 它不能是 CGLib 代理类。

    • Spring Data 所使用的构造函数不能是私有的。

    如果满足上述任一条件，Spring Data 将通过反射回退到实体实例化。

    属性人口

    一旦创建了该实体的实例，Spring Data 将填充该类中所有剩余的持久化属性。 除非这些属性已由实体构造函数填充（即通过构造函数参数列表传入），否则标识符属性将被首先填充，以便解析循环对象引用。 随后，所有未被构造函数填充的非瞬态属性将被设置到实体实例上。 为此，我们采用以下算法：

    1. 如果该属性是不可变的，但暴露了 `with…` 方法（见下文），我们使用 `with…` 方法来创建具有新属性值的新实体实例。

    2. 如果定义了属性访问（即通过 getter 和 setter 进行访问），我们将调用 setter 方法。

    3. 如果该属性是可变的，则直接设置该字段。

    4. 如果属性是不可变的，我们将使用构造函数（参见对象创建）来为持久化操作创建该实例的副本。

    5. 默认情况下，我们直接设置字段值。

    属性人口内部结构

    与我们在对象构建中的优化类似，我们也使用 Spring Data 运行时生成的访问器类来与实体实例进行交互。

    class Person {

  private final Long id;
  private String firstname;
  private @AccessType(Type.PROPERTY) String lastname;

  Person() {
    this.id = null;
  }

  Person(Long id, String firstname, String lastname) {
    // Field assignments
  }

  Person withId(Long id) {
    return new Person(id, this.firstname, this.lastname);
  }

  void setLastname(String lastname) {
    this.lastname = lastname;
  }
}
    生成的属性访问器
    class PersonPropertyAccessor implements PersistentPropertyAccessor {

  private static final MethodHandle firstname;              (2)

  private Person person;                                    (1)

  public void setProperty(PersistentProperty property, Object value) {

    String name = property.getName();

    if ("firstname".equals(name)) {
      firstname.invoke(person, (String) value);             (2)
    } else if ("id".equals(name)) {
      this.person = person.withId((Long) value);            (3)
    } else if ("lastname".equals(name)) {
      this.person.setLastname((String) value);              (4)
    }
  }
}
    1 PropertyAccessor 持有底层对象的可变实例。这是为了能够修改原本不可变的属性。
    2 默认情况下，Spring Data 使用属性访问方式来读取和写入属性值。根据 private 字段的可见性规则，使用 MethodHandles 与字段进行交互。
    3 该类提供了一个 withId(…) 方法，用于设置标识符，例如当实例被插入数据存储且已生成标识符时。调用 withId(…) 会创建一个新的 Person 对象。所有后续的修改都将在新实例中进行，而不会改变之前的实例。
    4 使用属性访问允许直接进行方法调用，而无需使用 MethodHandles。

    这为我们带来了比反射间接提升约 25% 的性能。 要使领域类符合此类优化的条件，它需要遵守一组约束：

    • 类型不得位于默认包或java 包下。

    • 类型及其构造函数必须是public的。

    • 作为内部类的类型，必须是static的。

    • 所使用的 Java 运行时必须允许在源 `ClassLoader` 中声明类。Java 9 及更高版本施加了某些限制。

    默认情况下，Spring Data 会尝试使用生成的属性访问器；如果检测到限制，则会回退到基于反射的访问器。

    让我们看看以下实体：

    示例实体
    class Person {

  private final @Id Long id;                                                (1)
  private final String firstname, lastname;                                 (2)
  private final LocalDate birthday;
  private final int age;                                                    (3)

  private String comment;                                                   (4)
  private @AccessType(Type.PROPERTY) String remarks;                        (5)
  private @Transient String summary;                                        (6)

  static Person of(String firstname, String lastname, LocalDate birthday) { (7)

    return new Person(null, firstname, lastname, birthday,
      Period.between(birthday, LocalDate.now()).getYears());
  }

  Person(Long id, String firstname, String lastname, LocalDate birthday, int age) { (7)

    this.id = id;
    this.firstname = firstname;
    this.lastname = lastname;
    this.birthday = birthday;
    this.age = age;
  }

  Person withId(Long id) {                                                  (1)
    return new Person(id, this.firstname, this.lastname, this.birthday, this.age);
  }

  void setRemarks(String remarks) {                                         (5)
    this.remarks = remarks;
  }
}
    1 标识符属性为 final 类型，但在构造函数中被设置为 null。该类提供了一个 withId(…) 方法用于设置标识符，例如当实例被插入数据存储且已生成标识符时。原始的 Person 实例保持不变，因为会创建一个新的实例。通常会对其他需要存储管理但可能需要更改以进行持久化操作的属性应用相同的模式。wither 方法是可选的，因为持久化构造函数（见第 6 点）本质上是一个拷贝构造函数，设置该属性将被转换为创建一个新实例，并将新的标识符值应用其中。
    2 firstname 和 lastname 属性是普通的不可变属性，可能通过 getter 方法暴露。
    3 age 属性是不可变的，但它是从 birthday 属性派生而来的。按照所示的设计，数据库值将优于默认值，因为 Spring Data 仅使用声明的构造函数。即使意图是优先采用计算结果，也重要的是该构造函数也必须接受 age 作为参数（以便可能忽略它），否则属性填充步骤将尝试设置 age 字段，但由于该字段不可变且不存在 with… 方法而失败。
    4 comment 属性是可变的，通过直接设置其字段来填充。
    5 remarks 属性是可变的，通过调用 setter 方法来填充。
    6 summary 属性是瞬态的，不会被持久化，因为它被标注为 @Transient。Spring Data 不使用 Java 的 transient 关键字来排除属性不被持久化，因为 transient 是 Java 序列化框架的一部分。请注意，该属性可以与持久化构造函数一起使用，但其值将默认为 null（如果属性类型是基本类型，则为其相应的基本类型初始值）。
    7 该类提供了一个工厂方法和一个构造函数用于对象创建。这里的核心思想是使用工厂方法而不是额外的构造函数，以避免通过 @PersistenceCreator 进行构造函数消歧的需要。相反，属性的默认值处理在工厂方法内部完成。如果您希望 Spring Data 使用工厂方法进行对象实例化，请将其标注为 @PersistenceCreator。

    一般建议

    • 尽量使用不可变对象——创建不可变对象非常简单，只需调用其构造函数即可完成对象的实例化。 此外，这还能避免在领域对象中散布允许客户端代码操纵对象状态的 setter 方法。 如果确实需要这些方法，建议将其设为包级私有（package protected），以便仅由有限的同包类型调用。 仅通过构造函数创建对象的速度比通过属性赋值快高达 30%。

    • 提供一个全参构造函数——即使您无法或不愿将实体建模为不可变值，提供接受实体所有属性（包括可变属性）作为参数的构造函数仍然具有价值，因为这允许对象映射跳过属性填充过程，从而实现最佳性能。

    • 使用工厂方法而非重载构造函数，以避免使用 @PersistenceCreator——由于全参构造函数对于最佳性能是必需的，我们通常希望暴露更多针对特定应用程序用例的构造函数，这些构造函数会省略诸如自动生成的标识符等内容。 采用静态工厂方法来暴露全参构造函数的各种变体，是一种成熟的模式。

    • 确保遵守相关约束，以便生成的实例化器和属性访问器类能够被使用。

    • 若要生成标识符，仍需使用最终字段配合全参数持久化构造函数（首选）或 with… 方法 —

    • 使用 Lombok 避免样板代码——由于持久化操作通常需要包含所有参数的构造函数，其声明往往变成对样板式参数到字段赋值语句的繁琐重复，而使用 Lombok 的 @AllArgsConstructor 可以最好地避免这种情况。

    覆盖属性

    Java 允许对领域类进行灵活设计，子类可以定义一个与其超类中已声明的同名属性。 考虑以下示例：

    public class SuperType {

   private CharSequence field;

   public SuperType(CharSequence field) {
      this.field = field;
   }

   public CharSequence getField() {
      return this.field;
   }

   public void setField(CharSequence field) {
      this.field = field;
   }
}

public class SubType extends SuperType {

   private String field;

   public SubType(String field) {
      super(field);
      this.field = field;
   }

   @Override
   public String getField() {
      return this.field;
   }

   public void setField(String field) {
      this.field = field;

      // optional
      super.setField(field);
   }
}

    两个类都使用可赋值类型定义了 `field`。然而，`SubType` 会遮蔽 `SuperType.field`。 根据类的设计，使用构造函数可能是设置 `SuperType.field` 的唯一默认方式。 或者，在 setter 中调用 `super.setField(…)` 也可以设置 `SuperType` 中的 `field`。 所有这些机制在某种程度上都会产生冲突，因为属性名称相同，但可能代表两个不同的值。 如果类型不可赋值，Spring Data 会跳过超类型的属性。 也就是说，被覆盖属性的类型必须可赋值于其超类型属性类型才能注册为覆盖属性；否则，超类型属性将被视为瞬态。 我们通常建议使用不同的属性名称。

    Spring Data 模块通常支持覆盖属性以持有不同的值。从编程模型的角度来看，有几点需要考虑：

    1. 应持久化哪些属性（默认为所有声明的属性）？ 您可以通过使用 @Transient 注解来排除某些属性。

    2. 如何在数据存储中表示属性？ 为不同的值使用相同的字段/列名通常会导致数据损坏，因此您应该至少使用一个显式的字段/列名来标注这些属性。

    3. 使用@AccessType(PROPERTY)不可行，因为无法在不对 setter 实现做出任何额外假设的情况下设置超属性。

    Kotlin 支持

    Spring Data 适配了 Kotlin 的具体特性，以支持对象的创建和修改。

    Kotlin 对象创建

    支持实例化 Kotlin 类，所有类默认不可变，且需要显式声明属性以定义可变属性。

    Spring Data 会自动尝试检测持久化实体中用于实例化该类型对象的构造函数。 解析算法的工作方式如下：

    1. 如果存在一个带有@PersistenceCreator注解的构造函数，则使用它。

    2. 如果类型是Kotlin 数据类，则使用主构造函数。

    3. 如果存在一个带有@PersistenceCreator注解的单个静态工厂方法，则使用该方法。

    4. 如果有单个构造函数，则使用它。

    5. 如果存在多个构造函数且其中恰好有一个被标注为@PersistenceCreator，则使用该构造函数。

    6. 如果类型是 Java 的Record，则使用规范构造函数。

    7. 如果有无参构造函数，则使用它。 其他构造函数将被忽略。

    考虑以下 `data` 类 `Person`：

    data class Person(val id: String, val name: String)

    上述类编译为具有显式构造函数的典型类。我们可以通过添加另一个构造函数并用@PersistenceCreator注解来定制该类，以指示构造函数偏好：

    data class Person(var id: String, val name: String) {

    @PersistenceCreator
    constructor(id: String) : this(id, "unknown")
}

    Kotlin 支持通过为参数提供默认值来实现参数的可选性。当 Spring Data 检测到具有参数默认值的构造函数时，如果数据存储未提供相应值（或简单地返回 null），它会将这些参数留空，以便 Kotlin 应用参数默认值机制。考虑以下对 name 参数应用默认值的类：

    data class Person(var id: String, val name: String = "unknown")

    每次 `name` 参数不在结果中或其值为 `null` 时，`name` 将默认为 `unknown`。

    Spring Data 不支持委派属性。对于 Kotlin 数据类，映射元数据会过滤掉委派属性。 在其他所有情况下，您可以通过使用 @Transient 注解来排除委派属性的合成字段。

    Kotlin 数据类的属性填充

    在 Kotlin 中，所有类默认都是不可变的，若要定义可变属性，则需显式声明。 考虑以下 data 类 Person：

    data class Person(val id: String, val name: String)

    该类实际上是不可变的。它允许创建新实例，因为 Kotlin 会生成一个 `copy(…)` 方法，该方法通过复制现有对象的所有属性值，并将作为参数提供的属性值应用过来，从而创建新的对象实例。

    Kotlin 属性重写

    Kotlin 允许声明属性重写，以便在子类中修改属性。

    open class SuperType(open var field: Int)

class SubType(override var field: Int = 1) :
	SuperType(field) {
}

    这种安排会导致两个名为 `field` 的属性。 Kotlin 会为每个类中的每个属性生成访问器（getter 和 setter）。 实际上，代码看起来如下所示：

    public class SuperType {

   private int field;

   public SuperType(int field) {
      this.field = field;
   }

   public int getField() {
      return this.field;
   }

   public void setField(int field) {
      this.field = field;
   }
}

public final class SubType extends SuperType {

   private int field;

   public SubType(int field) {
      super(field);
      this.field = field;
   }

   public int getField() {
      return this.field;
   }

   public void setField(int field) {
      this.field = field;
   }
}

    SubType 上的 getter 和 setter 仅设置 SubType.field，而不会设置 SuperType.field。 在这种安排下，使用构造函数是设置 SuperType.field 的唯一默认方法。 虽然可以通过在 SubType 中添加一个方法来通过 this.SuperType.field = … 设置 SuperType.field，但这不符合支持的习惯用法。 属性覆盖会在一定程度上产生冲突，因为这些属性具有相同的名称，但可能代表两个不同的值。 我们通常建议使用不同的属性名称。

    Spring Data 模块通常支持覆盖属性以持有不同的值。从编程模型的角度来看，有几点需要考虑：

    1. 应持久化哪些属性（默认为所有声明的属性）？ 您可以通过使用 @Transient 注解来排除某些属性。

    2. 如何在数据存储中表示属性？ 为不同的值使用相同的字段/列名通常会导致数据损坏，因此您应该至少使用一个显式的字段/列名来标注这些属性。

    3. 使用@AccessType(PROPERTY)时，无法将其作为超属性设置，因为超属性不可被设定。

    Kotlin 值类

    Kotlin 值类旨在构建更具表现力的领域模型，使底层概念更加明确。 Spring Data 可以读取和写入使用值类定义属性的类型。

    考虑以下领域模型：

    @JvmInline
value class EmailAddress(val theAddress: String)                                    (1)

data class Contact(val id: String, val name:String, val emailAddress: EmailAddress) (2)

    基于约定的映射

    当未提供额外的映射元数据时，MappingCassandraConverter 遵循一些约定将领域对象映射到 CQL 表。这些约定如下：

    • 简单的（短的）Java 类名通过转换为小写映射到表名。例如，com.bigbank.SavingsAccount 映射为名为 savingsaccount 的表。

    • 转换器使用任何已注册的 Spring Converter 实例来覆盖对象属性到表列的默认映射。

    • 对象的属性用于在表和列之间进行转换。

    您可以通过在 CassandraMappingContext 上配置一个 NamingStrategy 来调整约定。命名策略对象定义了从实体类以及实际属性派生表、列或用户定义类型的约定方式。

    以下示例展示了如何配置一个 `NamingStrategy`：

    示例 2. 在 CassandraMappingContext 上配置 NamingStrategy
    		CassandraMappingContext context = new CassandraMappingContext();

		// default naming strategy
		context.setNamingStrategy(NamingStrategy.INSTANCE);

		// snake_case converted to upper case (SNAKE_CASE)
		context.setNamingStrategy(NamingStrategy.SNAKE_CASE.transform(String::toUpperCase));

    映射配置

    除非显式配置，否则在创建 CassandraTemplate 时默认会生成一个 MappingCassandraConverter 实例。 您可以自行创建 MappingCassandraConverter 的实例，以便在启动时指定类路径扫描位置，从而提取域类的元数据并构建索引。

    此外，通过创建自己的实例，您可以注册用于将特定类映射到数据库和从数据库映射的 Spring `Converter` 实例。以下示例配置类设置了 Cassandra 映射支持：

    示例 3。用于配置 Cassandra 映射支持类的@Configuration 类
    @Configuration
public class SchemaConfiguration extends AbstractCassandraConfiguration {

	@Override
	protected String getKeyspaceName() {
		return "bigbank";
	}

	// the following are optional

	@Override
	public CassandraCustomConversions customConversions() {

		return CassandraCustomConversions.create(config -> {
			config.registerConverter(new PersonReadConverter()));
			config.registerConverter(new PersonWriteConverter()));
		});
	}

	@Override
	public SchemaAction getSchemaAction() {
		return SchemaAction.RECREATE;
	}

	// other methods omitted...
}

    `AbstractCassandraConfiguration` 要求您实现用于定义 keyspace 的方法。 `AbstractCassandraConfiguration` 还提供了一个名为 `getEntityBasePackages(…)` 的方法。您可以重写该方法，以告知转换器扫描带有 `@Table` 注解的类的位置。

    您可以通过重写customConversions方法向MappingCassandraConverter添加额外的转换器。

    AbstractCassandraConfiguration 会创建一个 CassandraTemplate 实例，并将其注册到容器中，名称为 cassandraTemplate。

    基于元数据的映射

    要充分利用 Spring Data for Apache Cassandra 支持中的对象映射功能，您应该使用 @Table 注解来标记您的映射域对象。 这样做可以让类路径扫描器找到并预处理您的域对象，以提取必要的元数据。 只有经过注解的实体才会用于执行模式操作。 在最坏的情况下，SchemaAction.RECREATE_DROP_UNUSED 操作会删除您的表，从而导致数据丢失。 请注意，表是从会话的键空间中访问的。 不过，您可以指定一个自定义的键空间，以从特定的键空间中访问表/UDT。

    以下示例展示了一个简单的领域对象：

    示例 4。示例领域对象
    @Table
public class Person {

  @Id
  private String id;

  @CassandraType(type = Name.VARINT)
  private Integer ssn;

  private String firstName;

  private String lastName;
}
    @Id 注解告诉 Mapper 您希望使用哪个属性作为 Cassandra 的主键。 复合主键可能需要稍微不同的数据模型。

    主键处理

    Cassandra 要求 CQL 表至少包含一个分区键字段。 表还可以声明一个或多个聚类键字段。 当您的 CQL 表具有复合主键时，必须创建一个 `@PrimaryKeyClass` 来定义复合主键的结构。 在此上下文中，“复合主键”指一个或多个分区列与一个或多个聚类列的组合（可选）。

    主键可以使用任何单个简单的 Cassandra 类型或映射的用户定义类型。不支持集合类型的主键。

    简单主键

    简单的主键由实体类中的一个分区键字段组成。 由于仅包含一个字段，我们可以安全地将其视为分区键。 以下示例展示了在 Cassandra 中定义的一个 CQL 表，其主键为 `user_id`：

    示例 5。Cassandra 中定义的 CQL 表
    CREATE TABLE user (
  user_id text,
  firstname text,
  lastname text,
  PRIMARY KEY (user_id))
;

    下面的示例展示了一个 Java 类，其注解方式与上一节中定义的 Cassandra 相对应：

    示例 6：注释实体
    @Table(value = "login_event")
public class LoginEvent {

  @PrimaryKey("user_id")
  private String userId;

  private String firstname;
  private String lastname;

  // getters and setters omitted

}

    复合键

    复合主键（或组合键）由多个主键字段组成。 具体来说，复合主键可以包含多个分区键、一个分区键和一个聚类键，或者多个主键字段。

    在 Spring Data for Apache Cassandra 中，复合键可以用两种方式表示：

    • 嵌入于实体之中。

    • 通过使用@PrimaryKeyClass。

    复合键的最简单形式是由一个分区键和一个聚类键组成的键。

    以下示例展示了一个用于表示表及其复合键的 CQL 语句：

    示例 7：具有复合主键的 CQL 表
    CREATE TABLE login_event(
  person_id text,
  event_code int,
  event_time timestamp,
  ip_address text,
  PRIMARY KEY (person_id, event_code, event_time))
  WITH CLUSTERING ORDER BY (event_time DESC)
;

    扁平复合主键

    扁平复合主键作为平铺字段嵌入实体中。 主键字段需使用@PrimaryKeyColumn注解进行标注。 查询时，必须包含针对各个字段的谓词条件，或使用MapId。 以下示例展示了一个具有扁平复合主键的类：

    示例 8：使用平面复合主键
    @Table(value = "login_event")
class LoginEvent {

  @PrimaryKeyColumn(name = "person_id", ordinal = 0, type = PrimaryKeyType.PARTITIONED)
  private String personId;

  @PrimaryKeyColumn(name = "event_code", ordinal = 1, type = PrimaryKeyType.PARTITIONED)
  private int eventCode;

  @PrimaryKeyColumn(name = "event_time", ordinal = 2, type = PrimaryKeyType.CLUSTERED, ordering = Ordering.DESCENDING)
  private LocalDateTime eventTime;

  @Column("ip_address")
  private String ipAddress;

  // getters and setters omitted
}

    主键类

    主键类是一种复合主键类，它映射到实体的多个字段或属性。 该类需使用 @PrimaryKeyClass 注解进行标记，并应定义 equals 和 hashCode 方法。 这些方法的值相等语义应与所映射数据库类型的数据库相等性保持一致。 主键类可用于仓库（作为 Id 类型），也可用于在单个复杂对象中表示实体的身份。 以下示例展示了一个复合主键类：

    示例 9：复合主键类
    @PrimaryKeyClass
class LoginEventKey implements Serializable {

  @PrimaryKeyColumn(name = "person_id", ordinal = 0, type = PrimaryKeyType.PARTITIONED)
  private String personId;

  @PrimaryKeyColumn(name = "event_code", ordinal = 1, type = PrimaryKeyType.PARTITIONED)
  private int eventCode;

  @PrimaryKeyColumn(name = "event_time", ordinal = 2, type = PrimaryKeyType.CLUSTERED, ordering = Ordering.DESCENDING)
  private LocalDateTime eventTime;

  // other methods omitted
}

    以下示例展示了如何使用复合主键：

    示例 10：使用复合主键
    @Table(value = "login_event")
public class LoginEvent {

  @PrimaryKey
  private LoginEventKey key;

  @Column("ip_address")
  private String ipAddress;

  // getters and setters omitted
}

    嵌入式实体支持

    嵌入式实体用于在 Java 领域模型中设计值对象，其属性会被扁平化到表中。 在下例中可以看到，User.name 被标注了 @Embedded。 这一后果是，UserName 的所有属性都被折叠到 user 表中，该表包含三列（user_id、firstname、lastname）。

    嵌入式实体只能包含简单属性类型。 无法将嵌入式实体嵌套到另一个嵌入式实体中。

    然而，如果结果集中的 `firstname` 和 `lastname` 列值实际上为 `null`，则根据 `@Embedded` 的 `onEmpty` 设置，整个属性 `name` 将被设置为 `null`，因为当所有嵌套属性均为 `null` 时，该设置会将对象置为 `null`。
    与这种行为相反，`USE_EMPTY` 尝试使用默认构造函数或接受来自结果集的可为空参数值的构造函数来创建新实例。

    示例 11。嵌入对象的示例代码
    public class User {

    @PrimaryKey("user_id")
    private String userId;

    @Embedded(onEmpty = USE_NULL) (1)
    UserName name;
}

public class UserName {
    private String firstname;
    private String lastname;
}
    1 如果firstname和lastname均为null，则属性为null。使用onEmpty=USE_EMPTY来实例化UserName，即使其属性的值可能为null。

    您可以使用 `@Embedded` 注解的可选 `prefix` 元素，在实体中多次嵌入值对象。该元素表示一个前缀，并将附加到嵌入式对象的每个列名之前。请注意，如果多个属性映射到相同的列名，则后定义的属性将覆盖先前的属性。

    使用快捷方式@Embedded.Nullable和@Embedded.Empty来替代@Embedded(onEmpty = USE_NULL)和@Embedded(onEmpty = USE_EMPTY)，以减少冗长性，同时相应地设置 JSR-305 注解@javax.annotation.Nonnull。

    public class MyEntity {

    @Id
    Integer id;

    @Embedded.Nullable (1)
    EmbeddedEntity embeddedEntity;
}
    1 @Embedded(onEmpty = USE_NULL) 的快捷方式。

    映射注解概述

    MappingCassandraConverter 可以利用元数据来驱动对象到 Cassandra 表中行的映射。以下是对这些注解的概述：

    • @Id：应用于字段或属性级别，用于标记用于标识目的的属性。

    • @Table：在类级别应用，用于指示该类是数据库映射的候选者。 您可以指定对象存储所在的表名。 当指定键空间时，所有 DML 和 DDL 操作中的表名将以前缀形式包含该键空间。

    • @PrimaryKey：与@Id类似，但允许您指定列名。

    • @PrimaryKeyColumn：Cassandra 专用的主键列注解，允许您指定主键列的属性（例如用于聚簇或分区）。 该注解可应用于单个或多个属性，以表示单一主键或复合（组合）主键。 如果将其用于实体内的属性，请确保同时应用 @Id 注解。

    • @PrimaryKeyClass：在类级别应用，表示该类为复合主键类。必须在实体类中与@PrimaryKey一起引用。

    • @Transient：默认情况下，所有私有字段都会映射到行中。此注解会排除应用该注解的字段，使其不被存储到数据库中。瞬态属性不能在持久化构造函数中使用，因为转换器无法为构造函数参数生成值。

    • @PersistenceConstructor：标记一个给定的构造函数（即使是包级私有的），用于从数据库实例化对象。 构造函数的参数通过名称映射到检索行中的键值。

    • @Value：此注解属于 Spring 框架。在映射框架中，它可以应用于构造函数参数。 这使得您可以使用 Spring 表达式语言语句，在利用该值构建领域对象之前，对从数据库中检索到的键值进行转换。 若要引用给定 Row/UdtValue/TupleValue 的属性，则需使用类似 @Value("#root.getString(0)") 的表达式，其中 root 指代给定文档的根节点。

    • @ReadOnlyProperty：在字段级别应用，用于将属性标记为只读。 绑定到实体的插入和更新语句不包含此属性。

    • @Column：应用于字段级别。 描述在 Cassandra 表中表示的列名，从而使列名可以与类的字段名不同。 可用于构造函数参数，以在创建构造函数时自定义列名。

    • @Embedded：应用于字段级别。 使映射到表或用户定义类型的类型能够使用嵌入对象。 嵌入对象的属性被扁平化并合并到其父结构的结构中。

    • @Indexed：应用于字段级别。 描述在会话初始化时创建的索引。

    • @SASI：在字段级别应用。 允许在会话初始化期间创建 SASI 索引。

    • @SaiIndexed：在字段级别应用。 允许在会话初始化期间定义存储附加索引（SAI）的创建。

    • @CassandraType：应用于字段级别，用于指定 Cassandra 数据类型。默认情况下，类型由属性声明推导得出。

    • @VectorType：在字段级别应用，用于指定 Cassandra 向量类型。 在使用模式生成时，此注解是必需的。

    • @Frozen：在字段级别应用于类类型和参数化类型。声明冻结的 UDT 列或冻结集合，例如 List<@Frozen UserDefinedPersonType>。

    • @UserDefinedType：在类型级别应用，用于指定 Cassandra 用户定义类型（UDT）。 在指定键空间时，所有 DML 和 DDL 操作中的 UDT 名称都将以前缀形式包含该键空间。 默认情况下，类型由声明推导得出。

    • @Tuple：在类型级别应用，用于将类型用作映射元组。

    • @Element：应用于字段级别，用于指定映射元组中的元素或字段序数。 类型默认由属性声明推导得出。 也可用于构造函数参数，以在创建构造函数时自定义元组元素的序数。

    • @Version：在字段级别应用，用于乐观锁，并在保存操作时检查修改。初始值为zero，每次更新时会自动递增。

    映射元数据基础设施定义在独立的、与技术和数据存储无关的 spring-data-commons 项目中。

    索引创建

    您可以使用 `@Indexed`、`@SaiIndexed` 或 `@SASI` 注解特定实体属性，以便在应用程序启动时创建二级索引。 索引创建会为标量类型、用户定义类型和集合类型生成简单的二级索引。

    您可以配置一个 SASI 索引以应用分析器，例如 `StandardAnalyzer` 或 `NonTokenizingAnalyzer`（分别使用 `@StandardAnalyzed` 和 `@NonTokenizingAnalyzed`）。

    映射类型区分了 `ENTRY`、`KEYS` 和 `VALUES` 索引。 索引的创建会根据注解的元素推导出索引类型。 以下示例展示了创建索引的多种方式：

    示例 15。映射索引的变体
    @Table
class PersonWithIndexes {

  @Id
  private String key;

  @SASI
  @StandardAnalyzed
  private String names;

  @SaiIndexed
  @VectorType(dimensions = 1536) // required for table generation
  private Vector vector;

  @Indexed("indexed_map")
  private Map<String, String> entries;

  private Map<@Indexed String, String> keys;

  private Map<String, @Indexed String> values;

  // …
}

    @Indexed 注解可以应用于嵌入实体的单个属性，也可以与 @Embedded 注解一起使用，在这种情况下，嵌入实体的所有属性都会被索引。
    在会话初始化期间创建索引可能会对应用程序启动性能产生严重影响。
