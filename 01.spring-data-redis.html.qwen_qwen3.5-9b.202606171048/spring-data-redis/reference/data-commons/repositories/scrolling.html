    Scrolling

    滚动是一种更细粒度的方法，用于遍历大型结果集的分块数据。 滚动包含稳定排序、滚动类型（基于偏移量或基于键集的滚动）以及结果限制。 您可以通过使用属性名称定义简单的排序表达式，并通过查询推导使用 Top 或 First 关键字 定义静态的结果限制。 您可以连接表达式以将多个条件收集到一个表达式中。

    滚动查询返回一个 `Window<T>`，允许获取元素的滚动位置以获取下一个 `Window<T>`，直到您的应用程序消耗完整个查询结果。 类似于通过获取下一批结果来消费 Java 的 `Iterator<List<…>>`，查询结果滚动让您可以通过 `ScrollPosition` 访问位置，例如以下示例所示：

    Window<User> users = repository.findFirst10ByLastnameOrderByFirstname("Doe", ScrollPosition.offset());
do {

  for (User u : users) {
    // consume the user
  }

  if (users.isLast() || users.isEmpty()) {
    break;
  }

  // obtain the next Scroll
  users = repository.findFirst10ByLastnameOrderByFirstname("Doe", users.positionAt(users.size() - 1));
} while (!users.isEmpty());

    `ScrollPosition` 标识包含整个查询结果集的元素的精确位置。 查询执行将位置参数视为排他性的，结果将从给定位置之后开始返回。 `ScrollPosition#offset()` 和 `ScrollPosition#keyset()` 是 `ScrollPosition` 的特殊形式，用于指示滚动操作的起始点。

    上述示例展示了静态排序和限制。 您可以定义替代的查询方法，接受一个 `Sort` 对象以定义更复杂的排序顺序或按请求进行排序。 类似地，提供一个 `Limit` 对象允许您按请求动态定义限制，而不是应用静态限制。 有关动态排序和限制的更多信息，请参阅 查询方法详情。

    遍历并消费Window实例需要大量的条件判断才能达到最优的数据库往返性能，这很容易变成一项重复性的工作，而使用WindowIterator可以简化这一过程。

    `WindowIterator` 提供了一种实用工具，通过消除检查下一个 `Window` 是否存在并应用 `ScrollPosition` 的需求，从而简化了在多个 `Window` 之间滚动浏览的操作。

    WindowIterator<User> users = WindowIterator.of(position -> repository.findFirst10ByLastnameOrderByFirstname("Doe", position))
  .startingAt(ScrollPosition.offset());

while (users.hasNext()) {
  User u = users.next();
  // consume the user
}

    使用偏移量进行滚动

    偏移分页与传统的分页类似，它使用一个偏移量（Offset）计数器来跳过指定数量的结果，并让数据源仅返回从给定偏移量开始的结果。 这种简单的机制可以避免将大量结果发送给客户端应用程序。 然而，大多数数据库要求在服务器返回结果之前，先将完整的查询结果物化到内存中。

    示例 1：使用OffsetScrollPosition与仓储查询方法
    interface UserRepository extends Repository<User, Long> {

  Window<User> findFirst10ByLastnameOrderByFirstname(String lastname, OffsetScrollPosition position);
}

WindowIterator<User> users = WindowIterator.of(position -> repository.findFirst10ByLastnameOrderByFirstname("Doe", position))
  .startingAt(OffsetScrollPosition.initial()); (1)
    1 从偏移量为 0 开始，以包含位置 0 处的元素。

    `ScrollPosition.offset()` 与 `ScrollPosition.offset(0L)` 之间存在区别。前者表示滚动操作的起始点，指向一个不特定的偏移量；而后者则标识结果中的第一个元素（位于位置 `0`）。鉴于滚动的**独占性**，使用 `ScrollPosition.offset(0)` 会跳过第一个元素并将其转换为偏移量 `1`。

    使用键集过滤进行滚动

    基于偏移量的滚动要求大多数数据库在服务器返回结果之前，必须将完整结果物化。因此，虽然客户端仅能看到请求结果的一部分，但您的服务器需要构建完整的结果集，从而导致额外的负载。

    键集过滤方法通过利用数据库的内置功能实现子集检索，旨在降低单个查询的计算和 I/O 需求。 该方法维护一组用于恢复滚动操作的键，通过将键传入查询来有效修改您的过滤条件。

    Keyset-Filtering 的核心思想是利用稳定的排序顺序开始检索结果。当你想要滚动到下一批数据时，会获取一个 ScrollPosition，该位置用于在已排序的结果中重建当前位置。ScrollPosition 捕获了当前 Window 内最后一个实体的键集（keyset）。执行查询时，重建过程会将条件子句重写为包含所有排序字段和主键，以便数据库能够利用潜在索引来运行查询。数据库只需根据给定的键集位置构建一个较小的结果集，而无需完全生成一个大结果集再跳过部分数据直到达到特定的偏移量。

    键集过滤要求用于排序的键属性必须为非空值。此限制是由于存储特定比较运算符对 null 值的处理方式以及需要在索引源上运行查询所导致的。在可空属性上执行键集过滤将导致意外结果。
    使用KeysetScrollPosition与仓储查询方法
    interface UserRepository extends Repository<User, Long> {

  Window<User> findFirst10ByLastnameOrderByFirstname(String lastname, KeysetScrollPosition position);
}

WindowIterator<User> users = WindowIterator.of(position -> repository.findFirst10ByLastnameOrderByFirstname("Doe", position))
  .startingAt(ScrollPosition.keyset()); (1)
    1 从头开始，不要应用额外的过滤条件。

    当数据库中存在与排序字段匹配的索引时，键集过滤效果最佳，因此静态排序非常适用。 应用键集过滤的滚动查询要求查询返回用于排序顺序的属性，并且这些属性必须在返回的实体中进行映射。

    您可以使用接口和 DTO 投影，但请确保包含所有已排序的属性，以避免键集提取失败。

    在指定 `Sort` 顺序时，只需包含与查询相关的排序属性即可；如果您不希望确保查询结果的唯一性，则无需为此操心。键集查询机制会通过添加主键（或复合主键的其余部分）来修正您的排序顺序，从而保证每个查询结果都是唯一的。
